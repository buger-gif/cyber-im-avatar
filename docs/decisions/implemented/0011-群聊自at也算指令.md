# 0011 群聊里 @ 自己也算指令

> 状态: implemented
> 日期: 2026-11-06
> 关联: spec 0039（推翻 spec 0029 的群聊非目标）

## 背景

spec 0029 把「本人 @ 自己 = 对替身说话」做成 `kind=cmd`，但只限私聊；群聊里本人 @ 自己仍记
`out/replied`，永不唤醒。当时的理由写在取舍表里：群里 @ 自己噪声大，且 agent 的回复全群可见。

2026-11-06 本机实测：一个在盯且 `timer=1` 的群里，本人发 `@<自己的显示名> …`，快车道拉到后
记 `out/replied`、正文清空、没有 turn。用户判断这是行为错误：群正是工作发生的地方，@ 自己是
显式指向替身的动作，不该因为会话类型不同就失效。同一周的公开稿也把「群里自己 @ 自己不算指令」
列为当时的边界，并写明理想形态是「不管私聊还是群，@ 自己就是把这句话变成一张工单」。

## 决策

群聊里的自 @ 与私聊同权：记 `kind=cmd`、进唤醒批次、唤醒 agent；不算待回、不刷角标；
指令不等全量模式的合并窗口。群里不因此自动对外发言：唤醒载荷要求指令默认只在本地处理。

## 备选

| 备选 | 为什么不行 |
| --- | --- |
| 维持只做私聊（spec 0029 的取舍） | 用户要在群里下指令时得切回私聊、再把结论搬回群；同一个动作在群里失效没有任何提示 |
| 群里自 @ 只在「只盯 @我」模式算 | 关注程度管的是「旁观消息要不要叫醒」，不是「本人能不能下指令」；全量群里同样需要 |
| 全量群的指令也等 60 秒合并窗口 | 最多晚一分钟才起 turn，用户看到的就是「没触发」；指令是交互，其余消息仍合并 |
| 用前缀（如 `/im`）代替 @ 自己 | 平台已把 @ 自己做成显式动作，再发明一套语法要教用户两遍 |
| 加一个「群聊也认自 @」开关 | 默认关则用户继续踩同一个坑；默认开则开关只是增加解释成本，熔断与「默认不对外发言」已兜底 |

## 后果

- 接受：群里 @ 自己是对全群可见的动作，同事可能看到；这是用户主动选择的下指令方式。
- 接受：agent 若在群里回复时 @ 了自己会形成回环；靠载荷规则与同会话 10 分钟 5 次熔断兜底，
  面板 `last_error` 可见。
- 接受：默认不拉（`timer=-1`）与没在盯的群仍然看不到自 @；这是拉取节奏，不随本决策改变。
- 重新考虑的触发条件：群里自 @ 唤醒的实际频率/成本证明确实是噪声（例如误把闲聊当指令），
  或团队里有多人共用同一账号。届时优先按群开关，而不是回退成「群聊一律不认」。

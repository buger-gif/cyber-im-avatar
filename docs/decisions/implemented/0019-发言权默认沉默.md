# 0019 发言权默认沉默：没有增量不说话

> 状态: implemented
> 日期: 2026-11-24
> 关联: 修订 0017 的默认口径；spec 0060

## 背景

2026-11-24 10:30，漏洞管理平台（bot）为一条高危漏洞自动建修复跟进群，推「漏洞即将逾期提醒」卡片：
mentions 里同时带处理人和安全跟进人，正文只 @ 处理人问进展，卡片里已经写明截止时间与
「已修复就提复测」。10:35，安全跟进人又补了一条「截止时间 / 复测路径」——没有增量信息，
只是把角色字段上的 @ 当成「有人叫我干活」，被用户当场指出主动性过高。

0017 的默认口径是「点我名：回」「信息同步可以发」，没有区分真人消息与机器人通知，
也没给「信息同步」设门槛，机器人自动群 + 自动卡片正好落在「点名了但没人要我干活」的缝里。

## 决策

默认动作为沉默。发言必须过两槛之一：

1. **有增量**：对方还不知道、且会改变他动作的信息（新结论 / 新进度 / 新事实 / 交付物 /
   明确卡点），或需要本人拍板；
2. **真人明确在问**：人点名问我、派活给我、要我表态。

机器消息（告警、催办卡、自动通知）里的 @ 按角色字段处理（处理人 / 跟进人 / 知会人）：
先看正文实际要谁做什么，指向别人就只当知会、不代答。机器人刚发过的、卡片里写着的、
自己说过的都不算增量；平台已经催过的不跟催。轮到自己必须出手的节点（截止已过、状态变了、
对方承诺的时间过了）才发，且只说新增部分。判不准就沉默，沉默只记日报（`[未回]`）。

四处同一口径：`RIGHTS_DEFAULT`（代码单点）、`rightsLine()` / `buildOpenPrompt`（载荷）、
根 `SKILL.md`（agent 规则）、面板占位与说明（人看的那份）。

## 备选

| 备选 | 为什么不行 |
| --- | --- |
| 只在 `SKILL.md` 里加一句「机器人消息别回」 | 每轮载荷先给的是代码里的默认摘要，两套口径会打架；面板显示的也是旧默认 |
| 把 bot 消息从唤醒里过滤掉 | 改的是唤醒范围，用户没要求；bot 卡片之后处理人的回复仍要跟进，截止日还会再提醒 |
| 保留「信息同步可以发」 | 这次超发的直接原因就是它被理解成「把知道的说一遍」；改成「有增量的信息同步」仍允许同步 |
| 每个机器人群的工作本写一段窄口径 | 同一角色分工会在几十个自动群里重复；默认值应该是一处常量，按群覆盖只留例外 |

## 后果

- 接受：默认更保守，可能漏掉「其实该说」的场合。兜底是：机器卡片之后真有人回仍会唤醒；
  截止日的再次提醒本身是新增量。
- 接受：改默认要发版（0017 的既有成本）；已写自定义发言权的群不受影响。
- 接受：面板默认文案变了，用户需要重新读一遍。
- 重新考虑的触发条件：
  - 出现「该催没催、截止错过了」的可复现样本（说明节点提醒不够）；
  - 机器人的卡片不再带处理人、只点跟进人（角色字段语义变了）；
  - 用户明确要求机器消息也要主动汇报。

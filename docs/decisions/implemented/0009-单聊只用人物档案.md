# 0009 单聊只维护一份人物档案，群保留两层

> 状态: implemented
> 日期: 2026-11-05
> 关联: spec 0035、ADR 0008

## 背景

ADR 0008 把画像拆成「人物档案 + 会话工作本」，本意是让人的评价跨会话复用、让群规不被
个人评价淹没。上线（0.14.0 / 0.14.1）后私聊出现了同一件事的两种落点：

- 每条私聊既有 `profiles/<platform>/<chat_id>.md`（工作本），又有
  `profiles/people/<platform>/<person_id>.md`（人物档案）；
- 加入值守时插件仍会 `ensure` 工作本，于是私聊凭空多一份 md；
- 唤醒载荷对私聊同时给两条路径，agent 每轮都要判断写哪份；
- 面板人物卡片的「私聊工作本」入口点开没有编辑区（`personBookEditor` 从未被调用），
  是死代码。

单聊里「这个会话」就是「对面这个人」，两层没有换来任何跨会话收益。用户原话：
「单聊模式 不要搞两层md了，单聊直接用目标人的md就好了 你搞两层 多余」。

## 决策

- **单聊只有一份记忆文件**：对面那个人的人物档案。插件不再创建、不再展示、载荷不再给
  私聊的会话工作本；只在这条私聊成立的备注也写进这份档案，用「私聊：」开头。
- **群保留两层**：群规与工作要求不属于任何一个成员，仍写会话工作本；成员评价写人物档案。
- **旧私聊工作本整文件搬迁**：第一次被面板或值守碰到时，若人物档案还不存在，把旧工作本
  原样搬进人物档案路径（复制成功后删旧文件，不覆盖已有档案；不改写、不拆段）；人物档案已存在则旧文件保留，载荷给
  「旧私聊工作本（待并入）」与 `.history.md` 目标，由 agent 合并归档。
- **推不出人物 ID 的私聊仍退回工作本**（钉钉 `senderId` ≠ `userId` 未验证）：宁可多一份
  兜底，也不把内容静默写到错的人身上。

## 备选

| 备选 | 为什么不行 |
| --- | --- |
| 私聊继续两层，只在面板隐藏工作本 | 文件与载荷仍是两套，agent 每轮还要判断写哪份；用户要的是少一份文件 |
| 群也合并成一份 | 群规与对成员的评价生命周期不同，多群遇到同一人会重复评价（ADR 0008 的结论） |
| 用脚本按语义把旧工作本拆进人物档案四段 | 归属是语义判断，脚本拆会静默错归因，违反「不替你说错话」 |
| 旧工作本直接删、让 agent 重建 | 已有结论第一眼就丢了；面板会显示空档案 |
| 给 `state.chats` 加 `person_id` 记住注册时的 ID | 要升 state 版本；消息到达后 `recent[].sender_id` 已够推导，钉钉映射仍未定 |
| 人物档案再分「私聊 / 群」两节 | 同一事实在群里也可能成立；「私聊：」前缀足够，不必把模板长成两层 |

## 后果

- 接受：单聊人物档案增长更快（渠道备注也进来），更容易撞 8/12KB；靠心跳整理与
  `.history.md` 归档兜底。
- 接受：旧私聊工作本搬迁后旧路径消失；回滚代码后内容仍在人物档案里，只是路径换了，
  需要旧路径时手动移回，不需要清 `state.json`。
- 接受：钉钉私聊继续用工作本兜底，直到真机确认 `senderId` = `userId`。
- 重新考虑的触发条件：如果将来一个「人」需要多套互相冲突的单聊口径（例如同一人在两个
  租户下要求不同），再评估按会话分文件，而不是把工作本加回来。

# 0006 富媒体由插件取回，图片随唤醒载荷交付

> 状态: implemented
> 日期: 2026-11-03
> 关联: `docs/specs/archive/0017-standin-reliability.md`

## 背景

DSH 插件壳在宿主进程里跑平台 CLI，已经在为每个值守会话拉消息；`lark-cli` 提供
`+messages-resources-download` 与 `--download-resources`，DSH 宿主也有
`ctx.attachments.admitPromptContent()`，可以把图片转成 durable `image` block 放进
user message。也就是说，插件有能力在唤醒时把图片/文件取回来，和文本一起交给会话，
不需要让模型先看到一个 `img_...` key 再自己想办法。

另一方面，`state.json` 的定位是“每会话最近 10 条指针”，不能变成媒体库；面板也没有
资源路由，浏览器拿不到本地文件。平台差异也真实存在：企微媒体要走 `wecom-cli media`，
钉钉在插件壳里没有 adapter，卡片/合并转发/位置等类型没有稳定的资源取法。

## 决策

**插件在命中唤醒时取回适配的媒体，随唤醒载荷一起交付：**

- 图片下载后通过 DSH `attachments.admitPromptContent()` 转成 `image` block，和文本一起
  进入 user message，模型直接可见；
- 文件/语音/视频下载到 `~/.im-standin/media/`，prompt 给本地路径，agent 用文件工具读；
- 同一批消息的下载有上限（4 张图 / 10MB / 单条 20 秒），失败只降级，不阻断 turn；
- **只有未适配的类型**（卡片、合并转发、位置、名片、系统消息、未知类型，以及平台下载
  命令不可用/失败的消息）才在 prompt 里标“可用 CLI 取”，并带 `msg_id`/`media_id`；
- `state.json` 只存 `msg_type` / `app_link` / `media_id` / `media_paths`，不存二进制；
- 面板不内嵌预览，只给“在 IM 客户端打开”或“已在会话中附带”。

## 备选

| 备选 | 为什么不行 |
| --- | --- |
| 只把媒体 key 放进 prompt，让 DSH 会话自己用 CLI 取 | 模型看不到图片；把下载/鉴权/失败处理全丢给 agent，用户明确否掉 |
| 插件下载后只给本地路径、不 attach | 模型仍然看不到图；图片应作为 image block 随消息交付 |
| 每轮 poll 都下载媒体 | 没人发消息时也打下载接口，违背“等待期零成本”；只在唤醒时取本批 |
| 把二进制存 `state.json` 或新开 `/api/resource` | 指针状态变成媒体库，增加存储/清理/鉴权/路径穿越面，和“插件只当壳”冲突 |
| 面板直接嵌平台临时 URL | 飞书媒体 URL 需要鉴权，可能带 token；把短期链接暴露给浏览器/日志 |
| 只适配图片，文件/音视频继续走 CLI | 客户发文件是真实场景；文件不 attach 也可以给本地路径，成本很低 |
| 给钉钉补插件 adapter | 平台差异大、没有实测授权链路；先如实标注，独立 skill 继续支持 |

## 后果

- 接受：唤醒时多一次下载，turn 启动会慢一点；用 20 秒超时、单批上限和失败降级兜住。
- 接受：本地媒体目录需要 7 天/200MB 清理，并在清理后回写 `recent.media_paths`。
- 接受：图片能否被模型看到取决于当前 DSH 会话模型是否支持 image 输入；不支持时
  只能给本地路径并说明“当前模型不可读图”，不能假装看得到。
- 接受：企微/钉钉/卡片类消息仍可能只能转人工；这是平台能力边界，不猜。
- 重新考虑的触发条件：DSH 原生提供 IM 媒体拉取/附件查看；或用户要求面板内嵌预览，
  且愿意接受新的资源路由与缓存清理策略。届时另写 ADR，不在本决策上打补丁。

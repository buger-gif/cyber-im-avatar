# 0010 会话寿命跟随保温节奏

> 状态: implemented
> 日期: 2026-11-06
> 关联: spec 0036

## 背景

0.12.0 给插件壳定了两个独立时钟：`dsh.warm_min`（默认 55 分钟）做保温，`dsh.idle_reset_min`
（默认 180 分钟）闲置换会话。默认值下一通没人说话的会话会连续保温约 3 次，用户要求
「保温只做一次；第二个保温周期还没有新消息，之后来新消息就开新会话」。

两个键并存时，用户很难从面板上的两个数字算出「到底多少分钟换会话」；实际触发点取决于
两者中哪个先到，还要叠加保温轮不推进闲置时钟的规则。

## 决策

只保留 `dsh.warm_min` 作为会话寿命的唯一时钟：每段连续闲置最多保温一次；再过一个
`warm_min` 仍无真实消息，下一条消息换新 DSH 会话。`dsh.idle_reset_min` 退役。

## 备选

| 备选 | 为什么不行 |
| --- | --- |
| 保留 180 分钟作为上限，取两者更早 | 用户明确要「完全以保温为准」；两个键并存仍要解释两个数字，且默认 110 分钟会先到，180 实际不生效 |
| 每个 DSH 会话一辈子只保温一次 | 中间来过真实消息后缓存照样会冷；用户选择按「一段闲置」重新给一次额度 |
| 定时器到点主动换会话 | 没人说话时换会话没有收益；懒到下一次消息才换，读数最准，也不动旧会话 |
| `warm_min=0` 时保留一个隐式的 180 分钟兜底 | 「关闭保温」却仍偷偷换会话，比多一个键更难解释；要换就把间隔调大，要停就接受不换 |
| 把 `idle_reset_min` 留成 no-op 但保留面板输入 | 面板上留着不生效的数字比删掉更误导；老配置加载时静默丢弃即可 |

## 后果

- 接受：换会话的最早时间从「180 分钟」提前到「约 2×warm_min」（默认约 110 分钟）；想让
  会话活得更久，就把 `warm_min` 调大，而不是另调一个键。
- 接受：`warm_min=0` 同时关闭保温与自动换会话；面板与 CHANGELOG 必须写明。
- 接受：老配置里的 `dsh.idle_reset_min` 被静默丢弃，不迁移、不报错。
- 重新考虑的触发条件：出现「想保温但不换会话」或「想换会话但不保温」的真实需求，且不能
  通过调整 `warm_min` 满足；或者第二个周期的实际成本读数证明保温一次仍然太贵。

# 0014 载荷只声明变化：口径按会话记住，未变不重复

> 状态: implemented
> 日期: 2026-11-12
> 关联: spec 0045

## 背景

0043 把发送方式做成值班单点配置后，选择是「每轮唤醒 / 开场都在载荷末尾声明实际生效值」，
理由是模式可能中途切换，旧会话里的口头约定不可信（0013）。同一时期，关注程度说明与
本人指令规则也是每轮复读。

真实使用中，这些值在同一条 DSH 会话里通常长期不变：普通命中载荷只有 1 行消息，却固定跟着
3–4 行发送方式；本人每次 @ 自己下指令，同一段规则原文复读一遍。用户在自己的值守会话里
看到的是连续多轮完全相同的尾巴，明确要求「没变的值不要来回一直追加」。

约束没有变：切换模式必须下一轮就生效；换 DSH 会话 / 重开后 agent 不能靠猜。区别只在于
「重复」是不是唯一手段。

## 决策

- 每条 DSH 会话在插件内存里记一份「已声明口径」`{ send_mode, wake_mode, cmd }`
  （key=`platform:chatId:sessionId`，上限 64；换会话 / 重开 / 进程重启后为空）。
- 唤醒载荷只在**首次**或**取值变化**时追加发送方式 / 关注程度注记；本人指令规则只在
  该会话第一次出现 `cmd` 时追加。未变的轮次只追加消息行。
- 变化注记保留 `发送方式：<新值>` 前缀并在括号里写「已从 X 切换」，切换当轮即可见。
- 记录只在 `agent.followup()` 成功之后写回（`runTurn` 的 `onSent` 钩子），载荷没送出去
  不会被误记为已声明。
- 口径的持久依据放 `SKILL.md`：本人 @ 自己 = 指令、回复里不要 @ 本人自己；发送方式以
  本会话最后一次声明为准，没声明过时默认草稿审批。
- 会话被 DSH 压缩（`compaction/summary` 或成功的 `compaction/end`）时清空该会话的记录
  与已给过的人物档案指针，下一轮把口径与路径完整重带一次；失败的压缩（`compaction/end`
  带 `error`）不算。

## 备选

| 备选 | 为什么不行 |
| --- | --- |
| 维持每轮重复 | 换会话 / 上下文被压缩后不会丢口径，但每轮固定多 3–5 行噪声；用户已明确否决。 |
| 只在首轮声明一次 | 模式中途切换时不会生效，agent 会继续按旧模式，面板切了像没切。 |
| 每轮输出一行现状（「发送方式：全自动」） | 仍然每轮占一行，只是变短；与「没变就不追加」诉求冲突。 |
| 把「已声明口径」持久化进 `state.json` | 重启后少声明一次，但要加字段、改契约、写迁移；收益远小于成本，内存记录已够。 |
| 本人指令规则继续每轮重复 | 防回环最稳，但同样属于用户点名的复读；改为会话内首次声明，另有 poller 5 次 / 10 分钟熔断与 skill 常驻规则兜底。 |
| 未变时输出「（口径未变）」占位 | 依旧每轮多一行，信息量为零；干脆不输出。 |
| 不检测压缩，只靠 skill 常驻规则 | 压缩后上下文里可能已经没有声明，agent 只能默认草稿；DSH 有确定性的 `compaction/*` 事件，没理由靠猜。 |
| 压缩后让所有值班都重声明 | 压缩只影响一条会话；按 `session.id` 精确清掉那一条的记录即可。 |

## 后果

- 接受：DSH 压缩会替换掉一段历史，插件靠 `compaction/*` 事件在下一轮补声明一次；
  若事件缺失（旧版 DSH）或只是截断而非压缩，兜底是 `SKILL.md` 常驻规则 +「本会话最后
  一次声明为准、没声明过默认草稿」+ 面板随时可切。
- 接受：进程重启后第一条命中会补声明一次（内存记录丢失），之后恢复不重复。
- 接受：压缩检测依赖 DSH 的 `compaction/*` 事件名；旧版没有时退化为 skill 常驻规则兜底。
- 接受：切换发送方式 / 关注程度只在下一轮唤醒或开场可见，正在跑的那一轮仍按旧设置收尾
  （与 0013 的既有口径一致）。
- 重新考虑的触发条件：
  - 出现可复现的「agent 因不知道发送方式而漏发 / 误发」，且 skill 常驻规则也覆盖不了；
  - DSH 会话压缩策略变化，导致长会话里口径大面积丢失；
  - 用户反过来要求每轮保留一行状态（届时改注记形式，不改取值来源）；
  - DSH 改变压缩事件名或载荷，导致压缩后无法确定性补声明。

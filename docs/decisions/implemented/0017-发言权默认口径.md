# 0017 发言权默认口径：默认值先行，按群覆盖

> 状态: implemented
> 日期: 2026-11-18
> 关联: spec 0051（修订 `docs/decisions/implemented/0016-发言权契约.md` 的降级规则）

## 背景

0016 的规则是「工作本里的发言权段为空 → 该群本轮强制草稿，写完自动恢复」。它随 0.24.0
发出去后，当场暴露三个问题：

1. 存量群的工作本里都没有这一段，于是**所有全自动群一夜之间掉到草稿**；
2. 恢复的办法是「让用户先写一句话」，等于把「没有默认值」的成本转给用户；
3. 产品其余部分都是「默认值跑、想改再改」，只有这里是「不配就不许自动」。

同时默认口径本身太保守、只会防守：群里最常见的两种情况都被判死——**没点任何人、但问题是给你/
需要你表态的**，以及**信息同步**（把已确认的进度/结论发到群里）。

## 决策

发言权有一份内置默认口径（`RIGHTS_DEFAULT`，代码里单点维护，不落盘）；工作本那段为空就用默认
（`custom=false`），写了就覆盖（`custom=true`）。发言权不再影响发送方式——默认值一上来就有，
用户不需要为它做任何事，想改才点进去改。

默认口径按「这条点名了谁」排顺序：

- 点我名：回（这是给我的）
- 点了别人：只当知会，不代答；除非那条明确也在问我
- 没点任何人：先判断——问题悬在群里、任务派到我头上、需要我表态或给结论 → 回；
  纯告警、寒暄、别人之间的对话 → 沉默
- 信息同步：已确认的进度、结论、事实，可以主动发到群里
- 判不准：沉默，等下一次点名

## 备选

| 备选 | 为什么不行 |
| --- | --- |
| 空段 → 强制草稿（0016 的做法） | 老群集体降级；恢复要用户手写；把默认值缺失的成本转给用户。上线二十分钟就被真实使用否掉 |
| 把默认文本写进每个群的工作本 | 几十份副本会各自漂移，改默认口径要迁移数据；默认值应该是一处常量 |
| 只展示口径、不给按群覆盖 | 每个群分工不同（跟进人 / 负责人 / 旁观），没有覆盖点就只能靠提示词兜 |
| 默认只写防守（只回点名的） | 「没人点名但答得了」「信息同步」会被判死，等于把「只看不回」换个说法，用户会关掉值守 |
| 让 agent 每轮自己从零判断该不该说 | 正是 0.24.0 之前的形态：没有规范、只有开放式邀请，事故就是这么来的 |

## 后果

- 接受：默认口径在代码里，**改默认要发版**；按群覆盖仍在面板，改单个群不用发版。
- 接受：默认口径比 0016 主动（允许答没人点名的问题、允许信息同步），判错时会更快说错话。
  兜底是「发言要说清为什么由你出面」+ 面板按群改 + skill 铁律（钱/合同/承诺/外部群一律停）。
- 接受：面板显示「默认口径 / 本群已改」，不显示「未定义」——没有「未定义」这个状态了。
- 重新考虑的触发条件：
  - 真实群里几乎每个群都被单独覆盖（说明默认口径不值钱，应该换一套默认）；
  - 出现「默认口径下代答了本该归属人答的问题」的可复现样本；
  - 有人确实需要「关了自动发言」这个档（现在只能改成很窄的口径，没有硬开关）。

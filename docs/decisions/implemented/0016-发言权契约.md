# 0016 发言权契约：授权边界写进工作本，未定义就不自动发

> 状态: implemented
> 日期: 2026-11-18
> 关联: spec 0051（并触发 0013 的「重新考虑」条件）

> 降级规则（「未定义就不自动发」）已由 `docs/decisions/implemented/0017-发言权默认口径.md` 修订：
> 发言权改为「内置默认口径 + 按群覆盖」，不再影响发送方式。其余结论仍然有效。

## 背景

0013 拍过：发送方式交给用户显式设定，插件只声明、不代发，兜底靠 skill 铁律与默认草稿；
并把「agent 在 `auto` 下出现可复现的越界发送，且 skill 铁律无法收敛」列为翻案条件。

2026-11-18 出现了这个信号：飞书群里某值班机器人 @ 的是处理人，值守账号是同一个群的
跟进人，`send_mode=auto`，agent 在开场轮以跟进人身份代处理人回了「我先看下代码」。
凭证链显示 @ 识别是对的——库里那条消息被判 `fyi`、`skip=no-mention`，`duty.trigger` 仍是
`added`。错的不是判据，而是**开场轮没有可依据的授权边界**：载荷只给「有该回的就按 skill 回」
这种开放式邀请，加上当时工作本还是空模板，agent 无从知道「我在这群是谁、什么该我管」。

同一时间另一个事实：把 `wake_mode` 收紧成「只 @ 我就回」并不能解决问题——新建群经常
没有任何 @ 但任务确实落在本人身上。**注意力（省 token 的启发式）与发言权（正确性）被
绑在 mention 这一个信号上**，于是收紧就漏、放松就错，两头都是同一个错误的两个方向。

## 决策

每个群有一份**发言权契约**，落在会话工作本的固定小节；插件只做两件确定性的事：
把事实（本人身份、谁被 @、本批是否点你名）交给 agent，并在契约未定义时把该群本轮的发送
方式降为草稿。契约写好后全自动自动恢复——**这是依赖关系，不是开关**。

## 备选

| 备选 | 为什么不行 |
| --- | --- |
| 收紧成「没 @ 你就禁止发送」 | 把「多发一条」换成「漏回一条」：新群没 @ 任何人、但任务显然属于本人的场景会被判死。事故的两个方向只是换了个朝向。 |
| 开一个 `loose` 关注程度档 | 现有 `all` 就是「每条都看」，错的是它文案里写死的「非点名的群消息只看不回」；加模式等于把同一件事建模两遍。 |
| 让插件在发送时做闸门（注册发送工具 / 关键词黑名单） | agent 用平台 CLI 直发，插件拦不住；注册工具也能被 CLI 绕过，除非把 CLI 移出沙箱，而那会毁掉「复用本机登录态」。0013 已否过关键词闸门。 |
| 每轮都让 agent 写一份决策 JSON 才能发 | 没有强制点（发不出去脚本照样能发），只会把判断变成填表，还把正文与判断落进插件状态，违背 0004。 |
| 契约放独立文件 | 工作本里已经有「群内工作要求 / 成员与角色」，契约属于同一类东西；拆两个文件等于同一份规范长两处，agent 读哪份都可能过期。 |
| 发言权交给 skill 写死（提示词里给一套通用规则） | 每群的角色不同（跟进人 / 负责人 / 旁观）；通用规则只能覆盖平均情况，正是这次误判的成因。 |
| 新群首轮一律强制草稿（一次性） | 只防第一次；保温过期换会话又是一个「第一次」。且它只拦发送，不改善判断，等于用退让掩盖缺失。契约缺失时降级覆盖了它，而且会自愈。 |

## 后果

- 接受：多一份要维护的东西。它落在工作本里、由开场轮写第一版、由人在面板改；agent 只读，
  用户要求时才改。写与读是同一个文件，不会出现双源。
- 接受：契约未定义期间该群只能出草稿。这是有意的不对称——以本人身份发错话不可恢复，
  漏一次回复可以补。
- 接受：契约是人写的自然语言，插件只做结构判断（小节存在且非空），不解析语义；语义错了
  仍然是人的责任，但错误可见、可改。
- 接受：插件仍然无法阻止 `auto` 下的违规发送。这条与 0013 的结论一致，只是把兜底从
  「skill 铁律」前移到「先有授权边界」。
- 重新考虑的触发条件：
  - 契约段在真实使用中长期为空（说明开场轮写不出有用的契约），就该改成按平台/按群类型模板；
  - 出现「契约是对的、agent 仍越界」的可复现样本，则说明缺的是执行侧闸门而不是授权边界；
  - 平台提供可编程的发送前审批，再考虑把降级从「提示」升级成「拦截」。

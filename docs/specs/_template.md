## 背景

现状是什么、谁遇到了什么问题、为什么现在要做。**只写事实**，不写方案。
能给出读数就给读数（多少会话、几次调用、多长耗时）。

## 目标与非目标

- 目标：一句话说清做完之后哪件事变好了。
- 非目标：明确这次不做什么，防止范围蔓延。

## 方案

按「段」拆，每段回答一个问题。涉及接口 / 表 / 配置的，直接写形状（字段名、类型、默认值），
并注明要同步哪份契约。

## 取舍

| 备选 | 否掉的理由 |
| --- | --- |
| 方案 B | 为什么不行 |

有拍板价值的（影响后续架构）另写 `docs/decisions/`，这里只留一句指针。

## 影响面

- 代码：哪些文件
- 契约：哪几份要同 commit 改
- 用户可见：面板 / CLI / 升级行为
- 兼容：老配置、老数据怎么办

## 验收

每条都要能跑命令或点一下验证，不写「功能正常」这种话。

- [ ] 具体动作 → 期望结果
- [ ] 具体动作 → 期望结果

## 风险与回滚

- 风险：最坏情况是什么
- 回滚：撤哪个 commit / 关哪个开关，数据要不要清

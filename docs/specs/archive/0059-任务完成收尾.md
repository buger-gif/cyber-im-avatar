# 0059 任务完成收尾

> 状态: 实施中
> 编号: 0059
> 版本: 0.26.0
> 关联: 实施时同 commit 改 `docs/specs/contracts/02-storage.md`、`03-config.md`、
> `01-api.md`；与 0057 的 7 天无命中退役并列

## 背景

0057 解决的是「一直没人找它」的静默值守：连续 7 天没有命中就退。但还有一类会话不是静默，
而是**活已经干完了**：群里的事上线 / 验收 / 关单结束，或者某个人找分身办的事已经交付、
没有后续问题。这种会话会一直占着值守位，每次轮询、每次保温都在为一个已经结束的任务花钱。

用户希望在「会话保活」判断时顺手判断这件事：任务已经干完、或某人的活已经结束，就记一笔
「可以关了」，但**不是立刻关**——两天内没人再让它干活，才真正退出；两天内来了新活，就
取消收尾、继续值守。

## 目标与非目标

- 目标：保活轮可以由 agent 判断「任务完成」，写一个结构化收尾标记；插件记成
  `duty.state="closing"` 并给 2 天观察期；到期无新活就退役，有新消息/待回/在飞就取消。
- 非目标：不在客户消息轮里判断收尾；不立刻关闭；不解析聊天正文做语义判断；不替代 0057
  的 7 天静默退役；不删除会话、画像或 DSH 会话。

## 方案

### 1. 谁来判断、在哪判断

- 只在**值守心跳（保活轮）**里判断：这一轮已经在读工作本 / 人物档案，是最便宜的判断点；
  不额外拉 IM 消息、不发消息。
- 判断依据只给两样：载荷列出的记忆文件（群的「本会话结论与待办」、单聊的人物档案 / 历史结论）
  与本会话已有上下文。看不出「干完了」就不写。
- 判断是 agent 的语义决定；插件只认结构化标记，不读自然语言、不猜。

### 2. 收尾标记

心跳轮的 assistant 消息末尾，单独一行：

```
[值守收尾] 任务已完成：<≤40 字原因>
```

- 只在 `warm=true` 的轮次里解析；客户消息轮、开场轮里出现同样的行一律忽略。
- 同一轮有多个 assistant 消息时取最后一条非空文本；只认行首 `[值守收尾]`。
- 标记行不会自动发到 IM；prompt 明确要求「不要写进发给会话的正文」。
- 没有标记 = 继续值守，不做任何状态变化。

### 3. 状态机

`duty.state` 增加 `closing`，`duty.close_at` 记观察截止（epoch 秒），`duty.trigger` 增加
`warm`。标记命中后：

```
watch/none ──[值守收尾]──▶ closing(close_at = now + close_after_days×86400)
closing ──新命中/待回/在飞/手动操作──▶ watch（取消收尾）
closing ──到期且没有新活──▶ retired（自动退役）
```

- 标记写入：`state="closing"`、`by="agent"`、`trigger="warm"`、`decided_at=now`、
  `reason=<标记原因>`、`close_at=now + close_after_days×86400`。
- 拒绝标记：`pendingCount>0`、正在试用 / 排队 / 分诊、未值守、已屏蔽、`close_after_days=0`。
- 取消收尾：新命中消息在 `process()` 里直接改回 `watch` 并清 `close_at`；到期检查时若发现
  `pending > 0`、在飞 turn、`wake.active`、`progress.state=running`，同样取消而不是关。
- 到期关闭：复用 `duty.retire()`，`state="retired"`、`by="system"`、
  `reason="任务已完成，N 天无新活"`、`close_at=0`、`decided_at=now`。
- 7 天静默退役（0057）跳过 `closing`，两条路径不抢同一个会话；`close_after_days=0` 时
  现有 `closing` 直接取消回 `watch`，不留下卡死状态。

### 4. 运行位置

- `maybeClose()` 与 `maybeRetire()` 并列，放在同一个后台维护 tick 里，在 `maybeWarm()` 前；
  不依赖 `dsh.warm_min`、不依赖 DSH 宿主、不跑模型。
- 标记解析在 `turns.runTurn()` 的 warm 分支：捕获最后一条 assistant 文本，`result.ok` 时
  调 `duty.markClosing()`。解析失败只记日志，不影响心跳结果。
- 不需要新路由；不需要 agent 写文件，因此不受 `dsh.full_access` 影响。

### 5. 配置与面板

- 新配置键 `duty.close_after_days`：默认 `2`，范围 `0–30`，`0=关`。
- 面板「值守分诊」增加「任务完成收尾（天，0=关）」；说明写「保活轮判断干完了才记，
  2 天内没有新活才退，新消息自动取消」。
- 会话详情的状态标签：`closing` 显示「任务已完成 · 观察中」并带剩余时间；`retired` 的
  reason 区分「7 天无命中」与「任务完成」。
- `/api/duty` 的 counts 增加 `closing`；`/api/chats` 已带 duty，无需新路由。

### 6. 与 0057 的关系

| 场景 | 路径 |
| --- | --- |
| 没人找它，静默 7 天 | 0057：`retire_after_days` → `retired` |
| 保活轮判断活干完了，2 天没新活 | 0059：`closing` → `retired` |
| 收尾观察期内来了新活 | 取消 `closing`，回到 `watch`；7 天时钟从新命中重算 |
| 收尾关闭后群里又有新个人 @ | 与 0057 一样，sweep 重新分诊，不直接恢复 |

### 7. 实施步骤

1. `duty.js`：`closing` 枚举、`close_at`、`markClosing()`、`cancelClosing()`、`close()`、
   标记解析；`retire()` 支持自定义 reason。
2. `state.js`：`duty.close_after_days` 配置 + duty 字段 / 枚举。
3. `poller.js`：`maybeClose()` 接进 tick；`process()` 命中时取消 closing；`maybeRetire()`
   跳过 closing。
4. `turns.js`：warm 分支捕获最后 assistant 文本并解析标记；`buildWarmPrompt` 增加可选的
   收尾判断说明（`close_after_days=0` 时不出现）。
5. 面板配置与状态标签；重建 `client.js`。
6. 契约 01/02/03、architecture / README / CHANGELOG 同步；补测试。

## 取舍

| 备选 | 否掉的理由 |
| --- | --- |
| 保活轮判断完立刻关 | 误判一次就丢掉一个还在用的会话；2 天观察 + 新消息取消是纠错窗口 |
| 插件自己读聊天判断任务完成 | 需要理解语义，违反「插件只做确定性搬运」；判断归 agent |
| 用 decision 文件让 agent 写 | 心跳轮 cwd 是工作区，不一定能写 `~/.im-standin/duty`；标记行不受 `dsh.full_access` 影响 |
| 把 2 天并进 7 天 | 静默 7 天与「任务已完成」是两回事；合并会把刚干完的会话再拖 7 天 |

## 验收

- [ ] 心跳轮写 `[值守收尾] 任务已完成：…` → `duty.state=closing`、`close_at≈now+2d`
- [ ] 2 天内无新消息，到期 → `retired`，reason 含「任务已完成」
- [ ] 观察期内来新私聊 / 个人 @ / 待回 / 在飞 → 取消 `closing`，回到 `watch`，不关闭
- [ ] 客户消息轮里出现同样的标记 → 忽略，不改变状态
- [ ] `close_after_days=0` → 不产生新的 `closing`；已有 `closing` 取消回 `watch`
- [ ] 7 天静默退役跳过 `closing`，不会提前按 7 天路径关闭
- [ ] 面板 2 / 0 可保存；详情显示观察中与剩余时间
- [ ] `node --test`、`python3 tests/run_tests.py`、`bash scripts/gate.sh --quick` 全绿

## 风险与回滚

- 风险：agent 过早判断「干完了」，2 天后关闭，之后才来新活。缓解：2 天观察、任何新命中
  立即取消、群新 @ 可重新分诊、私聊可手动重加、设置可关。
- 风险：标记行被写进发给 IM 的正文。prompt 明确禁止；插件只解析 warm 轮，客户轮不认。
- 回滚：`duty.close_after_days=0` 立即停用；撤代码后 `closing` 归一成 `watch`（枚举不含时
  按 none），不会误关。

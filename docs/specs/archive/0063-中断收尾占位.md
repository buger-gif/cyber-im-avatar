# 0063 中断收尾占位

> 状态: 已验收
> 备注: 随 0.27.0 发；桌面 app 复核挂账 `docs/implementation/PROGRESS.md`
> 编号: 0063
> 版本: 0.27.0
> 关联: 上游 [Discussion #14340](https://github.com/deepseek-ai/deepseek-harness/discussions/14340)

## 背景

DSH 0.2.2-rc.5 在流式回答被取消时（手动停止、插件 `agent.cancel`、看门狗超时），如果模型
只产出了 reasoning、还没有任何正文或工具调用块，会按「保留已交付前缀」的既有设计持久化：

```json
{"type":"assistant/message","data":{"interrupted":true,"message":{"role":"assistant","content":[{"type":"reasoning","text":"..."}]}}}
```

下一轮请求把这条消息序列化成只含 thinking 块、没有 text / tool_use 的 assistant 消息；严格
按 Anthropic Messages 协议的网关直接返回 400 `invalid_parameter_error: The content field is
a required field.`。消息常驻历史，之后每轮都在 0.5 秒内失败、一个 token 都不产出，重试 /
重开会话 / 重启 App 都不能自愈。

上游定位在 `packages/core/agent-loop/src/agent.ts`（`interruptedBlocks()` 非空就落
assistant/message，只有 reasoning 也算非空）与 `packages/llm/llm-deepseek/src/serialize.ts`
（只跳过转换后内容为空的 assistant 消息；只有 reasoning 会转成非空 thinking 块）。master 与
`dsh-v0.2.3-alpha.2` 都未修。本插件不能改 DSH 安装目录（app.asar）与 `~/.dsh` 下的
vendor 代码，只能在宿主进程内做本地兜底。

## 目标与非目标

- 目标：任何会话写 `assistant/message` 且 `interrupted === true`、内容里没有正文 /
  tool-call / image 时，在写入那一刻追加一个占位正文块，让后续模型请求合法；会话不再永久卡死。
- 目标：不改事件类型、不改 seq、不改已有历史、不改用户看到的转录。
- 非目标：修上游；改 DSH 安装目录 / app.asar / vendor 代码；处理已经卡死的存量会话；改
  state.json 配置键或面板。
- 非目标：把占位文案写进用户可见的聊天记录。它只存在于模型请求历史。

## 方案

### 挂点

新增 `dsh-plugin/lib/guard.js`，导出 `installReasoningGuard(ctx)`；在
`dsh-plugin/lib/index.js` 的 `apply()` 里调用一次。模块只定义常量和函数，没有顶层副作用。

安装分两路，覆盖启动先后：

1. `ctx.on("session/created", (session) => install(session))` 覆盖新会话；
2. `ctx.inject(["sessions"], (hostCtx) => hostCtx.sessions.list().forEach(install))` 覆盖插件
   就绪时已经存在的会话。

两路都先注册监听再扫已有列表，避免中间新开的会话漏掉。安装是实例级包装
`session.append`，不改 `Session.prototype`；同一个 session 用
`Symbol.for("dsh-cyber-im-avatar.reasoning-guard")` 标记 + 模块内 `WeakSet` 保证只包一次。
包装函数必须返回原 append 的返回值（agent loop 依赖返回的 `seq`）。

### 命中条件

以下全部满足才补块：

- 事件类型是 `assistant/message`；
- `data.interrupted === true`；
- `data.message.content` 是数组；
- 内容里没有非空白 `text` 块、没有 `tool-call` 块、没有 `image` 块。

命中后用浅拷贝构造新对象，不原地改 frozen 的 data / message / content：

```js
{
  ...data,
  message: {
    ...data.message,
    content: [...data.message.content, { type: "text", text: GUARD_BLOCK_TEXT }],
  },
}
```

### 占位块的写法

文案抽成 `REASONING_GUARD_TEXT`：

```
（上一轮在思考阶段被中断，未产生内容）
```

实际写进 content 的 `text` 是 `[//]: # (文案)`。这是 Markdown 链接定义：GFM 把
`definition` 节点渲染为 `null`，所以聊天转录看不到占位文案；序列化仍把它当普通 `text`
发给模型，满足「assistant 消息必须有正文 / tool_use」的要求。若直接写裸文案，DSH 会把它
当正文渲染给用户，违反「不改转录显示」。

### 安全与开关

- 包装内只把守护逻辑放进 try/catch；一旦判断 / 构造失败，就按原参数调用原 append。
- 原 append 抛错时异常原样抛出，不吞掉、不重试（agent loop 靠异常结束本轮）。
- 安装 / 命中时用现有 `console` logger 打一行 `[im-standin]` 前缀日志，只带 session id 与
  seq，不打印任何消息内容。
- 环境变量 `IM_REASONING_GUARD=0` 关闭（默认开启）；关闭时完全不挂监听、不包装。
- 不写任何 session 日志文件，不碰已有的 `session.v4.jsonl.zstd`。

## 取舍

| 备选 | 否掉的理由 |
| --- | --- |
| 改 `serialize.ts` 丢弃无正文的 assistant 消息 | 要改 DSH 安装目录 / vendor 代码，违反约束；上游修好后也不能随插件撤 |
| 改 `agent.ts` 不落 reasoning-only 消息 | 同上，且会丢掉已交付前缀的既有设计 |
| 直接写裸占位文案 | 模型请求合法，但聊天转录会多出一行假正文 |
| 用只有空白字符的 text 块 | 序列化会跳过空 text，仍然 400 |
| 在 `llm.stream` 请求前改历史 | 不改持久化事件，重启 / 换路由后仍可能卡死；且要碰模型层 |
| 用 ZeroMQ / 空白 Unicode 混淆 | 模型请求里没有可读占位，排障不可见，不可取 |

## 影响面

- 代码：新增 `dsh-plugin/lib/guard.js`；`dsh-plugin/lib/index.js` 增加一次安装调用。
- 测试：新增 `dsh-plugin/tests/guard.test.mjs`。
- 配置：不新增 state.json 键；只新增环境变量 `IM_REASONING_GUARD`，不进契约 03。
- 用户可见：Transcript 不变；模型请求历史多一个不可见占位块；命中时 `~/.dsh/logs` 有
  `[im-standin] reasoning guard: ...` 一行。
- 兼容：只包装当前进程内的 live session；已有 `session.v4.jsonl.zstd` 不改。存量已卡死
  会话仍按主工作区的单独方案处理。
- 分发：`lib/guard.js` 随 `lib` 进包；不改 `client.js`，不需要重跑 `build:skill`（skill
  包只含 `SKILL.md` 与 `scripts/`）。若 `npm pack` 的 `files` 已含 `lib`，无需改 package.json。

## 风险与回滚

- 风险：占位块改变 DSH 对 assistant 消息的 surface 内容；若 UI 未来不再把 Markdown
  definition 渲染为空，占位文案可能露出来。降级手段是关掉开关。
- 风险：另一个插件也包装 `session.append`；实例级包装按安装顺序叠加，不冲突，但排查时
  需知道本插件是其中一层。
- 回滚：删掉 `apply()` 里的 `installReasoningGuard(ctx)` 调用，或启动前设
  `IM_REASONING_GUARD=0` 重启。无数据迁移、无存量文件改动。

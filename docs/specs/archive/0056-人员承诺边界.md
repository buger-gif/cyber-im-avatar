# 0056 人员承诺边界

> 状态: 实施中
> 编号: 0056
> 版本: 0.26.0
> 关联: 无接口 / state / 配置变更；改 `SKILL.md` 与唤醒载荷文案

## 背景

2026-11-23，一个值守会话里，对方在群里点名约「明天抽时间开个会」。agent 查了日历，直接回了
「明天 11 点可以」。工作本里已经写了「不替人答应时间」，但 agent 没有把「参会」归进承诺；
这一条必须硬停。

但边界不能一刀切。翻最近 18 份值守日报，日常动作集中在：漏洞状态对账 / 复测 / 修复 / 关单
（56 条）、查证 / 核对 / 分析（50 条）、解释口径 / 答疑（40 条）、文档 / 表格 / 清单（36 条）、
进度同步 / 催办 / 协调（57 条）、交付文件（27 条）；会议 / 参会只有 1 条。绝大多数是分身
**自己就能做完**的活——查漏洞、复测、修、写文档、解释、同步、催办。如果把「修问题、审文档、
发清单、代问」也列进「不能答应」，等于把主职工作停掉。

所以边界按**能力**分，不按「像不像承诺」分：分身能做完的直接做掉；只有需要本人未来亲自
到场、花时间、签字、付款、授权或拍板的事才停。

## 目标与非目标

- 目标：参会 / 约时间 / 出差 / 线下签字 / 价格合同付款 / 系统权限 / 公开发布 / 接受风险 /
  批准例外这类**只能由本人**做的事，分身不答应、不定时间，记日报 P1；其余查证、复测、修复、
  写文档、解释、同步、催办由分身直接做完并回结果，不占 P1。
- 非目标：不做正文级过滤器 / 审批队列；不改发送方式；不阻止分身做技术判断（漏洞真伪、
  复测是否通过、是否重复单、影响面、修复建议）；不把普通工作推回给用户。

## 方案

### 1. 三类判断

| 类 | 例子 | 分身动作 |
| --- | --- | --- |
| 分身现在能做 | 查 / 核 / 分析、漏洞复测 / 修复 / 关单、配置核对、跑测试、写文档 / 表格 / 清单、发交付物、解释原理 / 口径、同步进度、催办要材料 | 直接做，做完说结果；不要只回「我看看」然后不干，也不要记 P1 |
| 只能本人做 | 参会 / 约见 / 电话 / 出差 / 面试 / 培训 / 线下签字；合同 / 价格 / 付款；系统权限 / 凭据；公开发布；接受风险 / 批准例外 / 替本人拍板 | 不答应、不定时间、不说「可以 / 几点」；回「收到，具体安排我确认后答复」，记 P1 |
| 别人做 | 让同事修、让平台审批、等外部排期 | 可以同步 / 催办 / 要材料（做完说「已同步 / 已催」），但不替别人承诺完成时间，也不替本人承诺「我明天给你 / 回头处理」 |

判断句：**这件事我现在能不能用工具做完？** 能 → 做；不能且要本人 → 停；不能但能让别人做 →
只做协调动作，不承诺结果时间。

### 2. 固定动作

1. 先做能做的：能查就查、能复测就复测、能修就修、能写就写；本轮做完再回复，不把「我稍后
   看」「我明天给你」留给未来。
2. 需要本人拍板的，不查日历挑时间、不答「可以 / 几点」、不替本人接受风险或批准例外；
   只回不承诺层，并把谁、什么时候、要本人做什么、最晚何时回写进当日日报 P1。
3. 工作本 / 人物档案只记「待本人确认」，不写「已答应」；分身自己做完的事写结果，不写 P1。
4. 只有本人针对**这一件事**明确说「答应 / 参加 / 可以 / 就这个价」，才按本人指令对外确认；
   偏好、惯例、以前答应过同类事都不算授权。

### 3. 落地位置

- `SKILL.md` 的 `## 承诺边界：自己能做的直接做，本人到场 / 拍板的才停`：三类判断 + 两个例子；
  铁律里的敏感清单只留本人事项，不再列「修问题 / 审文档 / 发清单」。
- `dsh-plugin/lib/turns.js` 的 `sendModeNote`：草稿 / 全自动都只硬停本人事项，并明确
  「其余能查、能核、能测、能修、能写的，直接做掉再回结果，不要留成 P1」。
- `dsh-plugin/lib/duty.js` 的 `DEFAULT_POLICY`：新装用户同一口径；已有 `policy.md` 不覆盖。
- 不改 `state.json` / 路由 / 配置键，三份契约不需要同 commit 改。

### 4. 实施步骤

1. 改 `SKILL.md`：收敛承诺边界，铁律与 P1 例子同步。
2. 改 `turns.js` 的 `sendModeNote`；补测试断言「修 / 查 / 写允许」「参会 / 拍板停」。
3. 改 `duty.js` 的 `DEFAULT_POLICY`。
4. 跑 `node --test` 与 `python3 tests/run_tests.py`；用合成会话人工看一遍草稿 / 全自动输出。
5. 归档本 spec，真机验收写进 `PROGRESS.md` 挂账。

## 取舍

| 备选 | 否掉的理由 |
| --- | --- |
| 把所有「承诺」都硬停 | 会把漏洞修复、复测、文档、解释、催办这些主职工作停掉；日报里 90% 以上是这类活 |
| 在插件发送前做正则拦截 | 插件不解析正文、不代发；同一规则会在 Node 与 prompt 里长两遍，误杀正常回复，违反设计铁律 8 |
| 所有涉及时间的回复都静默 | 会把「我查一下日志」这类正常信息也堵死；边界应是「不替本人到场 / 拍板」，不是「不许提时间」 |

## 影响面

- 代码：`dsh-plugin/lib/turns.js`、`dsh-plugin/lib/duty.js`
- 文档：`SKILL.md`、`dsh-plugin/skill/SKILL.md`（构建产物）、`docs/implementation/PROGRESS.md`
- 契约：无
- 用户可见：遇到参会 / 约时间 / 签字 / 付款 / 拍板时只回不承诺层并进 P1；查证、复测、修复、
  文档、解释、催办照常做完再回
- 兼容：纯文案，无迁移；旧会话下一轮重新声明发送方式时生效

## 风险与回滚

- 风险：模型把「本人拍板」误判成技术判断（如替本人接受风险 / 批准延期），或把能做的活推给
  用户。前者靠 P1 清单与真机验收；后者靠 prompt 里「直接做掉」的明示和测试。
- 回滚：撤 `SKILL.md` 与 `turns.js` 文案即可；无状态、无迁移。

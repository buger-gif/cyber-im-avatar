# 0052 私聊进度卡 — 实施计划

> 关联 spec：`docs/specs/archive/0052-私聊进度卡.md`

## 步骤

1. **配置与状态形状**：`lib/state.js` 的 `DEFAULT_CONFIG.dsh` 加 `progress_card: false`；
   `normalizeConfig` 只认显式 true；`normalizeChat` 补 `progress_card` 三态
   （null 跟随 / true 开 / false 关）与 `progress`（`msg_id` / `turn_id` / `state` /
   `created_at` / `updated_at` / `last_error` / `counts` / `ids`，`ids` 最多 5 条）。
   同步 `docs/specs/contracts/03-config.md`、`02-storage.md`。
   验证：`node --test tests/state.test.mjs`。

2. **卡片纯函数与 tracker**：新建 `lib/progress.js`：
   - `parseProgressLine`：只解析 `[进度] n/m 现在：...；接着：...`，多行取最后一条有效；
   - `sanitizePublicLabel`：URL/邮箱/路径/ID/长数字/反引号等结构性过滤；
   - `countAction`：只按 `tool/call.name` 归到查资料/改文件/执行操作/并行处理，不读参数；
   - `buildProgressCard`（Card 2.0、`update_multi`、无 note、第一行“已做”计数，
     有标记时加任务级“现在/接着/第 n/m 步”，再加用时；header/body/footer、hash）；
   - `ProgressTracker`（2 分钟建卡、1.5 秒防抖、从建卡起 10/30/60 秒分档、复用 running 卡、
     结束态、失败/撤回/连续 3 次停止、注入 clock/timer）。
   验证：`node --test tests/progress.test.mjs`（计数分类、标记解析、哨兵、无标记仍有计数、
     2 分钟门限、10/30/60 心跳、hash、生命周期；脱敏 fixture 回放 10 个 >2min p2p，
     2 分钟计数非空、patch 数 27–39，22 个群长 turn 不出）。

3. **IM 发送/更新**：`lib/im.js` 加飞书 `cmd_send_card` / `cmd_send_card_user` /
   `cmd_patch_card`，`Adapter.sendCard` / `patchCard`，`IM.sendCard` / `patchCard`；
   只飞书，其它平台 `unsupported`；发送必须拿到 `message_id`；patch 的 `--data` 正确转义。
   验证：`node --test tests/im.test.mjs`（命令形状、ok:false、无 message_id、非飞书）。

4. **turn 接线**：`lib/turns.js` 在 `followup` 后 `progress.begin`；`collect()` 把
   `turn/start`、`tool/call.name`（只做计数）、`assistant/message` 文本（只找 `[进度]` 行）、
   `turn/end.reason.kind` 交给 tracker；不接 `tool/result`、`step/start`、`todo/write`。
   `finish()` / `cancel()` / `stopAll()` 收口；`warm` / `desk` 不启用。
   验证：`node --test tests/turns.test.mjs`（2 分钟内不发、2 分钟后一张卡、计数增长、
   复用、结束态、重启扫尾）。

5. **轮询过滤**：`lib/poller.js` 用 `chat.progress.ids` 排除卡片：不进 `selfEpoch`、
   不进 `recent` / `classified`，`best` 仍推进水位。
   验证：`node --test tests/poller.test.mjs`（不把对方消息标成 `you-replied`；
   卡片之后的新消息仍进批次；水位不倒退）。

6. **配置接口与面板**：`lib/app.js` 合并 `dsh.progress_card`，新增
   `POST /api/chat/progress`（`inherit` / `on` / `off`，群聊回 `single_chat`）；
   `web/panel.js` 设置页加全局开关、私聊详情加三态“跟随全局 / 开 / 关”与状态；
   `python3 scripts/build_client.py` 重建 `lib/client.js`。
   验证：`node --test tests/app.test.mjs`、`python3 tests/test_docs.py`。

7. **载荷与 skill**：`lib/turns.js` 的 `progressCardFor` 按“单点三态覆盖全局”判断；
   仅在生效时按 spec 0045 首次/变化声明“卡片自动计数；可选写 `[进度]` 补现在/接着”；
   加入 `announcedFor`，压缩后重带；根 `SKILL.md` 与 `dsh-plugin/skill/SKILL.md`
   同步“进度卡看载荷”一节。
   验证：`node --test tests/turns.test.mjs`（首次有、未变不复读、关闭没有、压缩后重带）。

8. **文档与真机**：同步三份契约、`references/feishu.md`（Card 2.0 send/patch 事实）、
   `docs/architecture/03-runtime.md`、`dsh-plugin/README.md`、`README.md`、
   `CHANGELOG.md` 未发布小节、`PROGRESS.md`、当日 log；跑
   `bash scripts/gate.sh --quick`；真机由用户在测试私聊开开关验证（全局/单点、本人 sender、
   2 分钟建卡、计数增长、可选 `[进度]`、轮询不误判、重启收尾）。

# 0055 spec 流程收敛：active 上限 2，plan 按需

> 状态: 已验收
> 编号: 0055
> 版本: 0.25.0
> 关联: `docs/AGENTS.md`、`docs/specs/README.md`、`scripts/verify_docs.py`、`scripts/doc_budgets.json`

## 背景

2026-11-23 清点 `docs/specs/active/`：16 个 spec、16 份 plan，几乎全部已实现并发布
（最老的 0030 停在 0.13.1），只有 0052 / 0053 / 0054 是 0.25.0 的活。流程本身有三个漏洞：

- **没有归档压力**：spec 要等「验收」才搬走，真机项常挂很久没人回填，于是做完的也一直留在
  active；下一个会话要逐个点开才知道哪些还活着。
- **plan 变成默认动作**：`docs/AGENTS.md §4` 把「非平凡」定义成「跨两个以上文件」，
  实际上几乎每个功能都跨文件，于是 16 个 spec 里 16 个都配了 plan，同一件事写两遍。
- **没有机器闸**：active 的数量、状态、目标版本都没人校验，只能靠自觉。

## 目标与非目标

- 目标：active 只留真正在办的事，**至多 2 项**；已实现的（含真机项未做的）搬去 archive，
  真机项集中记进 `docs/implementation/PROGRESS.md` 的挂账。
- 目标：默认只写一份 spec；plan 只在跨多个提交 / 分阶段迁移 / 方案要先探路时写，
  其余把 3–6 步「实施步骤」写进 spec。
- 目标：`scripts/verify_docs.py` 拦住四种回潮：active 超过 2 项、active 里出现
  `已验收` / `已放弃` 状态、目标版本已发布还留在 active、没有 spec 的孤立 plan。
- 非目标：不改 spec 必备小节、编号规则、契约对账；不删历史 log / archive。

## 方案

### 1. 一次清仓

把 0030–0053 里已实现且自动测试通过的 16 个 spec（连同 plan）`git mv` 到
`docs/specs/archive/`，在 `docs/specs/archive/README.md` 追加登记行；0052 / 0053 的版本列
写「0.25.0（未发布）」并注明真机待验。归档是「实现 + 自动测试通过」的动作，不是发版动作。

### 2. 规则改写

- `docs/AGENTS.md §4`：写清 active 上限与 plan 门槛；归档不再等真机，真机项写进挂账。
- `docs/specs/README.md`：目录表、流转图、命名规则同步；补「active 上限与清理」一节，
  说明机器闸与满了怎么清（归档 / 放弃 / 合并 / 降级为挂账）。
- 根 `AGENTS.md` 开发流程第 1 条、`CONTRIBUTING.md §改了哪里要连带改什么` 各同步一句。

### 3. 机器闸

`scripts/verify_docs.py` 的 `check_specs()` 增加：

| 检查 | 判据 | 提示 |
| --- | --- | --- |
| active 上限 | active 里 `NNNN-*.md` 的编号数 > 2（`-plan.md` 不计数） | 列出编号，先归档再开 |
| 状态 | active 的 `> 状态:` 只能是 `待实施` / `实施中` | 已做完就搬 archive |
| 目标版本 | active 的 `> 版本:` ≤ `dsh-plugin/package.json` 的 `version` | 已发布：归档或抬版本 |
| 孤立 plan | active 的 `NNNN-*-plan.md` 找不到同名 spec | 删 plan 或补 spec |

版本比较按 `MAJOR.MINOR.PATCH` 数值元组；缺 `> 版本:` 行算 FAIL。

### 4. 现状回写

`PROGRESS.md` 删掉 0038–0048 的陈旧断点，只留 0054 在办与 0.25.0 的待验项；当日
`docs/implementation/log/2026-11-23.md` 补这次清理的读数。

## 风险与回滚

- **风险：版本闸在发版瞬间误伤。** 约定就是发版提交前先归档；真被拦了就按提示搬走，
  不要把阈值改宽。
- **风险：一次搬 16 个 spec，历史引用路径变化。** log / archive 里的旧路径保持原样（冻结区），
  活文档与审计里的指针同步改成 archive 路径。
- **回滚**：`git revert` 这次文档提交；`verify_docs.py` 的四条检查可单独撤掉，不影响数据。

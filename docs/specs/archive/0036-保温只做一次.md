# 0036 保温只做一次，第二个周期换会话

> 状态: 已验收
> 编号: 0036
> 版本: 0.15.0
> 关联: `docs/specs/contracts/02-storage.md`、`docs/specs/contracts/03-config.md`、`docs/decisions/implemented/0010-会话寿命跟随保温节奏.md`

## 背景

0.12.0 起会话寿命由两个键控制：`dsh.warm_min` 决定多久跑一次保温，`dsh.idle_reset_min`
决定闲置多久后的下一条消息换新会话。默认值 55 / 180 分钟，意味着一通没人说话的会话会连续
跑 3 次保温（约 55 / 110 / 165 分钟），直到 180 分钟后才换。

用户要求：**保温只做一次**。第一个周期（约 55 分钟）照常保温；第二个周期（约 110 分钟）
仍没有真实消息时不再保温，此后新消息直接开新会话。中间如果来过真实消息，从那一刻重新计时，
下一段闲置还能再保温一次。

## 目标与非目标

- 目标：每段连续闲置最多一次保温；第二个 `warm_min` 到期后停止保温，下一条真实消息在新
  DSH 会话里处理。真实消息会把「一次保温」的额度重新打开。
- 非目标：不改保温轮的内容（续缓存 + 整理载荷列出的记忆文件）；不在定时器里主动换会话
  （仍然懒到「下一条消息」才换）；不改独立 skill 形态的 55 分钟重挂与 180 分钟退出——
  skill 没有会话管理权，这次只动 DSH 插件壳；不新增状态字段。
- 非目标：不做「每个 DSH 会话一辈子只保温一次」。用户明确选择按「一段闲置」重新给额度。

## 方案

### 1. 配置：只有保温间隔

`dsh.warm_min` 保留，默认 `55`，范围 `0–1440`；`0` = 关闭保温。因为换会话的时钟也由它
推导，**`0` 同时关闭自动换会话**。

`dsh.idle_reset_min` 退役：从 `DEFAULT_CONFIG`、`normalizeConfig()` 与面板里删掉；老
`state.json` / `panel.json` 里残留的键在加载时丢弃，不报错、不迁移。契约 03 把它移进退役键。

### 2. 保温：每段闲置最多一次

`Poller.maybeWarm()` 的候选条件在现有「值守中、未屏蔽、有绑定会话、首轮载荷已消费、
无待回、无在飞、平台身份可用」之上改成：

- `idle = now - max(last_turn.at, session_bound_at)`；
- `idle < warm_min*60`：还没到第一个周期，不保温；
- `idle >= warm_min*120`：已经过了第二个周期，这通会话下一次有消息就会换，不再花钱保温；
- `last_warm_at > last_real`：这段闲置已经保温过一次，不再保第二次；
- 失败也算一次（`last_warm_at` 照写），不按 tick 重试。

一次 tick 最多启动一个保温轮。真实消息打断在飞保温时不记为「已保温」，下一段闲置重新获得
一次额度。

### 3. 到期：懒到下一次唤醒才换

`Turns._wake()` 在取消旧轮之后、`resolveSession()` 之前判断：

- 有 `dsh_session`、`warm_min > 0`、没有在飞 turn；
- `now - max(last_turn.at, session_bound_at) >= warm_min*120`；
- 命中就 `state.setSession(chat, "")`，`last_reset.reason = "idle"`。

之后仍走现有新会话创建：`firstTurn` 为真，首轮载荷重新带入口、chat_id、运行形态与记忆文件
路径，并多一行「上一段会话闲置超过约 N 分钟（只保温一次），已自动重开」。旧会话留在 DSH
侧边栏，不删除、不归档。

到期判断只看真实闲置时长，不看是否真的跑过保温：插件休眠/重启错过保温窗口时，长时间无
消息后的第一条消息仍然换新会话；`warm_min=0` 时不换。

### 4. 状态与面板

不新增字段。语义更新：

- `last_warm_at`：当前这段闲置里那一次保温的时刻；换会话时归零；
- `last_reset.reason = "idle"`：改为「保温一次后第二个周期仍无新消息」；
- 面板设置页「会话生命周期」只留一个「保温间隔(分钟)」输入，文案写明「只保温一次；再过
  一个周期没有新消息，下一条消息换新会话；0 = 关闭保温与自动换会话」；
- 详情页「上次保温」保持；重置原因文案改成「保温后一个周期仍无新消息，已自动重开」。

## 取舍

| 备选 | 否掉的理由 |
| --- | --- |
| 保留 `idle_reset_min`，取两者更早 | 用户明确要求「完全以保温为准」；两个时钟并存会让「实际多少分钟换」依赖两个键，难解释 |
| 每个 DSH 会话一辈子只保温一次 | 中间来过真实消息后缓存仍会冷；用户确认按「一段闲置」重新给一次 |
| 定时器到点就主动换会话 | 没人说话时换会话没有收益；懒到下一次消息读数最准，也不影响旧会话 |
| 第二个周期继续保温、只是不在 180 分钟后再保 | 默认配置下等于 3 次保温，正是用户要省掉的开销 |
| `idle_reset_min` 留成 no-op 但保留面板项 | 面板上留着不生效的数字比删掉更容易误导；老配置加载时静默丢弃即可 |

拍板记录见 `docs/decisions/implemented/0010-会话寿命跟随保温节奏.md`。

## 验收

- [x] 闲置 60 分钟、没保温过 → `maybeWarm()` 启动一次；同段闲置再 tick 不启动
- [x] 保温后闲置到 120 分钟 → `maybeWarm()` 返回 false（不再保温）；下一条消息 `dsh_session`
      变化、`session_turns=0`、`last_reset.reason="idle"`，首轮载荷含「已自动重开」
- [x] 保温后、第二个周期前（如 80 分钟）来真实消息 → 不换会话；从那以后闲置 60 分钟 →
      再保温一次
- [x] 插件错过保温窗口（从未保温）但已闲置 120 分钟 → 下一条消息仍换新会话
- [x] `warm_min=0` → 不保温；闲置再久也不换会话
- [x] 保温启动被真实消息取消 → 不写 `last_warm_at`，下一段闲置仍可保温
- [x] `/api/config` 不再返回 `dsh.idle_reset_min`；老配置带该键加载后也被丢弃
- [x] 面板设置页只剩「保温间隔」一个输入；保存后读回夹取后的值
- [x] `node --test`、`python3 tests/run_tests.py`、`bash scripts/gate.sh` 全绿
- [x] 独立预览页走查设置卡片与详情「上次保温 / 自动重开」文案

## 风险与回滚

- 风险：`warm_min` 设得很大时，换会话也会被推得很晚；面板文案已写明两者同源。
- 风险：`warm_min=0` 的用户从此不会自动换会话；这是「完全以保温为准」的直接代价，写进
  CHANGELOG 与设置页。
- 回滚：恢复 `dsh.idle_reset_min` 的默认值/夹取与面板输入，撤掉 `_wake` 的
  `warm_min*2` 分支和 `maybeWarm` 的两个上限；已产生的 `last_reset` / `last_warm_*` 不需要清。

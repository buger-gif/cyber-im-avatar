## 背景

2026-11-13 面板飞书卡片出现一条红色 `last_error`，内容是一段多行缩进被 HTML 压平后的
lark-cli 原始错误 JSON：

```
{ "ok": false, "identity": "user", "error": { "type": "network", "subtype": "transport",
  "message": "API call failed: Get \"https://open.feishu.cn/open-apis/im/v1/messages?...\"
```

同一条 `im +chat-messages-list` 直连 1.3 秒成功，`bootstrap.py --selftest` 连跑 3 次全过，
`lark-cli doctor` 8 项全 pass。结论是**一次瞬时传输失败**，但自检把它当成红色故障，
还丢了可诊断信息：

- `scripts/doctor.py` 的 `check_cli_doctor()` 把 CLI 体检里所有非
  `pass/ok/skip` 状态算 `fail`，于是 `cli_update=warn(1.0.98 → 1.0.100 available)`
  判飞书「不可用」、退出码 2，并打出「不要挂监听」。
- `check_path()` 只取 stderr 第一行 `err[0][:160]`；CLI 错误是多行 JSON，第一行是 `{`，
  实测输出为 `[fail] 通路: ERROR: 初始化水位失败: `，真实原因整段消失。
- `dsh-plugin/lib/im.js` 的 `fetchMessages()`、面板体检 `poller.doctor()`、
  `bootstrap.py --selftest`、`doctor.py` 通路检查，全部一次失败即下结论；
  60 秒快车道里一次网络抖动就会把会话标红。
- 面板把 CLI 原文（含完整 `oc_` ID 与 URL）直接显示，未归类、未脱敏。
- 实施中复现出第五个：`scripts/listen_core.py` 的短窗口自检先查 deadline 再查
  `fail_streak`，3 秒内全部拉取失败也会以退出码 3（「超时未命中」）收场，有水位文件时
  自检发现不了通路坏；`redact_sensitive()` 的 URL 正则还会连反斜杠一起吞掉，把 CLI 的
  转义 JSON 改坏，导致后续解析不到 `error.message`。

平台本没有坏，是自检没分辨「瞬时网络失败」与「真的不可用」，个别路径还会把失败报成成功。

## 目标与非目标

- 目标：一次瞬时传输失败不再留下红色状态：读请求与自检对 `network` 类失败各重试一次
  （0.5 秒退避）；重试成功即恢复绿灯。
- 目标：失败信息可读：CLI 的 `{error:{type,subtype,message,code}}` 归一为一行中文结论
  （网络 / 授权 / 权限 / 字段漂移 / 接口报错），面板与 `doctor.py` 都显示这一行；
  URL 收敛为 `<url>`，`oc_` / `ou_` / `wo…` ID 打码。
- 目标：`cli doctor` 的 `warn` 不再阻塞；只有 `fail`（以及 CLI 自己报 `ok:false`）算不可用。
  新版本提醒归 `warn`，仍展示修复命令。
- 目标：全平台体检只检查启用的平台（`state.json` 的 `config.platforms` 优先，其次
  `env.json` 里 `logged_in` 为真的平台，都没有则全查）；未启用的平台报 `skip`，
  不计入 `healthy` / `broken`，不拉低退出码。显式 `doctor.py <平台>` 不受此限。
- 非目标：不改拉取节奏、轮询间隔、快慢车道判定；不改任何路由 / 配置键 / `state.json` 形状。
- 非目标：不重试写操作（发送、表情、上传），避免重复消息。
- 非目标：不把网络失败静默成 `ok`；两次都失败仍然判 `fail`，只是原因要写清楚。

## 方案

### 1. 错误归一（插件与 Python 各一份，形状一致）

`describeCliError(text)` → `{ kind, summary }`：

| kind | 触发 | summary 形状 |
| --- | --- | --- |
| `network` | `error.type=network`，或 message 含 timeout / dial tcp / connection reset | `网络传输失败：<短原因>` |
| `auth` | `error.type=auth`，或 code 99991663 / 99991664，或 token invalid / expired | `授权已失效：<短原因>` |
| `permission` | message 含 permission / scope / 权限 | `缺少权限：<短原因>` |
| `schema` | 调用方传入 `SCHEMA_MISMATCH` 原文 | `字段漂移：<键名摘要>` |
| `api` | 其余带 `code` 的 `{ok:false}` | `接口报错 <code>：<短原因>` |
| `other` | 解析不出结构 | `拉取失败：<首段文本>` |

`<短原因>` 去掉 URL、控制字符，按 Unicode 截 120 字；ID 打码（插件保留头尾如
`oc_c56748…d313`，`doctor.py` 的 `redact_sensitive()` 统一写成 `<ID>`）。

### 2. 读请求重试（插件）

`Adapter.fetchMessages()` / 走它的 `fetchThread()`：

- 第一次 `rc != 0` 且 `kind=network` 且 `rc != 124`（124 是本进程超时杀进程，不重试，
  避免把等待翻倍）→ 等 500ms 再跑一次。
- 返回值新增 `error_detail`（脱敏原文，≤600 字符）；`error` 只放 `summary`。
- 成功时行为不变；`messages` / `ok` 字段形状不变。

### 3. 自检重试（Python）

- `bootstrap.listen_probe()`：跑一轮 3 秒监听，返回 `(rc, stdout, stderr)`，
  `--selftest` 与 `doctor.py` 共用。
- `selftest()` / `doctor.check_path()`：失败且 `kind=network` 时重试一次（0.5 秒）；
  仍失败时写「网络传输失败（已重试 1 次）：…」并给网络/代理排查指引；
  `auth` / `permission` / `schema` 不重试，直接给对应修复命令。
- `listen_core.py` 的短窗口退出：到点仍无一次拉取成功且有失败记录 → 打印
  `ERROR: 自检窗口内拉取全部失败: …` 并退出 2，不再被「超时未命中」掩盖。
- `data_guard.redact_sensitive()` 的 URL 字符类排除 `\`，不吞掉转义 JSON 的 `\"`。

### 4. doctor 宽严与启用平台

- `check_cli_doctor()`：`status=warn` → `warn`；`fail` 或未知状态 → `fail`。
- `enabled_platforms(env)` 与 `--platform` 的关系：显式指定 > `state.json` 配置 >
  `env.json` 登记 > 全部。未启用平台只报一条 `skip`「未启用」，不跑 CLI / 授权检查。
- `Report.worst()` 增加 `skip` 终态（全部检查项都是 skip 时）。
- `--json` 的 `summary` 增加 `skipped` 列表；`healthy` / `broken` 只看实际检查的平台。

### 5. 面板显示

`poller.pollChat()` 把 `chat.last_error` / `errors[]` 写成 `summary`；原文
`error_detail` 只进宿主日志（`logger.warn`），不上面板。面板渲染不变。

## 取舍

| 备选 | 否掉的理由 |
| --- | --- |
| 瞬时网络失败直接当 `warn` / 静默 | 真断网时也会变绿，属于「静默失效」；重试后仍失败必须红。 |
| 只在 prompt 里教 agent 重试 | 插件是确定性搬运层，抖动应在取数处收口，不能把网络细节推给模型。 |
| 重试发送请求 | 可能重复发消息；写操作一律不重试。 |
| 未装 CLI 的平台一律 `warn` | 用户主动启用却没装 CLI 是真故障，必须 fail；只有「未启用」才 skip。 |

## 影响面

- 代码：`dsh-plugin/lib/im.js`、`dsh-plugin/lib/poller.js`、`scripts/bootstrap.py`、
  `scripts/doctor.py`、`scripts/listen_core.py`、`scripts/data_guard.py`、
  `tests/run_tests.py`、`dsh-plugin/tests/{im,poller}.test.mjs`。
- 契约：无形状变化。`/api/doctor` 的 `detail` 文案更短更可读；`/api/status` 的
  `last_error` 仍是字符串，只是内容变成单行结论。
- 用户可见：面板红色错误变成一行中文；体检的 `warn` 不再显示成「不可用」；
  未启用的平台不再报 fail。
- 兼容：老 `env.json` / `state.json` 不用迁移；没有新配置键。

## 风险与回滚

- 风险：重试把单轮耗时上限抬高一行（网络类 + 最多一次 CLI 调用）。读请求超时本身已有
  45 秒 `execFile` 上限；重试只发生在 CLI 自己快速返回错误时，正常路径无额外开销。
- 风险：`describeCliError` 误判 `api` 为 `network` 时不重试即可，判定只认 `type` 与
  明确的超时关键字。
- 回滚：撤本条 commit 即恢复旧行为；没有数据迁移，`state.json` 不用清。

# 0051 发言权：默认口径先行，事实进载荷，按群覆盖

> 状态: 待实施
> 编号: 0051
> 版本: 0.24.1
> 关联: `docs/decisions/implemented/0017-发言权默认口径.md`（修订 0016 的降级规则）、
> `docs/specs/contracts/01-api.md`

## 背景

2026-11-18 飞书值守事故：某值班机器人在群里 @ 的是处理人，值守账号是同一个群的
跟进人，`send_mode=auto`，agent 在**开场轮**以跟进人身份代处理人回了进展。

本次取证纠正了当时的判断：插件侧的 @ 识别是对的——那条消息被存成 `kind=fyi`、
`skip=no-mention`，`probeForDuty` 里的 `anyMention` 为假，`duty.trigger` 因此仍是 `added`。
错在开场轮：载荷写的是「有该回的就按 skill 回」（开放式邀请），又没给本人身份，
当时工作本还是空模板，agent 无从知道「我在这群是谁、什么该我管」。

收紧成「只 @ 我就回」也不行：新建群经常没有任何 @，但任务确实落在本人身上；群里的
「没人被点名但答得了的问题」和「信息同步」也会被一并判死。注意力（省 token 的启发式）
与发言权（正确性）绑在 mention 一个信号上，收紧就漏、放松就错。

0.24.0 先按「契约未定义 → 强制草稿」发过一版，二十分钟内就被真实使用否掉：存量群集体
从全自动掉到草稿，恢复还要用户手写一句。默认值缺失不该由用户承担——见
`docs/decisions/implemented/0017-发言权默认口径.md`。

现状读数（本机）：314 个会话、32 个 `send_mode=auto`；`config.send_mode_default=auto`。

## 目标与非目标

- 目标：**每个群一上来就有一套能用的默认发言权口径**（点我名的回；没人点名而答得了的答；
  信息同步可以发；别人被点名的不代答）；插件把判断需要的事实（本人身份、谁被 @、
  本批是否点你名）给足，不再给结论；用户想按群改就改，改完只影响这个群。
- 非目标：不做发送拦截（做不到，见 0016）；不新增关注程度档；不做决策文件；
  不把正文或判断落进插件状态；不因为「发言权」改变发送方式。

## 方案

### 1. 默认口径是一个常量，不落盘

`dsh-plugin/lib/profiles.js` 的 `RIGHTS_DEFAULT`：

```
- 点我名：回（这是给我的）
- 点了别人：只当知会，不代答；除非那条明确也在问我
- 没点任何人：先判断——问题悬在群里、任务派到我头上、需要我表态或给结论 → 回；
  纯告警、寒暄、别人之间的对话 → 沉默
- 信息同步：已确认的进度、结论、事实，可以主动发到群里
- 判不准：沉默，等下一次点名
```

判断顺序是**先看这条点名了谁，再看内容**——不是「没 @ 我一律不回」。
本批的点名分布也由插件算好交给 agent：`本批 1 条点你名；2 条点了别人（不是给你的）；3 条谁都没点。`
（`mentions` 只有探针消息带，拿不到时降级成「其余 N 条没点你名」，不猜。）

- 工作本那段为空 → 用默认（`custom=false`）；写了 → 覆盖默认（`custom=true`）。
- **不影响发送方式**：默认值一上来就有，不需要用户配、也不会把群降成草稿。
- 只对群生效；私聊 `applicable=false`，返回默认文本但不参与判断。
- 改默认口径要发版（一处常量）；按群改在面板，不用发版。

### 2. 覆盖点是工作本里的固定小节

`profiles.profileTemplate()` 建群工作本时带上标题，body 为空（空 = 用默认）：

```markdown
## 我在这个群的发言权

```

- 结构性判定：`rightsSection(text)` 取标题行到下一个 `## ` 行；body 非空 = `custom`。
- 标题被删也算「没写过」→ 回到默认（不会因为删了标题就变成「无口径」）。
- 面板只有这一段可编辑；工作本其余字节逐字节不动。

### 3. 载荷从「结论」改成「事实 + 默认口径」

| 现在 | 改成 |
| --- | --- |
| `值守判断：watch（只盯 @我）` | `值守分诊：watch（插件自动发现后转入，不是被新消息叫醒）。`（只留事实） |
| `只盯 @我：非点名的群消息不需要处理。` | 删掉：mention 模式下非点名消息根本不会进批次 |
| `全量模式：非点名的群消息只看不回…` | `没点你名的行默认沉默；判定确实是交给你的任务才发言，并说清为什么由你出面。` |
| `有该回的就按 skill 回…` | `默认动作是沉默：只有落进上面几类才发言…` |
| `判断口径：个人 @ + 具体请求 → watch` | `点你名（mention.id == 本人 open_id）+ 具体请求 → watch` |

新增事实行（群，首轮 / 开场与变化时声明）：

- `本人：<name> · <platform> · open_id <id>`（取不到就省略，不猜）
- 每条消息行标出被 @ 的人：`- [10:30] 值班机器人（@周明）: …`；`（@你）` 保留
- `本批 N 条点你名。`（每轮都给，是本批数据不是口径）
- 发言权一句话：默认口径时给判据摘要 + 改法；本群单独改过时给工作本指针

开场轮另外允许 agent **在看出更细分工时**把结论写进工作本那一段（可选，不是前置条件）；
没看出来就不动它。

### 4. 面板：默认口径 / 本群已改

**只暴露这一段，不做整本编辑**：工作本里还有 agent 的知识（群内工作要求 / 成员与角色 /
结论），整本编辑会让人有机会覆盖它们——**人是授权方，agent 是知识方**。

- `GET /api/rights`（`platform`、`chat_id`）→
  `{ok, applicable, exists, custom, text, default_text, title, path, mtime}`；
  `text` 是**生效文本**（未改过就是默认文本）。
- `POST /api/rights`（`platform`、`chat_id`、`text`、`base_mtime`）：只替换该小节 body，
  **其余字节一个不改**；`base_mtime` 与磁盘不一致回 `stale`（沿用 0050 的模型）；
  `text` 为空 = 清空该小节（回到默认）；标题不存在时在文件末尾补回；上限 8KB；原子写（`600`）。
- `/api/targets` 的群行补 `rights`（该段原文，空串表示用默认）/ `rights_custom`，
  面板据此显示 `发言权 · 默认口径 / 本群已改`。
- 编辑器沿用 0050：`base_mtime` 冲突 → 保留草稿、取最新 mtime、再点一次才覆盖；
  另有「恢复默认」（留空保存）。

### 6. 没点你名的消息：给条数，按需在线拉

唤醒范围不动（群默认「只 @ 我」），但下一轮唤醒的载荷会多一行：

```
另有 2 条没点你名的群消息没转给正文；判断需要时按 skill 在线拉最近的群消息看。
```

- 统计口径：`recent[]` 里 `kind=fyi` + `skip=no-mention`、且在上次交付（`last_turn.at` /
  `session_bound_at`）之后的条数；`baseline` 与 `you-replied` 不算。
- 条数是「至少这么多」（`recent[]` 上限 10 条），载荷按条数说，不装作全集。
- 正文不落插件状态：要看得让 agent 自己用平台 CLI 拉，拉一次不多花钱。
- 取舍见 `docs/decisions/implemented/0018-没点名的消息给条数.md`。

### 5. 所有权

- 默认口径：代码里的常量，发版才变。
- 按群覆盖：人写，人是唯一作者；agent 只在开场轮看出特殊分工时补一版，之后只读。
- 用户可以随时在面板改；这就是控制点。

## 取舍

| 备选 | 否掉的理由 |
| --- | --- |
| 空段 → 强制草稿（0.24.0 的做法） | 存量群集体降级；恢复要用户手写；把默认值缺失的成本转给用户 |
| 默认文本写进每个工作本 | 几十份副本各自漂移，改默认要迁移 |
| 契约放独立文件 | 工作本已有「群内工作要求 / 成员与角色」，同一份规范长两处 |
| 面板整本编辑工作本 | 会覆盖 agent 的知识段，且没有单一「授权边界」的可见形态 |
| `custom` 塞进 `state.json` | 契约是文件内容，状态再存一份就是双源，agent 改文件后状态会漂 |

## 风险与回滚

- 风险：默认口径允许「答没人被点名的问题」和「信息同步」，判错时会更快说错话。
  兜底是发言必须说清「为什么由你出面」、面板按群改、skill 铁律优先（钱/合同/承诺/外部群停下）。
- 风险：agent 整文件写工作本时覆盖掉人刚改的那一段。缓解：SKILL 明确「写前重读、只增量改」，
  且只有开场轮在看出特殊分工时才写。
- 回滚：把 `RIGHTS_DEFAULT` 换回窄口径即可（一处常量，不改结构）；或在面板把某群改窄。

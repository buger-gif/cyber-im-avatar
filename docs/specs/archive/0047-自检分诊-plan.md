## 步骤（一步一验证）

1. **错误归一（Python）**
   `scripts/bootstrap.py` 增加 `classify_cli_error(text)` / `is_transient(kind)` /
   短原因清洗（去 URL、ID 打码、截 120 字）。
   验证：`python3 -c 'import scripts.bootstrap …'` 用四段样本（network / auth / api / 乱文本）
   打印 `kind + summary`，人工核对；ID 不出现在 summary。

2. **自检探针与重试（Python）**
   `bootstrap.listen_probe(platform, target, by_user)` 抽出 3 秒监听调用；
   `selftest()` 对 `network` 失败重试一次（0.5 秒），失败时打印归一原因 + 手册指针。
   `doctor.check_path()` 改用同一探针与重试，失败行写「网络传输失败（已重试 1 次）：…」。
   验证：stub CLI 返回多行 network JSON，`doctor.py feishu --chat-id oc_x` 输出含
   「网络传输失败（已重试 1 次）」，stub 计数为 2。

3. **doctor 宽严与启用平台（Python）**
   `check_cli_doctor()` 把 `warn` 归 `warn`；`enabled_platforms(env)` 按
   `state.json → env.json → 全部` 取启用集合；未启用只报一条 `skip`；
   `Report.worst()` 支持全 skip；`--json` 的 `summary.skipped` 同步。
   验证：三种环境各跑一次 `doctor.py --json`（有 state.json / 只有 env.json / 都没有），
   检查 `healthy` / `broken` / `skipped` 与退出码；`cli_update=warn` 时退出 0。

4. **插件侧归一与读请求重试（Node）**
   `dsh-plugin/lib/im.js` 导出 `describeCliError()`；`redact()` 对 `oc_` / `ou_` / `cidr` /
   `wo…` 打码；`fetchMessages()` 对 `network` + `rc!=124` 重试一次（500ms），
   返回 `error` = summary、`error_detail` = 脱敏原文。
   验证：`node --test dsh-plugin/tests/im.test.mjs` 新增用例（重试成功 / api 不重试 /
   summary 单行且脱敏）。

5. **面板错误收口（Node）**
   `poller.pollChat()` 的 `last_error` / `errors[]` 用 summary；`error_detail` 走
   `this.logger.warn`。`doctor()` 的「拉取通路」细节不再是一次性原文。
   验证：`node --test dsh-plugin/tests/poller.test.mjs`；本机跑一次
   `im.adapter("feishu").fetchMessages()` 看成功路径耗时与字段不变。

6. **测试与文档**
   `tests/run_tests.py` 增加两组 doctor 用例；同步 `references/troubleshooting.md`
   分诊表 + §D、`docs/architecture/03-runtime.md` 体检段、`CHANGELOG.md` 未发布、
   `PROGRESS.md` 断点、当日 `docs/implementation/log/2026-11-13.md`。
   验证：`python3 tests/run_tests.py`、`bash scripts/gate.sh --quick`、全量 `bash scripts/gate.sh`。

# 0037 命中回执表情

> 状态: 已验收
> 编号: 0037
> 版本: 0.16.0
> 关联: `docs/specs/contracts/03-config.md`

## 背景

现在从「插件拉到 @ 我的消息」到「agent 真正写出回复」之间有一段空白：面板上看得到 turn
在跑，但会话里的对方看不到任何回执。想告诉对方「收到了」，只能让 agent 先发一条消息，或者
干等——前者是多一条正文，后者在慢任务上像是没人值守。

飞书支持给消息点表情回复（`im reactions create`），不产生新消息，也不进聊天流。插件在拿到
绑定的 DSH 会话、把本轮载荷 `followup` 进去之后，正好是「会话已启动、任务消息已送出」这个
时点，适合点一个 `Get` 作为回执。

## 目标与非目标

- 目标：命中唤醒的 @ 消息，在任务载荷送进 DSH 会话后，以本人身份点一个 `Get` 表情；
  不新增正文消息，失败不影响这一轮 turn。
- 非目标：
  - 不给全量群里没 @ 我的旁观消息点表情（那是在替本人表态，不是回执）；
  - 不给私聊「全部消息」模式的普通私聊消息点（本 spec 只认 @；以后要扩再单开）；
  - 不做企微 / 钉钉适配（CLI 没有表情回复通路，静默跳过）；
  - 不做失败重试 / 离线队列 / 反应记录落盘。

## 方案

### 触发点与目标消息

- 触发点：`Turns.runTurn()` 里 `agent.followup(message)` 正常返回之后（会话由
  `resolveSession()` 解析/创建成功，载荷已交给 agent）。此时不等待 `user/message` 事件，
  避免消息被下一条新消息顶掉时回执永远不出现。
- 目标消息（本批 `messages` 里筛，`open` / 保温轮不筛）：
  - 群：`kind === "mention"`；
  - 私聊：`chat.wake_mode === "mention"` 且 `kind === "dm"`（只认 @ 模式下的 @ 消息）。
  - `cmd`（本人 @ 自己）、`out`、`fyi` 一律不点。
- 同一批多条 @ 就逐条点，上限跟随本批条数（≤10）；进程内按 `platform:msg_id` 去重，
  同一消息不重复点。

### 平台与调用

- 飞书：`lark-cli im reactions create --params '{"message_id":"om_x"}' --data
  '{"reaction_type":{"emoji_type":"Get"}}' --as user`，超时 15 秒。
- `Adapter` 增加 `cmd_reaction` 与 `react()`；`IM.react(platform, msgId, emoji)` 统一收口：
  平台没有该命令时返回 `{ok:false, unsupported:true}`，不 spawn、不报错。
- 回执调用是 fire-and-forget：不阻塞 turn，不写 `chats.last_error`，不改 pending / 水位。
  失败只在宿主 stdout 打一条 warn（每个平台每进程最多一条），并提示需要
  `im:message.reactions:write_only` 授权。

### 配置

- 新键 `dsh.ack_reaction`，默认 `true`；面板「设置 → 值守会话」加一行开关。
- `normalizeConfig()` 只把显式 `false` / `0` / `"false"` 当关闭，缺省与老 state 都按开处理。
- 关掉后不调用 CLI，其余行为不变。

## 取舍

| 备选 | 否掉的理由 |
| --- | --- |
| 等 `user/message` 事件再点 | 消息排队时回执会延迟；被新消息顶掉时可能永远不点，回执失去「已收到」的意义 |
| 先发一条「收到」文本 | 多一条正文，噪音大，也替本人多说了话 |
| 只给最新一条 @ 消息点 | 一批多条 @ 时漏回执；逐条点成本相同 |
| 全量群 / 私聊全部消息都点 | 替本人对旁观消息表态，超出「回执」语义 |
| 首版就做企微 / 钉钉 | CLI 没有表情回复命令，做了也是假支持 |

## 影响面

- 代码：`dsh-plugin/lib/im.js`（模板 + `react()`）、`dsh-plugin/lib/turns.js`（筛选与触发）、
  `dsh-plugin/lib/state.js`（默认值 / 归一化）、`dsh-plugin/web/panel.js` 与构建产物
  `dsh-plugin/lib/client.js`（开关）。
- 契约：`docs/specs/contracts/03-config.md` 加 `dsh.ack_reaction`。
- 用户可见：升级后默认开启，命中 @ 消息会多一个本人点的 `Get` 表情；设置页可关。
- 兼容：老 `state.json` 没有这个键，加载后按 `true`；不改 state 版本，不迁移数据。

## 验收

- [x] `GET /api/config` 返回 `dsh.ack_reaction=true`；`POST /api/config {"dsh":{"ack_reaction":false}}`
      后读回为 `false`，重启后仍为 `false`。
- [x] 群里 @ 我的一条消息命中后，`agent.followup` 成功 → CLI 收到一次
      `reactions create`（`Get`）；`out` / `fyi` / `cmd` 不触发。
- [x] 私聊「只认 @」模式下的 @ 消息触发；「全部消息」模式的普通私聊消息不触发。
- [x] 企微 / 钉钉命中不调用反应命令、不报错；`ack_reaction=false` 时飞书也不调用。
- [x] `followup` 抛错、或 `reactions create` 失败时，turn 结果与 `last_turn` / `last_error`
      均不受影响。
- [x] 真机：飞书群 @ 本人 → 消息上出现本人点的 `Get`，会话里没有多出正文消息（用户 2026-11-06 确认验收）。

## 风险与回滚

- 风险：授权缺 `im:message.reactions:write_only` 时回执静默失败，用户以为没生效。
  对策：设置页文案写明授权要求，失败在宿主日志留一行；文档同步。
- 风险：默认开启等于升级后以本人身份产生外部动作。对策：开关可关，文案明确「只回 @ 我的」。
- 回滚：把 `dsh.ack_reaction` 设为 `false` 即可停用；代码回滚删模板与触发点，无数据要清。

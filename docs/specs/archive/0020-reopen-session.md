# 0020 重开会话入口

> 状态: 已验收
> 编号: 0020
> 版本: 0.9.0
> 关联: `docs/specs/contracts/01-api.md`（复用 `POST /api/chat/session/reset`，无新增）

## 背景

`POST /api/chat/session/reset` 已经能用，面板上也有入口，但叫「新建会话」，而且藏在
「工作区」那一行的最右边。实际用起来找不到：它被当成工作区的附属操作，而它管的是 DSH 会话的
生命周期。用户问「插件哪点一下重开会话」就是这个原因。

## 目标与非目标

- 目标：话语对齐——按钮叫「重开会话」，放在「DSH 会话」那一行，和它管的对象在一起；两处入口
  （会话详情、分身页）同名同义。
- 非目标：
  - 不改接口：继续用 `POST /api/chat/session/reset`，参数与返回不变。
  - 不改语义：仍是「解绑 + 打断在飞 turn + 下一轮命中开新会话」，不是立刻新建。
  - 不动 `state.json` 字段。

## 方案

### 文案

| 位置 | 现在 | 改为 |
| --- | --- | --- |
| 按钮 | 新建会话 | **重开会话** |
| title | 解绑当前 DSH 会话，下一轮命中开新会话（旧会话保留在侧边栏） | 打断这一轮、解绑当前 DSH 会话，下一轮命中开新会话（旧会话留在侧边栏，不再续聊） |
| 确认框 | 新建会话？当前绑定的 DSH 会话会保留在侧边栏，但不再续聊。 | 重开会话？会打断正在跑的这一轮，并解绑当前 DSH 会话（旧会话留在侧边栏，不再续聊）。 |
| 成功提示 | 已解绑；下次命中在「X」开新会话 | 已重开：下一轮命中在「X」开新会话（旧会话留在侧边栏） |

### 位置

- **会话详情**：从「工作区」行右侧移除，放进 `if (watched)` 的「DSH 会话」行右侧。
  那一行本来就显示会话 chip、轮数、绑定时间，生命周期操作放这里才说得通。
- **分身页**：位置不变（实例行右侧），只改文案。
- 未值守的会话不再出现这个按钮——原来那句「加入值守时生效」一起去掉，行内只留工作区提示。

### 一致性

两处入口共用一个 `newSessionBtn()`（已有），改文案只改函数内部；分身页与详情页自动一致。

## 取舍

| 备选 | 否掉的理由 |
| --- | --- |
| 放进详情页顶部按钮条 | 那里已经有「去会话 / 现在处理 / 屏蔽」，再加一个会挤，而且它不是高频动作 |
| 立刻新建会话 | 与现有语义不符：新会话要有工作区、要有第一条消息才有意义，空开会浪费一次上下文 |
| 改名「重置会话」 | 「重置」容易被理解成清空消息或恢复默认配置，语义更糊 |

## 影响面

- 代码：`web/panel.js`（`newSessionBtn()` 文案与 `detailView()` 的位置）；`python3 scripts/build_client.py`。
- 契约：无。`POST /api/chat/session/reset` 不变，`01-api.md` 不动。
- 用户可见：按钮改名与换行；无数据迁移。
- 兼容：无。

## 风险与回滚

- 风险：把按钮从工作区行移走后，用户以为少了功能。缓解：移到同一屏的会话行，且改名更准。
- 回滚：撤销本 spec 对应 commit；纯前端改动，重跑 `build_client.py` 即可，无数据影响。

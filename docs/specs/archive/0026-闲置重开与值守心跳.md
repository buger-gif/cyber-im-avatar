# 0026 闲置重开与值守心跳

> 状态: 已验收
> 编号: 0026
> 版本: 0.12.0
> 关联: `docs/specs/contracts/02-storage.md`、`docs/specs/contracts/03-config.md`

## 背景

插件形态没有「监听进程退出」这个时点：轮询器只在命中时调用 `agent.followup`，空闲时不产生
任何模型请求。由此留下两个缺口：

1. **长会话没有上限**：`dsh_session` 只在手动「重开会话」、换工作区、会话丢失时清空。
   真实 `state.json` 里有 6 个已绑定会话，其中 5 个已闲置超过 3 小时；面板只在超过 50 轮时
   提示「较长，可新建」，仍然靠手动。上下文随对话一直累积，闲置越久，下一条消息的冷缓存
   全价读取越贵。
2. **没有缓存保温**：skill 形态靠 `--cache-refresh-min 55` 到点退出、让 agent 重挂来续缓存
   （`dsh-plugin/skill/scripts/listen_core.py`）；插件形态在 `README.md` 里明确写了
   「目前不做 55 分钟心跳」。模型服务商的上下文缓存通常 1 小时过期，间隔超过 1 小时后
   第一条消息按冷缓存计费。

用户要求：两项都补；保温轮顺便让 agent 归并一次画像（同一份会话、同一份画像，不额外起会话）。

## 目标与非目标

- 目标：插件形态闲置超过 3 小时的会话，在下一条消息唤醒时自动换一个新 DSH 会话；闲置未超
  阈值时，每约 55 分钟跑一次极轻的保温轮，续缓存并按 skill 规则归并当前对象画像。
- 目标：独立 skill 形态保持同一套 55 分钟保温与 3 小时闲置规则，但它没有会话管理权——
  3 小时没有新消息命中就退出，不重挂、不新建会话。
- 非目标：不新增后台定时模型调用给「没有绑定会话」或「从没跑过一轮」的对象；不做夜间免打扰
  时段（后续可加）；不改轮询节奏、水位与发送路径；不由插件代写画像或判断画像该删什么；
  不让 skill 自动换会话。

## 方案

### 1. 两个配置键

| 键 | 默认 | 范围 | 含义 |
| --- | --- | --- | --- |
| `dsh.idle_reset_min` | `180` | 0–1440 | 超过这么久没有「真实 turn」→ 下次唤醒前清空会话绑定；`0` = 关闭 |
| `dsh.warm_min` | `55` | 0–1440 | 闲置达到这么久跑一次保温轮；`0` = 关闭；重开开启时只在重开窗口内跑 |

「真实 turn」= `last_turn.at` 或 `session_bound_at`，**不包括**保温轮。保温轮不会把闲置时钟
推后：否则每 55 分钟一次心跳会让 3 小时重开永远不触发。

两个键各自独立：`warm_min=0` 只关保温，`idle_reset_min=0` 只关重开；重开关闭时保温仍按
间隔跑，只是不再换会话（长时间无人时仍会产生每小时一次缓存续期）。

### 2. 闲置重开（lazy，不在定时器里做）

`Turns._wake()` 在取消在飞 turn 之后、`resolveSession()` 之前判断：

- 有 `dsh_session`、`idle_reset_min > 0`、没有在飞 turn；
- `now - max(last_turn.at, session_bound_at) >= idle_reset_min * 60`；
- 命中就把 `state.setSession(chat, "")` 并记 `last_reset = {at, reason:"idle"}`。

之后走正常的新会话创建：`firstTurn` 为真，载荷重新带 `/cyber-im-avatar`、平台/对象、chat_id、
运行形态、画像路径，并多一行「上一次会话闲置超过 N 分钟，已自动重开；更早上下文按 skill 在线拉」。
旧会话原样留在 DSH 侧边栏，不删除、不归档。

手动重开、换工作区、会话丢失也写 `last_reset`，`reason` 分别为 `manual` / `workspace` / `missing`，
面板据此说清「为什么换了一个会话」。

### 3. 保温轮

调度在 `Poller.tick()` 之后，一次 tick 最多启动一个，避免整点同时叫醒一批会话。候选条件：

- `watching`、未屏蔽、平台已启用、有 `dsh_session`、`prompt_session === dsh_session`；
- 没有在飞 turn、没有待回（有待回交给正常唤醒）；
- `now - max(last_turn.at, session_bound_at) >= warm_min*60`；
- 若 `idle_reset_min > 0`，还要求闲置 **未到** 重开阈值（快重开的会话不再保温）；
- `now - last_warm_at >= warm_min*60`（失败也退避，不每个 tick 重试）。

`Turns.warm(chat)` 只复用**已存在**的会话（不新建），跑 `runTurn(..., warm:true)`：

- 载荷以「（值守心跳，不是客户消息）」开头，给画像绝对路径，要求按
  `SKILL.md §服务对象画像` 的规则检查/归并，不需要改就一个字别改；不拉消息、不发消息；
- 不写 `session_turns`、`last_turn`、`wake.active`，只写 `last_warm_at` / `last_warm_ok`；
- 不触发 post-turn 补拉；失败只记日志与字段，不覆盖 `last_error`；
- 真实消息到达时按现有 `wake()` 路径取消在飞 turn；保温启动到一半也会被取消。

### 4. 状态与面板

`chats` 末尾追加三个字段（契约 02）：

| 字段 | 形状 | 含义 |
| --- | --- | --- |
| `last_warm_at` | number | 最近一次保温轮的墙钟时刻；`0` = 没跑过 |
| `last_warm_ok` | bool/null | 最近一次保温轮结果；null = 没跑过 |
| `last_reset` | object | `{at, reason}`；reason = `idle` / `manual` / `workspace` / `missing` |

设置页新增「会话生命周期」卡片：两个数字框（分钟）+ 一个保存按钮，`0` 即关闭。
详情页在 DSH 会话行补「上次保温」与「闲置重开」提示；`turn_state === "warm"` 时显示「画像归并中」，
不显示成「处理中」，收件箱里也不把它算作 busy。

### 5. 插件里的话术

`SKILL.md §在 DSH 插件壳里` 增加「值守心跳」：收到这类载荷时按画像整理规则处理，
把它当维护轮而不是客户消息；规则只在 skill 写一份，插件 prompt 只做指针。

### 6. 独立 skill 形态：保温 + 闲置退出，不换会话

监听引擎没有会话管理权，不自动开新会话；把同一套节奏落在进程上：

- `--idle-exit-min` 默认 180：连续这么久没有「命中」就退出 **4**，stderr 标 `[idle-exit]`。
  命中才刷新 `idle_at`；被 `--sender` / `--keyword` 过滤掉的、自己发的都不算。
- 闲置时钟存进水位文件（`idle_at`），跨 55 分钟重挂沿用；`--new-watch` 只在用户明确要求
  重新值守时归零，自动重挂不带。
- `[cache-refresh]` 退出 3 时，agent 重挂前按 `SKILL.md §服务对象画像` 检查/归并一次，
  与插件保温轮同口径；退出 4 时不要重挂、不要开新会话。
- 退出 4 不是错误：用户不在时静默结束；下次用户要求继续值守，再加 `--new-watch`。

## 取舍

| 备选 | 否掉的理由 |
| --- | --- |
| 只做 55 分钟保温，不重开 | 上下文无上限；长会话越跑越贵，且旧事实会一直拖着 |
| 只重开，不保温 | 1–3 小时的间隔仍是冷缓存全价读；也没有画像归并的时机 |
| 保温时由插件直接调模型（不走 agent） | 无法复现 agent 下一轮的完整前缀（系统提示、工具表、动态上下文），不会命中缓存；还会绕过 skill 规则 |
| 保温轮结束后删掉这两条消息 | DSH 会话只追加，没有截断接口；靠 3 小时重开把旧轮次自然丢掉 |
| 每小时无条件整理画像 | 画像很小时是白跑工具调用；让 agent 按 8KB/20 条规则先判断，不需要就不动 |
| 定时器到点主动重开会话 | 没人说话时换会话没有收益；惰性重开只在下一条消息到来时发生，读数最准 |
| skill 也自动开新会话 | 监听引擎没有会话管理权，开了也是用户的会话；退出 4 结束值守、下次用户要求再挂更诚实 |

## 风险与回滚

- 风险：保温轮被模型误当成客户消息而对外发送；已在 prompt 与 skill 两处写明禁止，且发送仍需
  走 skill 的草稿/确认流。风险：每小时一次模型调用带来额外费用；`dsh.warm_min=0` 一键关闭。
  风险：3 小时重开丢掉会话内细节；画像与最近消息仍在本地，载荷明确要求按 skill 在线拉历史。
- 回滚：把两个键设为 0 即恢复现状；撤掉 `Turns.warm` / `maybeWarm` / `_wake` 的重开分支与
  三个字段即可，已产生的 `last_reset` / `last_warm_*` 不影响老代码加载。

# 0021 面板体验加固

> 状态: 已验收
> 编号: 0021
> 版本: 0.9.0
> 关联: `dsh-plugin/web/panel.js`、`dsh-plugin/scripts/demo/fixture.mjs`；无接口 / 存储 / 配置变化

## 背景

2026-11-03 对右侧栏面板做了一次交互走查：同一份 `dsh-plugin/web/panel.js` 挂在独立
预览页上，覆盖收件箱、分身、服务对象、体检、设置五个页签与会话详情，420 / 360 / 320
三种侧栏宽度，浅色与深色；另外模拟了 60 秒自动刷新和接口 500。结论不是单点样式问题，
而是三类基础体验缺口：

1. **刷新会打断输入**：后台 60 秒 `tick` 触发 `loadStatus()` / `loadChats()`，进而
   `paintBody()` 整块重建，输入值只存在 DOM 里。
2. **失败会伪装成空**：`api()` 对 500 / 网络错误不报错，各 `load*` 用 `d.items || []`
   覆盖本地数据，空态与错误态不可区分。
3. **窄侧栏布局失效**：320px 整块面板被裁；360px 设置页数字输入框被挤到约 31px。

另有收件箱行信息过载、危险操作无确认、收件箱行不可键盘操作、面板正文露内部 ID 等
问题。下表是本次走查的读数，作为本 spec 的验收基线：

| 场景 | 读数 / 现象 |
| --- | --- |
| 搜索框输入「林一」不提交，等 62 秒 | 输入值变为空字符串，焦点从 input 落到 body |
| 从「分身」卡片点「打开」，在输入框写「先别发，等我确认」，等 62 秒 | 草稿变为空字符串 |
| 360px 设置页两个 `input[type=number]` | 实测宽度约 30.97px，10 / 20 不可见 |
| 320px 面板 | `clientWidth=320`、`scrollWidth=360`；tab 栏最小宽度把 grid 列撑开 |
| `/api/inbox` 返回 500 | 列表显示「暂时没有需要你回的消息」，没有任何错误提示 |
| 真实 grouped 收件箱数据，360px | 「林一帆」→「林…」，「云雀项目 · 交付群」→「云雀…」；工作区 chip 只剩「agent」 |
| 真实 grouped 收件箱数据，420px | 群名「云雀项目 · …」与「默认 · agent…」被截断 |

> 范围说明：搜人 / 搜群卡片的「清空」按钮已实现；本次走查发现并修掉了「清空时搜索请求
> 尚未返回、旧响应把结果重新弹回来」的竞态（`web/panel.js` 的 `S.search.seq`，已重建
> `lib/client.js`）。本 spec 只列剩余问题，不重复已修项。

## 目标与非目标

- 目标：面板在 320 / 360 的右侧栏宽度下可正常读、可正常输入；后台刷新不再吞掉用户输入；
  接口失败必须看得见、可重试；破坏性操作先确认；收件箱主路径键盘可达。
- 非目标：
  - 不改轮询节奏、唤醒、发送、屏蔽、待回状态的后端语义；不改 `/api/*` 契约、
    `state.json` 字段与配置键。
  - 不重做视觉系统，不引入第三方运行时依赖，不新开端口。
  - 不做消息分页 / 「加载更早」；本次只把「最近 30 条」说清楚，分页另开 spec。
  - 0020 负责的「重开会话」入口位置与文案不在这里重复；若 0020 先实施，本 spec 只保留
    窄宽度下的视觉检查。
  - 不改 DSH 主题 token。11px tertiary 文本对比度偏低属于已知视觉债，本次记录、
    不调整（避免偏离宿主主题）。
  - 草稿只放内存，不写 `localStorage` / 磁盘；消息正文仍然不出本机。

## 方案

### 1. 刷新不打断输入（P0）

#### 1.1 输入中跳过后台 body 重绘（已实施）

在 `paintBody()` 入口判断当前焦点：焦点在文本框或文本域（`input` 且不是
checkbox / radio / button / submit，或 `textarea`）时，只刷新 header / footer，
不替换 `.ims-body`。选择 `select`、checkbox 仍按原逻辑重绘，避免影响工作区选择、
值守开关等即时操作。

- 不改变 `paint()` 的整体语义：页签切换、打开会话等用户主动导航仍然整块重建。
- 跳过的只是后台 `tick` / `loadStatus` / `loadChats` 触发的 body 重绘；下一次
  失焦、页签切换或用户操作会补上。
- 目的：用户正在打字时，不被 60 秒刷新清空、不丢焦点、不打断输入法候选。

#### 1.2 草稿落在面板内存里（未实施，下一批）

只靠 1.1 还不够——用户输入后失焦，再遇到一次重绘仍会丢。各输入点补内存草稿，
重绘时恢复：

| 位置 | 状态字段 | 恢复 / 清理 |
| --- | --- | --- |
| 搜人 / 搜群输入框 | `S.search.q`（现在只在点搜索时写） | `input` 事件实时写入；清空或搜索成功后再按现有逻辑处理 |
| 企微手动加入表单 | `S.search.wc = { name, id, kind }` | 输入 / 选择时写入；加入成功后清空 |
| 会话详情手动发送框 | `S.composerDrafts[platform:chat_id]` | `input` 时写入；发送成功后删除该会话草稿 |
| 设置页「拉取间隔」「私聊取前 N 个」 | `S.pollDraft = { interval_min, dm_recent }` | `input` 时写入；保存成功后清空 |
| 服务对象画像编辑 | 已有 `S.targetDrafts` | 保持不变 |

草稿只存在当前面板实例的内存中，不落盘、不跨刷新；面板卸载即丢。

### 2. 失败可见，不装空（P0）

现状：`api()` 在 HTTP 500 / 网络异常时返回 `{ error }` 或直接 reject，但
`loadStatus` / `loadInbox` / `loadChats` / `loadTargets` / `loadWorkspaces` 没有
区分「成功且 0 条」与「请求失败」，导致空态、0 计数、绿点「正在连接」等误导状态。

改法：

1. `web/panel.js` 增加统一的连接错误状态 `S.connError`（短文案 + 可选重试回调），
   只在请求成功时清空。
2. `loadStatus`：失败时保留上一份 `S.status`，设置 `S.connError`；头部圆点改为
   warn / 灰色，副标题显示「本地服务连接失败」而不是「正在连接本地服务…」。
   `S.status` 为空时不再显示绿点。
3. `loadInbox` / `loadChats` / `loadTargets`：失败时保留旧数据，设置 `S.connError`；
   对应页签顶部显示一条 `ims-banner warn`：「本地服务连不上：<短原因> · 重试」。
   空状态只在请求成功且确实 0 条时出现。
4. `openThread` / `refreshDetail`：请求失败时用已有的 `S.threadError` /
   `S.threadOffline` 展示错误横幅，不再落到「在线没有拉到消息」。
5. 401 保留现有「自动刷新一次」逻辑；刷新后仍失败时，横幅明确写「会话凭据过期，
   刷新页面（⌘R）」。不无限 reload。
6. 可重试入口：横幅上的「重试」调用对应的 `load*`；头部「同步」仍然只负责拉取一轮。

### 3. 窄侧栏布局（P0）

#### 3.1 面板不横向溢出

- `.ims-panel` 的 grid 列改为 `minmax(0, 1fr)`，让列可以收缩到容器宽度。
- `.ims-head` / `.ims-tabs` / `.ims-body` / `.ims-foot` 补 `min-width: 0`。
- `.ims-tabs` 保持横向滚动；320px 时标签栏可以左右滑，不再把整块面板撑到 360px。
- `.ims-card-h` / `.ims-rowline` 补 `min-width: 0`，卡片头允许换行；服务卡片头部的
  「去会话 / 打开 / 屏蔽」在 320px 时换到下一行，而不是被裁掉。

#### 3.2 设置页数字输入框

- 给三个数字框（值守间隔 / 发现间隔 / 私聊取前 N）固定 `flex: 0 0 92px;
  width: 92px`（或等价 class），不再参与 `flex:1` 的压缩。
- 行内放不下时由 `.ims-rowline` 的 `flex-wrap` 换行，标签和输入框保持配对。
- 验收宽度：360px 与 320px 下都能看清 `10` / `20` / `60`，输入框不小于 90px。

### 4. 收件箱行信息层级（P1）

现状：真实 grouped 数据下，一行同时出现名称、`私聊`、工作区 chip、未读点、
`agent 处理中`、屏蔽图标、时间、条数、展开箭头；名称被压缩成「林…」。

改法：

- 收件箱行不再渲染 `KIND.dm` 的「私聊」标签；群仍然显示「群」，`@我` / `客服` 等
  有意义的 kind 保留。平台头像与名称已经足够表达私聊。
- 「agent 处理中」缩短为「处理中」，`title` 保留「agent 正在处理这通会话」。
- 名称优先：名称不先于工作区 chip 被压缩；工作区 chip 允许截断，但保留完整
  `title`。行内空间仍不够时，把工作区 chip 放到摘要行下方（第二行），不要让名称
  变成单字。
- 服务卡片和详情里的重复状态文案一并收敛：卡片头已有「处理中」标签时，
  下面不再重复「agent 处理中」；详情保留一句说明即可。

验收基线：360px 下，`林一帆` 至少完整显示；`云雀项目 · 交付群` 至少显示
「云雀项目」四个字；工作区 chip 可见或可通过 `title` 读出；无横向滚动。

### 5. 危险操作确认（P1）

只加前端确认 / 置灰，不改变后端语义：

| 操作 | 现状 | 改为 |
| --- | --- | --- |
| 收件箱行屏蔽图标 / 详情「屏蔽」 | 一点即屏蔽；当前待回被标忽略、正文清空，取消屏蔽也不恢复 | 先确认，文案写明「会立即忽略当前待回并清空本地正文；取消屏蔽不会恢复」 |
| 设置「清理其他会话的待回」 | 一点即清理，没有确认 | 有待回时先确认；没有可清理项时置灰 |
| 值守中「移出」 | 直接取消值守，运行中的 turn 也会被打断 | 仅当 `turn_state === "running"` 时确认「会打断当前 agent 轮次」；空闲时不弹 |
| 详情「忽略这条」 | 没有待回时仍可点，点了才提示「没有可忽略的消息」 | 没有 `msg_id` 或没有待回时置灰 / 隐藏 |

### 6. 可访问性与信息暴露（P1 / P2）

- **收件箱行键盘可达**：`.ims-row` 增加 `role="button"`、`tabindex="0"`、
  `aria-label`（名称 + 摘要），并处理 Enter / Space；补可见的 `focus-visible`
  轮廓。Tab 能走到行，Enter 打开会话。
- **不再在正文露 imid**：
  - 服务对象卡片移除右上角的 `t.chat_id` 文本；需要排障时放进 `title` 或复制动作。
  - 体检页「本人」只显示可读名称；`self_id` 不进入可见文本，需要时放 `title`。
  - 搜索卡片已有的「不显示平台 id」规则不变。
- **按钮语义**：
  - 详情头部「拉取」从 ghost 文本改为带边框 / 同步图标的按钮，避免被读成
    「值守」开关的标签；文案可用「拉一次」。
  - 0020 已负责「重开会话」的位置与文案，这里不重复。
- **文案一致性**：
  - 服务对象标题「N 人」改为「N 个对象」（群对象也被计入）。
  - 空收件箱按筛选给出不同文案：待回 / 未读 / @我 / 私聊 / 全部。
  - 详情消息区显示「只显示最近 30 条；更早消息去 IM 客户端或 DSH 会话看」。
  - 搜索框 placeholder 在 360px 被截成「搜人 / 搜群：输入名称，…」；缩短为
    「输入名称搜索」或保留原文，但不要让截断影响输入。
- **已知视觉债**：11px tertiary 文本的对比度约 3.7:1，低于 WCAG AA 的 4.5:1。
  它来自 DSH 主题 token，本次不改；如果以后要改，先改主题 token 的消费方式，
  不要给面板单独塞颜色值。

### 7. 演示夹具对齐（P1，开发工具）

`dsh-plugin/scripts/demo/fixture.mjs` 的 `/api/inbox` 当前返回扁平消息，而真实
`/api/inbox` 默认返回按会话聚合的 `{ grouped: true, items: [{ count, unread,
last_epoch, kinds, preview }] }`。这会让独立预览页把同一个群拆成多行、时间与条数
不显示，后续截图 / 走查会误判。

- 夹具改为 grouped 形状，并补 `platforms[].chats`，消除预览里的 `undefined`。
- 增加仅开发用的失败开关（如 `#fail=inbox` / `#fail=status` / `#fail=chats`），
  让「500 不装空」可以在演示页稳定复现；不进入运行时。
- 更新后重新截 360 / 420 的收件箱、设置与详情图，作为本 spec 的走查证据。

### 8. 实施顺序

1. 1.1 + 1.2：输入保护与草稿恢复（`web/panel.js`，重建 `lib/client.js`）。
2. 2：连接错误状态与错误横幅（同一文件）。
3. 3：窄侧栏 grid / 换行 / 数字框（同一文件）。
4. 4 + 5：收件箱密度、危险操作确认（同一文件）。
5. 6：键盘可达、内部 ID、文案与按钮语义（同一文件）。
6. 7：演示夹具与失败开关（`scripts/demo/fixture.mjs`）。
7. 每步用演示页对应宽度截图 + `bash scripts/gate.sh --quick`；最后跑 `node --test`。

## 取舍

| 备选 | 否掉的理由 |
| --- | --- |
| 草稿写 `localStorage` 或 `state.json` | 消息正文会落盘，违背「消息只在本机内存 / 本地状态最小化」的边界；只放内存 |
| 直接停掉 60 秒自动刷新 | 状态会过期；采用「输入中跳过 body 重绘 + 草稿恢复」，header/footer 仍可刷新 |
| 让 `api()` 对所有非 2xx 直接 reject | 会影响所有 mutation 调用点的错误分支；先在数据加载器收口，接口契约不动 |
| 把屏蔽改成不清理待回 | 会改变后端语义与已有数据行为，另开 spec；本次只做确认 |
| 收件箱直接改成三行卡片 | 改动大、密度更低；先压缩标签和调整收缩优先级，保留两行结构 |
| 用 container query / JS 监听尺寸 | 先用 `grid minmax` + `flex-wrap`，零依赖、可回退 |
| 给面板单独调一套低对比度颜色 | 会偏离 DSH 主题 token；作为已知视觉债记录 |

## 影响面

- 代码：`dsh-plugin/web/panel.js`；`dsh-plugin/lib/client.js` 由
  `dsh-plugin/scripts/build_client.py` 重建；`dsh-plugin/scripts/demo/fixture.mjs`
  （仅演示）。
- 契约：无接口、`state.json`、配置键变化，不需要改 `docs/specs/contracts/`。
- 用户可见：右侧栏面板的输入、错误提示、窄宽度布局、收件箱行、危险操作确认、
  键盘操作与部分文案。
- 兼容：老状态文件、老工作区、已有值守会话不受影响；草稿只在内存，升级即失效。
- 测试：不引入 DOM 测试框架；用演示页 + CDP 截图 / evaluate 验收，`node --test`
  与 `gate.sh --quick` 保持全绿。

## 验收

- [x] 搜索框输入「林一」不提交，等待超过 60 秒：输入内容仍在，焦点不丢，清空按钮仍可见。
      实测（360px，65 秒）：`{value:"林一", focused:true, clear:true}`；切页签重绘后仍为
      `林一`（焦点按预期不保留）。
- [x] 从「分身」卡片点「打开」，在输入框写「先别发」，等待超过 60 秒：草稿仍在；
      点发送成功后该会话草稿清空。实测：65 秒后与强制重绘后均为「先别发」，发送后
      输入框为空。
- [x] 设置页把三个数字框分别改为有效值，等待超过 60 秒：值仍在；保存成功后草稿清除。
      实测：60 秒后仍为 `45 / 12 / 30`；保存 toast「已保存：值守 45 秒一拉 · 发现每 12 分钟」，
      三个值从 `/api/config` 回填。
- [x] `/api/inbox` 模拟 500：列表保留上一份数据并显示错误横幅；点「重试」成功后横幅消失；
      不再出现「暂时没有需要你回的消息」假空态。实测 `#fail=inbox`：横幅
      「本地服务连不上：…」、列表 3 行、空态 0 个；去掉故障后点「重试」，横幅 0 个、仍是 3 行。
- [x] `/api/status` 模拟 500：头部不再显示绿点 / 「正在连接本地服务…」，显示连接失败；
      体检页保留上次数据或明确错误。实测 `#fail=status`：圆点 `var(--fg3)`，副标题
      「本地服务连接失败」，无假空态。
- [x] 320px：`.ims-panel` 的 `scrollWidth === clientWidth`；tab 栏可横向滚动；
      所有按钮与文字不被裁掉。实测六个页签均为 `320/320`，tab 栏 `320/385`，越界元素 0。
- [x] 360px：设置页数字框宽度不小于 90px，能看清并修改 `10` / `20`。
      实测三个 `input[type=number]` 均为 92px，六页签 `360/360`。
- [x] 用 grouped 夹具在 360px 渲染收件箱：`林一帆` 完整显示，`云雀项目 · 交付群`
      至少显示「云雀项目」；工作区 chip 有完整 `title`；无横向滚动。实测名称三项完整，
      chip `title` 为 `/Users/demo/work/agent-hub（DSH 工作区）`，`scrollWidth=360`。
- [x] 收件箱点屏蔽：先弹确认（写明待回会被忽略、正文清空）；取消后状态不变；
      确认后可在设置里取消屏蔽。实测确认文案包含「会立即忽略它当前的待回，并清空本地
      保存的消息正文；取消屏蔽不会恢复」；取消后仍 3 行，确认后 2 行，设置页出现
      「已屏蔽的会话 · 林一帆 · 取消屏蔽」。
- [x] 「清理其他会话的待回」：有待回时先确认；没有可清理项时置灰。

## 风险与回滚

- 风险：输入中跳过后台 body 重绘，用户可能暂时看不到新消息。header / footer 仍刷新，
  失焦、切页签或下一次操作会补上；可接受。
- 风险：确认框增加操作步骤；只对真正不可逆的操作加，且文案写清后果。
- 风险：隐藏 imid 会降低现场排障的便利；保留 `title` / 日志入口，不牺牲正文可读性。
- 风险：收件箱行按 360px 调完，1400px 宽屏可能显得过松；用 420 / 1400 截图回归。
- 回滚：整体回退 `dsh-plugin/web/panel.js` 与重建后的 `lib/client.js`；无数据迁移、
  无配置变更，草稿只在内存，回滚不影响 `state.json`。

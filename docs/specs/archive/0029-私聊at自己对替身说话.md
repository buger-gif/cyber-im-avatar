# 0029 私聊 @ 自己即对替身说话

> 状态: 已验收
> 编号: 0029
> 版本: 0.13.0
> 关联: `docs/specs/contracts/01-api.md`、`docs/specs/contracts/02-storage.md`、`docs/specs/active/0027-私聊仅at唤醒.md`

## 背景

spec 0027 给私聊加了「只盯 @我」：只有**对方** @ 我才唤醒 agent。但用户也会在同一个私聊里
**自己 @ 自己**（正文写 `@<自己的显示名>`）跟替身说话：「@自己 帮我回他一下」。这是用户跟
AI 交互的方式之一，当前却完全无效——自己发的消息一律记 `out`、状态 `replied`，永不唤醒
（防回环口径）。

实测（本机 2026-11-04 15:43）：用户在值守私聊里发了一条以 `@<自己显示名>` 开头的消息，
poller 判成 `out/replied`，没有进批次，agent 没收到。

## 目标与非目标

- 目标：**私聊**里自己发的、确实 @ 到自己的新消息 → 记 `kind=cmd`，进唤醒批次，唤醒 agent。
  其它自己发的消息保持 `out`，不唤醒（防回环不变）。
- 目标：唤醒载荷把 `cmd` 行标成「本人（@自己）」，并写明：按指令执行/回答、不是客户消息、
  除非指令要求不要对外发消息、**回复里不要 @ 自己**（否则再次唤醒）。
- 目标：防回环熔断——同一会话 10 分钟内 cmd 唤醒超过 5 次就停下并在面板报错，
  而不是让一个回环无限烧 token。
- 非目标：不动群。群里自己 @ 自己仍记 `out`（噪声大、容易误伤，本次只做私聊）。
- 非目标：不改 @ 判定（复用 `isMention`：结构化 mentions 按本人 ID，缺 mentions 时按正文
  `@显示名` 词边界）。
- 非目标：不做新配置键，默认开启；不改 state 版本（`kind` 是开放枚举，新增值不需要迁移）。
- 非目标：不把 `cmd` 算待回/未读/角标——它是本人给替身的指令，不是客户在等回复。
- 非目标：cmd 唤醒失败不自动重试（它不进 `pendingCount`）；用户重发或点「现在处理」即可。

## 方案

### 1. 分类（`poller.process()`）

- 新增 `isCmd`：`chat.kind !== "group" && isSelf && isMention(m, selfId, names)`。
- 优先级：`baseline` → `isSelf ? replied : ignored`；否则 `isCmd` → `kind="cmd"`、
  `state="new"`；否则 `isSelf` → `out/replied`；其余按 0027 的 mention/all 口径。
- `cmd` 保留正文（`keepBody` 条件本来就是「new 且不是 out」）。
- `selfEpoch`（用于把同批更早消息标成 replied）**排除 cmd**：本人给替身下指令不等于已经
  回复了对面的消息，别把对面还没处理的 @ 吞掉。

### 2. 批次与唤醒（`poller.js`）

- `collectBatch` 的非 all 分支加入 `cmd`；`all` 分支只服务群，不涉及。
- `maybeWake`：批次里有 `cmd` 时先过熔断（见 §4），再走原有 `turns.wake`。
- `cmd` 不进 `isPendingMessage`（`state.js`），所以不刷角标、不进待回；`messageMatches`
  只在「全部」筛选里出现（默认分支）。

### 3. 载荷（`turns.js`）

- `formatMsgLine`：`cmd` 的说话人标成 `本人（@自己）`。
- 批次含 `cmd` 时附一段规则：
  「【本人指令】带「本人（@自己）」的行是本人对替身说的话，不是客户消息：按它执行或回答；
  除非指令明确要求、或按 skill 判断确有必要，否则不要往会话里发消息；你的回复里不要
  @ 本人自己——那会再次触发唤醒，形成回环。」
- 开场载荷里若最近上下文含 `cmd`，也加一句轻量说明（不是客户消息）。

### 4. 防回环熔断

`Poller` 内存里按会话记 cmd 唤醒时间（不落 state）：10 分钟窗口内 ≥5 次 → 本轮不唤醒，
`chat.last_error` 写「本人指令 10 分钟内超过 5 条，已暂停唤醒（疑似回环）」，同时进
`/api/logs` 的错误列表。冷却后自然恢复；宿主重启计数清空。

### 5. 面板（`web/panel.js`）

- `KIND` 增加 `cmd`：标签「指令」、强调色；`msgText` 的空正文兜底加「本人指令」。
- 收件箱筛选不变：cmd 只在「全部」里出现，不刷角标。

## 取舍

| 备选 | 否掉的理由 |
| --- | --- |
| 所有自己发的消息都唤醒 | 会自回环：agent 的回复也是自己发的，无限唤醒 |
| 用 `kind=dm` 复用待回口径 | 自己的指令会进待回/角标，像是客户在等回复 |
| 群里也支持 | 群里 @ 自己噪声大，且 agent 的回复全群可见，先只做私聊 |
| 加配置键开关 | 需求就是"交互方式"，默认可用；熔断兜底，不必多一个开关 |
| `cmd` 失败自动重试 | 指令不是待回，失败把 `last_turn` 报给用户看；重发即可，避免回环时反复重试 |

## 影响面

- 代码：`lib/poller.js`（分类、批次、熔断）、`lib/state.js`（`cmd` 进枚举、不算待回）、
  `lib/turns.js`（消息行与规则）、`web/panel.js` 与构建产物。
- 契约：`docs/specs/contracts/02-storage.md`（`kind` 枚举加 `cmd`）。
- 用户可见：私聊里自己 @ 自己会唤醒替身；收件箱「全部」里能看到这类行（标签「指令」）。
- 兼容：老 state 不含 `cmd`，加载无需迁移；降级回旧版时 `cmd` 会被归一化成 `fyi`，不影响发送。

## 风险与回滚

- 风险：agent 若在回复里 @ 自己会形成回环；靠载荷规则 + 熔断兜底，面板能看到 `last_error`。
- 风险：`cmd` 行会在「全部」筛选里出现，属预期；不进待回/角标。
- 回滚：撤掉分类分支即可回到「自己发的一律 out」；已写入的 `cmd` 行在旧版会归一化为 `fyi`，
  无数据迁移。

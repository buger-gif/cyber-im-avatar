# 0028 重开会话即开新会话

> 状态: 已验收
> 编号: 0028
> 版本: 0.13.0
> 关联: `docs/specs/contracts/01-api.md`

## 背景

spec 0020 把「重开会话」定为**只解绑**：打断在飞 turn、清空 `dsh_session`，等**下一轮命中**
再开新会话。当时的理由是「新会话要有第一条消息才有意义，空开会浪费一次上下文」，而且
值守私聊每条消息都命中，这个条件几乎立刻满足。

spec 0027 给私聊加了「只盯 @我」之后前提变了：普通消息不再命中，重开会话后可能几小时都
等不到「下一轮命中」。实测（本机 2026-11-04 15:41）：点重开会话后 `dsh_session` 清空、
`session_turns=0`，此后 4 分钟内没有新会话；面板只有「还没跑过；命中新消息时自动创建」，
看起来就是按钮失灵。同一时段用户还在切换关注程度，切完也没有任何 turn 起来，进一步加深
「旧会话没续上」的印象。

## 目标与非目标

- 目标：值守中（未屏蔽）的会话点「重开会话」后，**立刻**在新会话里跑一轮开场，面板与
  DSH 侧边栏马上有可继续的会话，不再依赖后续消息命中。
- 目标：切换关注程度时把会话状态说清楚（继续用当前会话 / 下一条命中开新会话），
  不让用户把「只认 @ 不唤醒普通消息」误判成会话坏了。
- 非目标：不改 @ 判定与「只盯 @我」语义；不改开场轮文案与「没该回的就不要发」的约束；
  不改闲置重开阈值（`dsh.idle_reset_min`）与保温轮；不给「只解绑、不跑」的第二个按钮；
  不动 skill 形态（它没有会话管理权）。
- 目标：同一类"主动丢掉绑定"的操作口径一致——换工作区把旧会话解绑时，值守中的会话
  也立刻在新工作区开一个，不再等下一轮命中。

## 方案

### 1. 接口：解绑后立刻开场

`POST /api/chat/session/reset` 在清空绑定并落盘之后：

- `watching && !blocked` → 调 `openAfterJoin(chat)`（先补拉一次，`wake=false, force=true`，
  不推进水位；再起一轮开场 turn）；返回体加 `open: {ok, reason, skipped}`，失败只报告
  原因，不回滚解绑。
- 未值守 / 已屏蔽 / 宿主未就绪 → 只解绑，`open` 为 `null` 或 `{ok:false, reason}`。
- **刚 cancel 的旧轮不算"在飞"**：`Turns` 新增 `busy()`（只有未取消的句柄算在飞），
  `Turns.open()` / `App.openAfterJoin()` / `/api/chat/wake` 都改用它。否则重开/关→开
  刚 cancel 完、句柄还在 `active` 里收尾时，open 会被误判成 `running` 而静默不开。
- 换工作区（`/api/chat/workspace`）同样收口：工作区变了、旧会话因此解绑、会话又在值守中
  （未屏蔽）→ 立刻开新会话，返回 `open`。面板 toast 一并说明。

开场轮沿用 spec 0025 的口径：先读最近 30 分钟上下文与画像，**没有需要回的就不要往会话里
发任何消息**，所以重开不会凭空对外发话。

### 2. 面板文案

- 确认框：`重开会话？会打断正在跑的这一轮，并立刻在新会话里重新开场（旧会话留在侧边栏，
  不再续聊）。新会话开在「<工作区>」。`
- 成功 toast：`已重开：旧会话留在侧边栏 · 新会话已开`；失败给
  `会话没起来：<原因>，下一条命中会重试`。
- 切换关注程度的 toast 补会话状态：已绑定 → `继续用当前会话`；没绑定 → `下一条命中开新会话`。

### 3. 覆盖 spec 0020 的取舍

0020 否掉「立刻新建」的前提是「下一条消息就会来」。0027 之后 @-only 私聊可能长期没有下一条
**命中**，所以改成「解绑 + 立刻开场」；空会话的顾虑由开场轮的「没该回的就不发」兜住。
0020 的按钮位置/命名/确认流程不变。

## 取舍

| 备选 | 否掉的理由 |
| --- | --- |
| 只改文案，保持只解绑 | 用户已经把它当失灵；@-only 下「下一轮命中」不可预期 |
| 空建会话但不跑开场轮 | DSH 侧边栏里没有内容的会话仍像「没建」；首轮载荷与 `prompt_session` 要靠一轮 turn 消费 |
| 只在空闲时自动开场（在飞打断就不跑） | 同一个按钮两套行为，无法预期；要停就用移出值守 / 屏蔽 |
| 重开后自动发一条消息 | 开场轮按 skill 判断该不该回，不强制外发；自动发会替你说话 |

## 影响面

- 代码：`dsh-plugin/lib/app.js`（`chatSessionReset`）、`dsh-plugin/web/panel.js` 与构建产物、
  `dsh-plugin/tests/app.test.mjs`。

- 兼容：接口只增返回字段 `open`，老面板忽略它不受影响；`state.json` 无新字段。

## 风险与回滚

- 风险：每次重开多一轮模型调用；面板连点会连续换会话（有确认框）。
- 回滚：撤掉 `chatSessionReset` 里的 `openAfterJoin` 与面板文案即可；已解绑状态无需迁移。

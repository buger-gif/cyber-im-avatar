# 0060 发言权默认沉默

> 状态: 实施中
> 编号: 0060
> 版本: 0.26.0
> 关联: 修订 `docs/decisions/implemented/0017-发言权默认口径.md`；决策见
> `docs/decisions/implemented/0019-发言权默认沉默.md`

## 背景

2026-11-24 10:30，漏洞管理平台（bot）为一条高危越权漏洞自动建修复跟进群，
推「漏洞即将逾期提醒」卡片：mentions 里同时带处理人和安全跟进人（本人），正文只 @ 处理人问
进展，卡片里已写明截止时间与「已修复就提复测」。

10:35，值守分身以安全跟进人身份补发了一条「截止 2026-11-25 10:00；修好后提复测，我 24 小时
内复测」。事实没错，但这张卡已经把这些写全了——这条没有增量信息，只是把角色字段上的 @ 当成
「有人叫我干活」。用户当场指出：这种机器人消息没有主动要求干活，应该沉默。

ADR 0017 的默认口径是「点我名：回」「信息同步可以发」，没有区分真人消息与机器人通知，
也没给「信息同步」设门槛，于是自动建群 + 自动卡片正好落在「点名了但没人要我干活」的缝里。

## 目标与非目标

- 目标：默认动作改成沉默；发言必须有增量（对方还不知道、且会改变他动作的信息）或真人明确
  在问；机器消息的角色 @ 不再触发发言。
- 非目标：不改唤醒范围（仍只认 `mention.id == 本人 open_id`）；不改发送方式（全自动 /
  草稿审批）；不改分诊 watch / trial / ignore 口径；不禁止信息同步，只是要求有增量。

## 方案

### 1. 默认口径（代码单点）

`RIGHTS_DEFAULT`（`dsh-plugin/lib/profiles.js`）重写成六条：默认沉默 / 增量门槛 /
机器消息不算点名 / 不重复 / 节点才发 / 判不准沉默。工作本那一段为空时仍用它，写了自定义
发言权的群不受影响。

### 2. 载荷摘要

`rightsLine()`（`dsh-plugin/lib/turns.js`）同步成一句话摘要；`buildOpenPrompt` 的
「判断顺序」从「先看这条点名了谁」改成「先看正文要谁做什么，不是看点名」，并写明机器人
刚发过 / 卡片里写着的不算增量。

### 3. agent 规则

根 `SKILL.md`「本人与发言权」按同一口径改写；日报的「今日已处理」增加 `[未回]`：
判断后决定沉默的会话也要留一行，写清为什么不说，避免沉默变成丢线索。

### 4. 人看的两处

面板「发言权」默认口径占位与说明（`dsh-plugin/web/panel.js`，`build_client.py` 重建
`lib/client.js`）；值守方针初始版里的口径行（`dsh-plugin/lib/duty.js` 的 `DEFAULT_POLICY`，
只影响新装，已存在的 `duty/policy.md` 不覆盖）。

## 取舍

| 备选 | 否掉的理由 |
| --- | --- |
| 只在 `SKILL.md` 加一句「机器人消息别回」 | 每轮载荷先给的是代码里的默认摘要，两套口径会打架 |
| 把 bot 消息从唤醒里过滤掉 | 改的是唤醒范围；bot 卡片之后处理人回复仍要跟进，截止日还会再提醒一次 |
| 保留「信息同步可以发」 | 这次超发的直接原因就是它被理解成「把知道的再说一遍」 |
| 每个机器人群的工作本写窄口径 | 同一角色分工会在几十个自动群里重复；默认值应在一处常量，按群覆盖只留例外 |

## 影响面

- 代码：`dsh-plugin/lib/{profiles,turns,duty}.js`、`dsh-plugin/web/panel.js`（+ 产物 `lib/client.js`）
- 用户可见：面板「发言权」默认文案；群聊首轮与口径变化轮的载荷摘要
- 兼容：工作本已写自定义发言权的群不变；默认群下一轮载荷即生效（`lib/*.js` 改动需重启 DSH）

## 验收

- `cd dsh-plugin && node --test` 全绿（374 条，含更新后的三处发言权断言）
- `python3 tests/run_tests.py` 与 `bash scripts/gate.sh --quick` 全绿
- 复现口径：同一张 bot 催办卡进载荷 → 摘要为「默认沉默」，明确「机器 @ 不算叫我干活」；
  真人 @ 问进展 → 仍给「人问我、派到我头上才接」
- 真机：重启 DSH 后，下一个 bot 自动群的首轮载荷应带新口径，且分身不再补卡片已有的信息

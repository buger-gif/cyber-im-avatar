# 0025 加入值守即开会话

> 状态: 已验收
> 落地版本: 0.11.0
> 编号: 0025
> 版本: 0.11.0
> 关联: `docs/specs/contracts/01-api.md`

## 背景

「加入值守」现在只写一个布尔值：`watching=true`。真正的 DSH 会话要等到**下一条命中消息**
才创建——群要等 `@`，私聊要等新消息。于是有两种尴尬：

- 加了值守，侧边栏没有会话、面板显示「还没跑过」，用户不知道到底生效没有；
- 想先让 agent 把上下文读进去（画像、最近聊天），也必须先等别人发一句。

用户的动作语义很清楚：**点「加入值守」= 现在就开始替我盯**，不是「挂个号等下次」。
最近半小时没事可做，不回没关系；但会话必须先建起来。

## 目标与非目标

- 目标：`/api/watch` 加入值守（以及 `/api/chat/mode` 从 `off` 切到 `mention`/`all`）时，
  立刻补拉一次、创建/绑定 DSH 会话并起一轮「开场」turn；没有可回的就不发消息。
- 非目标：不改命中唤醒的既有判据；不在开场轮里替用户发任何消息；不新增配置键。

## 方案

### 1. 触发点（契约 01）

| 动作 | 现在 | 之后 |
| --- | --- | --- |
| `POST /api/watch`（加入，`watching` 非 false） | 只写状态 | 写状态 → 补拉一次（`wake=false`）→ 起开场 turn |
| `POST /api/chat/mode`（`off` → `mention`/`all`） | 只写状态 | 同上 |
| 已值守的两通会话互相 `watch` 再点一次 | 幂等 | 已有绑定会话时也起一轮（等价「现在处理」），但不打断在飞 turn：在飞则跳过 |

补拉用 `pollChat(..., {wake: false, force: true})`：过期冷却也拉，拿完整正文给开场轮；
不推进水位，所以后续命中唤醒不受影响。

### 2. 开场轮（`lib/turns.js`）

新增 `Turns.open(chat, {reason})`，复用 `_wake` 的会话创建与权限流程，区别只在载荷：

- 取本地最近 30 分钟内、有正文的消息（最多 10 条，按时间正序），作为「最近上下文」；
- 载荷标明这是**人工开启**、不是命中唤醒，并给出两条硬口径：
  1. 没有需要回的就不要往会话里发消息；
  2. 有该回的按 `SKILL.md` 照常处理（`all` 模式下非点名只看不回，沿用模式规则行）。
- 无任何消息时也起 turn，载荷写「最近 30 分钟没有新消息」，只做上下文准备。

会话创建仍走 `resolveSession()`：没有 `dsh_session` 就新建，已有就复用（绑定不变）。

### 3. 失败不阻塞值守

开场轮失败（宿主未就绪、工作区不存在、会话被别的宿主占用）不能把「加入值守」搞失败：
`/api/watch` 仍返回 `ok:true`，另给 `open: {ok, reason}`，面板据此提示
「会话没起来：<原因>，下一条消息会重试」。

### 4. 面板

- 搜索/收件箱加入值守成功后，toast 从「已加入值守」改为「已加入值守，正在开会话…」，
  拿到 `open.ok` 再补一句「会话已开」；
- 详情页刷新一次，让用户马上看到会话卡片与「N 轮」。

## 取舍

| 备选 | 否掉的理由 |
| --- | --- |
| 只建会话、不起 turn | DSH 的会话是 turn 跑出来的；空会话没有 agent 上下文，等于没开 |
| 加入后等下一个轮询周期再唤醒 | 用户点完可能几十秒没反馈，正是这次要修的问题 |
| 开场轮直接补发一条「已上线」 | 拿用户身份对外说话，不在值守草稿确认流里，硬停 |
| 给开场轮单独加配置开关 | 用户要的就是「点了就开」，开关只会让行为更难解释 |

## 影响面

- 代码：`dsh-plugin/lib/turns.js`（`open` + 载荷）、`lib/app.js`（两个入口调用）、
  `web/panel.js`（toast 与刷新）
- 契约：`01-api.md`（`/api/watch`、`/api/chat/mode` 的副作用与返回字段）
- 用户可见：加入值守后立即出现会话并跑一轮；失败有明确提示
- 兼容：老调用方忽略 `open` 字段即可；不新增状态字段、不改配置

## 验收

- [x] 私聊点「加入值守」→ 立刻出现 DSH 会话并跑完一轮，`session_turns` ≥1
- [x] 群里选「只盯 @我」→ 同上；没有新消息时载荷写「最近 30 分钟没有新消息」，且不往群里发
- [x] 已有绑定会话的会话再点加入 → 复用同一 `dsh_session`，不新建
- [x] 宿主未就绪 / 工作区不存在 → `/api/watch` 仍 `ok:true`，`open.reason` 可读，值守状态已保存
- [x] 开场轮不推进 `last_epoch`，随后新消息仍能正常命中唤醒
- [x] `node --test`、`python3 tests/run_tests.py`、`bash scripts/gate.sh --quick` 全绿

## 风险与回滚

- 风险：每次加入值守都会起一轮模型调用（几秒到几十秒、一次 token），批量加人时成本可见。
- 回滚：删掉两个入口里的 `open` 调用即可恢复「等下一条消息」；不涉及数据清理。

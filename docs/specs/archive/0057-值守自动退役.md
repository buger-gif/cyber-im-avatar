# 0057 值守自动退役

> 状态: 实施中
> 编号: 0057
> 版本: 0.26.0
> 关联: `docs/specs/contracts/02-storage.md`（duty 加字段）、
> `docs/specs/contracts/03-config.md`（新配置键）、`docs/specs/contracts/01-api.md`（counts）

## 背景

本机实测 `chats` 有 343 条、值守 26 个（18 群 + 8 私聊），其中 6 个已经超过 7 天没有一次
命中。现在没有任何自动退役：只有用户在面板手动「不盯」，或试用期复核失败才会停。值守列表
只会越来越多，每个群每 10 分钟一次的拉取、每个私聊的保温与上下文成本都还在。

「会话保活」那一步能不能顺手判断退役？不能直接塞进 `maybeWarm()` 的现有条件里：它只处理
**已经绑定 DSH 会话、且闲置落在 `dsh.warm_min` 到 `2 × dsh.warm_min` 之间**的会话。一个
7 天没有命中、会话也已过期不保温的会话，恰好永远不在那个窗口里。退役扫描应复用同一个后台
维护 tick，但条件独立，不依赖保温是否开启、DSH 宿主是否就绪。

## 目标与非目标

- 目标：一个值守连续 `duty.retire_after_days`（默认 7）天没有「命中」时，自动退出值守
  （`watching=false`、`timer=-1`、`duty.state="retired"`），面板能看到原因；不删会话、不删
  画像、不删 DSH 会话；用户重新加入即可恢复。
- 非目标：不清空待回、不退役正在处理 / 试用复核中的会话、不改轮询节奏、不自动恢复私聊
  值守、不自动删除 `chats` 记录。

## 方案

### 1. 什么叫「命中」

「命中」= 一条会叫醒分身、需要本人知道的新消息。只算新到、非本人发送的消息：

| 会话 | 命中 |
| --- | --- |
| 私聊 · `wake_mode=all`（默认） | 对方发来的任意消息 |
| 私聊 · `wake_mode=mention` | 对方 @ 本人（或正文写 @本人名字） |
| 群 · `wake_mode=mention`（默认） | 个人 @ 本人；`@所有人` 不算 |
| 群 · `wake_mode=all` | 任意非本人消息（全量模式本来就会唤醒） |

不算命中：本人自己发的消息、进度卡、`cmd`（本人 @ 自己是给分身的指令，不是客户活动）、
首次基线里的历史消息、群里的非 @ 闲聊。**群里有闲聊但没有点你名，仍算不活跃**——这正是
要退役的那类值守：一直拉、一直不叫醒。

### 2. 时间戳

- `chats[].duty.last_hit_at`（number，epoch 秒）：最近一次命中的消息时间；新字段，追加在
  duty 对象最后。在 `poller.process()` 分类出新消息时按 `msg.ts_epoch` 取最大并夹到当前
  时间；sweep 找到新的个人 @ 时也更新。老数据缺省 0。
- 退役时钟取 `max(last_hit_at, duty.decided_at, chats[].added_at, last_turn.at,
  last_wake_at, session_bound_at)`：没有命中过的新值守从加入 / 判断 / 手动打开时起算，
  不会一加入就被退役。
- 没有以上任何时间（极老数据）时**不退役**，避免拿 0 当 1970 年。

### 3. 退役条件

一条值守同时满足才退役：

1. `watching=true` 且未 `blocked`；
2. `duty.state` 不在 `queued` / `triaging` / `trial` / `reviewing`；
3. 没有待回（`pendingCount == 0`）；
4. 没有在飞 turn / `wake.active` / `progress.state=running`；
5. `now - max(上述时间) >= retire_after_days × 86400`。

待回未处理的不退：那说明值守还有活没干完，静默退掉等于丢消息。试用中的不退：试用有自己的
复核路径，避免两套生命周期抢同一会话。

### 4. 退役动作

新增 `duty.retire(chat, { now, days })`，只做确定性状态迁移：

- `watching=false`、`timer=-1`（群不再进轮询，私聊不再进候选）；
- `duty.state="retired"`、`by="system"`、`decided_at=now`、
  `reason="${days} 天没有新的命中，自动退出值守"`、`review_at=0`、`error=""`；
- `sweep_epoch = max(sweep_epoch, last_epoch)`：退役前的旧 @ 不再翻出来；
- 保留 `target` / `recent` / `dsh_session` / 记忆文件 / 画像；不删 `chats` 行。
- 有残留 `duty.event_id` 时顺手删掉对应决策文件，避免退役后又被旧决策拉回值守。

### 5. 何时跑

`Poller.tick()` 在 `maybeDuty()` 之后、`maybeWarm()` 之前调一次同步的 `maybeRetire()`：

- **不依赖** `dsh.warm_min > 0`、不依赖 DSH 宿主就绪、不调用模型；只扫 state，一次 save；
- 一次 tick 可以退役多个，记一行日志（只记数量，不记聊天名 / 正文）；
- 暂停（`paused`）时不跑，与其它定时维护一致；
- 不放在 `maybeWarm()` 内部，理由见背景：保温窗口覆盖不到 7 天不活跃的会话。

### 6. 退役之后

- **群**：`maybeSweep()` 把 `retired` 也纳入候选，并允许 `added_at <= baseline` 的老群
  （只对 retired 放宽）；新的个人 @ 会重新走一遍分诊，仍受群人数 / 上限 / 每日配额约束。
  不会直接恢复，也不会绕过策略。
- **私聊**：没有 sweep 发现路径，退役后不会自动恢复；用户在面板重新「加入值守」即可。
  这是有意取舍：不为了自动恢复继续拉一个已经判定不活跃的私聊。
- **面板**：会话状态标「已自动退役」并显示 reason；设置页加
  `retire_after_days`（0=关）；「值守中」列表只算 `watching`，退役后自然移出。
- **记录保留**：`duty.cleanupRecords()` 仍只清 `ignore` / `failed`；`retired` 保留，供面板
  解释与后续重新分诊。用户「忘记」会话时才删整行。

### 7. 配置 / 存储 / 接口

- 新配置键 `duty.retire_after_days`：默认 `7`，范围 `0–365`，`0` = 关闭自动退役。
  面板「值守分诊」里可改；同 commit 改 `docs/specs/contracts/03-config.md`。
- `chats[].duty.state` 枚举加 `retired`；`chats[].duty.last_hit_at` 追加在 duty 对象最后；
  同 commit 改 `docs/specs/contracts/02-storage.md`。
- `GET /api/duty` 的 `counts` 加 `retired`；`GET /api/chats` 已原样带 duty，无需新路由；
  同 commit 改 `docs/specs/contracts/01-api.md` 的描述行。
- 兼容：老 state 缺 `last_hit_at` 按 0 补；老代码遇到 `retired` 会按 `none` 归一（0.25.0
  的枚举不含它），最坏是面板少一个标签，不会把会话拉回值守。

### 8. 实施步骤

1. `state.js`：配置键 + 夹取 + duty 枚举 / 字段；`duty.js`：`last_hit_at`、`retired`、
   `retire()`、`activityAt()`、`dutyCounts`。
2. `poller.js`：`process()` 写 `last_hit_at`；`maybeRetire()` 并接进 `tick()`；
   `maybeSweep()` 纳入 retired；sweep 命中写 `last_hit_at`。
3. `panel.js`：设置项、状态标签、说明；跑 `build_client.py`。
4. 三份契约 + `docs/architecture/02-data.md` / `03-runtime.md` 同步。
5. 补测试：退役 / 待回 / 在飞 / trial / 0 关 / 手动重开 / 群 sweep 重判 / last_hit。
6. 跑 `node --test`、`python3 tests/run_tests.py`、`bash scripts/gate.sh --quick`，归档。

## 取舍

| 备选 | 否掉的理由 |
| --- | --- |
| 用 `last_epoch` / 最后一条群消息当活跃 | 群里天天闲聊但从不点你名，会永远不退，解决不了值守越来越多 |
| 塞进 `maybeWarm()` | 保温只覆盖绑定会话的 55–110 分钟闲置窗口，7 天不活跃的会话永远轮不到 |
| 直接删 `chats` 行 | 丢画像、丢会话绑定、丢水位；重新加入要从头来，且无法在面板解释为什么没了 |
| 每会话加「长期值守」开关 | 本期先用全局 `0=关` + 手动重新加入兜底；等真机上确实出现「不该退的重要群」再加，避免一次改太多 |
| 退役前先给用户发通知 | 插件只做确定性搬运，不写日报、不发消息；通知由面板状态与日报 P1 承担 |

## 影响面

- 代码：`dsh-plugin/lib/state.js`、`duty.js`、`poller.js`、`web/panel.js`、`lib/client.js`
- 契约：`01-api.md`、`02-storage.md`、`03-config.md`
- 架构：`docs/architecture/02-data.md`、`03-runtime.md`
- 用户可见：设置页新增退役天数；会话详情新增「已自动退役」；值守列表会随时间变短
- 兼容：老 state 缺字段按 0；`retire_after_days` 缺省 7，升级后第一次 tick 会把已超过
  7 天的存量值守退役（预期行为，用户可在设置里改 0 关闭）

## 验收

- [ ] 7 天无命中的值守 → `watching=false`、`timer=-1`、`duty.state=retired`、reason 含天数；
      再跑一次不重复计数
- [ ] 有待回 / 在飞 turn / `wake.active` / trial → 不退役
- [ ] `duty.retire_after_days=0` → 一个都不退役
- [ ] 新命中把 `duty.last_hit_at` 推到消息时间；7 天从新命中重新起算
- [ ] 手动重新加入 → `duty.state=watch`、`decided_at` 刷新，不会被同一个旧时钟立刻退掉
- [ ] 退役群收到新的个人 @ → `maybeSweep` 重新排队；旧 @（≤`sweep_epoch`）不重复入队
- [ ] 面板设置 7 / 0 可保存；会话详情显示「已自动退役」与原因
- [ ] `node --test`、`python3 tests/run_tests.py`、`bash scripts/gate.sh --quick` 全绿

## 风险与回滚

- 风险：一个很重要的安静群 / 私聊 7 天没说话被退掉，之后来消息没人叫醒。缓解：设置可调 /
  可关；面板显示退役原因；私聊来消息时用户仍能在会话列表看到（只是不自动唤醒），群的新
  个人 @ 会重新分诊。真机观察后再决定是否加「长期值守」白名单。
- 回滚：把 `duty.retire_after_days` 设为 0 立即停止；撤代码后 `retired` 归一成 `none`，
  `watching=false` 保留，不会把会话错误地拉回值守。

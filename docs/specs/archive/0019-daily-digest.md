# 0019 每日关注摘要

> 状态: 已验收
> 编号: 0019
> 版本: 0.9.0
> 关联: `docs/specs/contracts/01-api.md`、`AGENTS.md §设计铁律` 第 8 条

## 背景

值守跑一段时间之后，缺一份「今天哪些事必须我本人出手」的地方可看。

- `/api/inbox` 只回答「有什么没回」：没有优先级，不区分「还没轮到」和「agent 看过了、拿不准」，
  也没有跨天欠账的读数（等 2 小时和等 18 小时长一个样）。
- **体检页管的是通路，不是判断**：它回答「CLI 通不通、宿主在不在、上一轮 turn 成没成」。
  agent 这一轮看到了什么、拿不准什么、哪条没敢回，没有任何地方沉淀；过一夜就只剩
  `chat.last_turn` 一个槽位。
- skill 形态没有面板：值守完一天，用户没有任何东西可以回看。

插件的确定性边界止于「发现消息 → 唤醒 agent」。唤醒之后发生什么——回不回、怎么归并、日报写成
什么样——插件不参与、不记录、不推断。所以这份摘要**完全由 agent 按 `SKILL.md` 在自己的会话里
维护**，插件只把它当普通文件原样读给面板看（`AGENTS.md §设计铁律` 第 8 条；先例是 spec 0018 的画像）。

## 目标与非目标

- 目标：值守的每个唤醒 turn 顺手把「需要人出手」的事收敛成一份本地日摘要，面板能看、隔几天还在、
  同一个人不会裂成好几行。
- 非目标：
  - 插件不参与摘要：不建目录、不写内容、不删文件、不解析、不统计、不记录 turn 结果。
  - 不新增配置键；不改 `state.json` 结构。
  - 不记录插件侧的失败（whoami 失败、turn 超时）——那是体检页的事，不进日报。
  - 不做推送（飞书/企微/邮件/桌面通知都不发）。
  - 不做周报/月报，不做移动端。
  - 面板不做富文本渲染，只显示原文（格式跑偏时宁可难看，也不要看起来像坏了）。

## 方案

### 职责切分

| 谁 | 做什么 | 不做什么 |
| --- | --- | --- |
| 插件 | `GET /api/digest` 原样读文件；面板显示原文与 mtime | 建目录、写、删、解析、统计、记 turn 结果、判断哪条该关注 |
| agent | 建 `digest/` 目录；读最近一份 → 合并本轮结论 → 覆盖写今天这份；顺手删 90 天前的 | 写 `state.json` / `env.json` / `media/` |

插件这边只有一次读盘，没有第二个写者。

### 产物

```
~/.im-standin/digest/YYYY-MM-DD.md    目录 0700、文件 0600；日期取本机本地时区；由 agent 创建与维护
```

一份文件就是一天。**整份覆盖写，不 append**——这是本 spec 唯一不能退让的约束。

### 整理规则（`SKILL.md` 的协议，agent 执行）

按重要性排：

1. **一个会话在待办区最多一行。** 同一对象不会因为发生多件事而多出几行；新的比旧的严重，
   就替换那一行并更新读数。这条是防裂化的根。
2. **分区按「人要不要动」分，不按时间流分。** 固定四段，顺序不变：

   | 分区 | 判据 | 人该做什么 |
   | --- | --- | --- |
   | P0 系统异常 | agent 自己调 CLI 时发现身份失效、CLI 不可用、发不出去 | 去修登录/环境，不修就静默失效 |
   | P1 等你拍板 | agent 看过了但没回（拿不准、越权、要决策）、这一轮代发失败 | 给个判断，或自己回 |
   | P2 在等回复 | 有 `dm` / `mention` 待回，且最老一条已等超过 4 小时 | 回复或指派 |

   > 插件侧的同类问题（whoami 失败、turn 超时）看体检页，不进日报——agent 没被唤醒时根本没人在
   > 跑，也就不该有 agent 写的记录。

3. **问题消失，行就消失。** 该会话 `recent` 里没有 `new` / `opened` 了，就从待办区删掉；
   只有**本轮确实处理过**的（自己回了、用户说知道了）才进「今日已处理」。
4. **跨天靠读上一份，不靠抄行。** 今天第一次写时，读最近一份（今天 → 昨天 → 更早），把仍在
   P1/P2 的项原样带过来，`首次` 保留原日期，`最近` 保持原值——等待时长由读者按这两个时间自己看。
5. **只写事实，不写断言。** 事由是一句 ≤40 字的概括（对方要什么/卡在哪），禁止粘贴原文、
   不写「应该回…」这类建议。
6. **只记自己亲历的失败。** CLI 报错、发送失败、身份失效是 agent 这一轮亲眼看到的，可以写；
   DSH 层面的 turn 超时、进程重启不在 agent 视野里，不猜、不补。

行格式（固定，字段少）：

```
- [P1] 示例对象A · 飞书私聊 · 问报价能否下周交 · 首次 11-03 10:20 · 最近 13:05 · 待回 2
- [P2] 客户C · 企业微信私聊 · 在等回复 · 首次 11-01 21:10 · 最近 11-01 21:10 · 待回 3
- [P0] 飞书 · 身份失效 · 首次 11-02 09:12 · 最近 13:40
```

- 对象用会话展示名；群标「飞书群」；P0 没有会话，写平台名。
- 「待回」是该会话 `recent` 里 `new` / `opened` 的条数，写不下可省。
- 不带 `msg_id`：正文本来就不落，要看原文点开面板对应会话即可，少记一个字段就少一处漂移。

模板：

```markdown
# 2026-11-03 · 今日关注

> agent 整理；覆盖写，不是日志。最新更新 14:30。

## P0 · 系统异常（不处理会静默失效）
- [P0] 飞书 · 身份失效 · 首次 11-02 09:12 · 最近 13:40

## P1 · 等你拍板
- [P1] 示例对象A · 飞书私聊 · 问报价能否下周交 · 首次 11-03 10:20 · 最近 13:05 · 待回 2

## P2 · 在等回复（超过 4 小时）
- [P2] 客户C · 企业微信私聊 · 在等回复 · 首次 11-01 21:10 · 最近 11-01 21:10 · 待回 3

## 今日已处理
- 14:30 客户D · 已回复
```

- 空分区不渲染标题；全空写 `今天没有需要你处理的。`。
- 单份超过 60 行就该归并了——那是「有人在叮你」，不是「需要你关注」。

### 一次更新的完整动作（agent）

```
1. 读最近一份日报 → 解析成「会话 → 行」的 map（一个会话只保留一行）
2. 读本轮载荷：新消息、会话
3. 对载荷里出现的每个会话：
     本轮已回复 / 用户说知道了 → 移到「今日已处理」，从 map 删掉
     recent 里已无 new/opened      → 从 map 删掉
     仍有待回且没回                → 更新事由/最近/待回数，按判据定分区
4. 上一份里本轮没出现的会话：原样保留（含首次日期）
5. 本轮自己遇到的 CLI 报错 / 身份失效 / 发送失败：在 P0/P1 增删对应行
6. 整份写回 ~/.im-standin/digest/<今天>.md（覆盖）
```

复核成本有上限：每轮最多用平台 CLI 复核 **3 条**最老的 P1/P2 项（看该会话最后一条是不是本人发的），
超出就按上一次记录的结论保留。这条是为了不让「整理日报」变成每轮几十次 CLI 调用。

### 插件侧（只读展示）

`GET /api/digest?date=YYYY-MM-DD`，默认今天：

| 情况 | 返回 |
| --- | --- |
| 文件存在 | `{ok: true, date, exists: true, text, mtime}` |
| 文件或目录不存在 | `{ok: true, date, exists: false, text: "", mtime: 0}` |
| `date` 不是 `YYYY-MM-DD` | `{ok: false, reason: "bad_date"}` |

日期只接受严格格式，拼出的绝对路径必须仍在 `digest/` 目录内（防 `..` 穿越）。只读，不创建文件。

### 面板

「关注」页签，排在「收件箱」之后，内容就是文件原文：

- 顶部：日期选择（默认今天）+ 「最后更新 14:30」。
- 正文：等宽文本，保留缩进；**不解析 markdown**。
- 空态：`今天还没有日报` + 一句「agent 会在下次被唤醒时写；现在没人找你就是没人在等」。
- 陈旧提示：文件 `mtime` 超过 24 小时，顶部加一行 `最后更新于 X 小时前`（黄色），不报警不推送。
- 不显示角标：数字在文件里，插件不解析。

### 与铁律的关系

| 铁律 | 结论 |
| --- | --- |
| 8 插件只做确定性搬运 | 本 spec 是它的第一个落地：插件对日报只有一次只读 |
| 不监听端口 | 不触碰：读文件 + 现有同源路由 |
| 消息正文只在本机 | 事由是概括不是原文；文件在 `~/.im-standin/` 内，不上传、不进日志 |
| 零第三方依赖 | 只用 `node:fs` / `node:path` |
| 迁移只放宽 | 不碰 `state.json`，不新增配置键，升级无行为变化 |

## 取舍

| 备选 | 否掉的理由 |
| --- | --- |
| 插件维护 `state.json.attention[]` + 派生 + 收敛 | 判断逻辑在 Node 里长一遍、prompt 里再长一遍，两边不一致；违反铁律 8 |
| 插件在唤醒载荷里塞日报路径 | 路径由本地日期就能推出来，塞进载荷等于让插件参与摘要；`SKILL.md` 写死约定即可 |
| 插件建目录 / 定时清理旧日报 | agent 是唯一的写者，目录生命周期归它；插件只读不写 |
| 每件事 append 一行 | 同一个人一天能出十几行，第二天没人看；问题解决了行还在 |
| 插件解析日报做角标/统计 | 格式一变就坏；原文显示坏了只是难看，解析坏了是误导 |
| 每天 0 点定时生成 | 没人唤醒时没有 agent 在跑，生成出来的也只是一份空壳 |
| 推飞书多维表格 / 飞书任务 | 要往 `~/.im-standin/` 之外写数据、推对象名；本次不做 |
| 独立开源看板（Grafana / Focalboard 等） | 都要新起服务与端口，违反 `docs/decisions/implemented/0001-zero-port.md` |

## 验收

- [x] `GET /api/digest` 无参返回 `exists` 与 `text`；`date=2026-11-02` 读对应文件；
      `date=../../etc/passwd` 与 `date=2026-13-99` 都返回 `bad_date`，读不到目录外文件。
- [x] 目录不存在时返回 `exists:false` 且**不创建**目录（`ls ~/.im-standin/` 前后一致）。
- [x] 手工放一份示例日报到 `~/.im-standin/digest/<今天>.md`，面板「关注」页签显示原文与「最后更新」；
      删掉文件刷新，显示空态文案。实测 3080（合成状态目录）：关注页显示原文与
      「最后更新 15:19」；移走文件后显示「今天还没有日报。agent 会在下次被唤醒时写…」。
- [x] 让真实 agent 按 `SKILL.md §值守日报` 连着更新同一份两次：第二次没有新增重复行，
      已处理的项移出待办区；同一会话始终只有一行（人工核对）。实测合成会话连续两轮
      live turn（15:22 / 15:25）：同一对象始终一行，第二轮改写了该行，没有追加重复记录。
- [x] 跨天演练：把今天的文件改名成昨天，构造一条未结项，再跑一次更新——该项被带过来且
      `首次` 仍是昨天日期。实测把未结项放进 `2026-11-02.md`、删掉今天文件后唤醒 agent：
      今天的文件带回该行，`首次 2026-11-02 09:00` 未被改写。
- [x] 本次改动只碰 `lib/app.js` 与 `web/panel.js`；`lib/state.js` / `lib/turns.js` /
      `lib/poller.js` / `lib/index.js` 未动；`python3 tests/test_docs.py` 的「契约 02 / 03」仍全绿。
- [x] `bash scripts/gate.sh --quick` 全绿。

## 风险与回滚

- 风险 1：agent 忘了更新，日报一直停在昨天的 mtime。缓解：面板显示「最后更新于 X 小时前」；
  `SKILL.md` 把它列进每轮收尾动作。
- 风险 2：agent 写歪格式（多出重复行、分区乱序）。面板只显示原文，坏格式不影响值守；
  协议里给了固定模板与「一个会话一行」的硬规则，验收里有连续两次更新的演练。
- 风险 3：`digest/` 越积越多。agent 在写的时候顺手删 90 天前的；即使不删，每天几 KB 也不影响。
- 风险 4：`dsh.full_access=false` 时会话写不进 `~/.im-standin/`。缓解：与画像同一条已知边界，
  agent 要如实告诉用户，不假装写了。
- 回滚：撤掉本 spec 对应 commit 即可——没有 `state.json` 结构变化、没有配置键，不需要迁移或清理；
  已生成的 `digest/*.md` 留在本机，删不删由用户定。

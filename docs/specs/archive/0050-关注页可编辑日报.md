# 0050 关注页可直接编辑日报

> 状态: 已验收
> 编号: 0050
> 版本: 0.23.0
> 关联: `docs/specs/contracts/01-api.md`、`docs/specs/archive/0019-daily-digest.md`、`docs/specs/archive/0033-关注页日报即时渲染.md`

## 背景

「关注」页签把 `~/.im-standin/digest/YYYY-MM-DD.md` 原文摊开给用户看（spec 0019），
但只能看不能改。会话工作本和人物档案都能在「服务对象」里直接编辑，唯独这份每天最常看的
清单不行；用户想把某一项删掉、补一句自己的判断或改个措辞，只能去终端开文件，体感断裂。

现状的约束都还在：日报由 agent 按 `SKILL.md §值守日报` 维护，整份覆盖写、一个会话一行；
面板的 3 秒静默刷新会不断重取文件（spec 0033），编辑时不能被它打断或覆盖。

## 目标与非目标

- 目标：在「关注」页点一下就能改当天或任意历史日期的日报，保存后立即显示；agent 下一轮
  整理时以用户改过的版本为底稿，不整份抹掉用户手写内容。
- 非目标：
  - 不做结构化表单、不解析分区与行格式，仍按纯文本整份编辑（铁律 8）。
  - 不新增配置键，不改 `state.json`，不新增端口 / 页面 / 富文本编辑器。
  - 不做版本历史、撤销、自动保存；冲突时让用户明确选「覆盖」或「重新载入」。
  - 不替用户决定日报内容，也不在插件里生成日报正文。

## 方案

### 1. 写接口 `POST /api/digest`

与现有 `GET /api/digest` 同路径（`App.digest` 读、`App.digestWrite` 写），日期校验共用
一个 helper：严格 `YYYY-MM-DD` + 日历合法 + 拼出的绝对路径仍在 `digest/` 内。

入参：

| 键 | 必填 | 说明 |
| --- | --- | --- |
| `date` | 否 | `YYYY-MM-DD`，缺省今天；非法回 `{ok:false, reason:"bad_date"}` |
| `text` | 是 | 整份覆盖写；必须是字符串 |
| `base_mtime` | 否 | 面板加载时的 mtime（秒，还没有文件时是 0）。带了这个键且磁盘 mtime 与它不一致（含 agent 新建 / 删除）→ `{ok:false, reason:"stale"}`，不写；完全省略才视为显式覆盖 |

- 上限 `256 KiB`（按 UTF-8 字节）：超过回 `{ok:false, reason:"日报超过 256KB"}`，拒绝不截断。
- `text.trim()` 为空 = 清空这一天：删除文件（删不掉容忍），返回 `exists:false`。
  空态比一份空文件更诚实，也让「今天还没有日报」的文案重新成立。
- 非空：目录按需创建（700），临时文件 + rename（600），成功后回与 GET 同形的
  `{ok:true, date, exists:true, text, mtime, truncated:false}`；`mtime` 用秒（与 GET 一致）。
- 面板每次都带 `base_mtime`：还没有文件时是 `0`；若用户编辑期间 agent 新建了文件，`0` 与磁盘不一致，同样回 `stale`。只有完全省略该键的调用方才是显式覆盖。
- 写入是用户显式点「保存」才发生；GET 仍然不建目录、不写盘。

### 2. GET 增加 `truncated`

文件超过 256 KiB 时 GET 本来就会截断并追加「（过长，已截断）」。截断后的文本不能拿来
编辑（保存会把截断内容写回、毁掉后半段），因此 GET 增加布尔字段 `truncated`；面板见到
`true` 就不给「编辑」按钮，并说明原因。GET 其余字段不变，仍不建目录、不写盘。

`mtime` 从整秒改为精确秒（带小数）：面板拿整秒去回写，会和分秒级的真实 mtime 比对出
假 `stale`；展示层仍按秒格式化，对用户无感。

### 3. 面板编辑态（`web/panel.js`）

- 关注页顶部日期行右侧加「编辑」；空态（这一天没有日报）也能点，进入空白编辑。
  `bad_date`、读取失败、`truncated=true` 时不显示编辑入口。
- 编辑态替换整页内容：
  - 顶行「编辑 YYYY-MM-DD 日报」+「保存」+「取消」；
  - 等宽 `textarea` 占满剩余高度，不用富文本，不解析 markdown；
  - 底部字节计数（超 256 KiB 禁用保存）与一句「整份覆盖写；agent 下一轮会以这份为底稿」。
- 编辑期间冻结本页的静默刷新（3 秒 tick 与 60 秒 tick 都跳过），避免磁盘新内容在输入时
  悄悄替换 `S.digest`；切到别的页签再回来，未保存草稿仍在，和人物档案 / 工作本的编辑行为一致。
- 保存成功：用接口回包更新 `S.digest` 与模块级缓存、退出编辑、提示「已保存 / 已清空这一天的日报」。
- `stale`（agent 刚写过）：**不丢用户草稿**。后台取一次最新版，保留 textarea 内容，顶部出现
  冲突条：「agent 刚更新过这份日报；再点一次保存会覆盖它」，旁边给「重新载入最新」。
  第二次点保存才用最新 mtime 覆盖，等于一次显式确认；再冲突就再次更新冲突条。
- `Esc` 取消编辑（先于退回会话列表）。日期选择器在编辑态不渲染，避免切日期丢草稿。
- 编辑态不影响其他页签；未保存内容只在浏览器内存里。

### 4. agent 侧协议

`SKILL.md §值守日报` 补一句：用户可能直接在面板里改这份文件。更新时先把当前文件读成底稿，
只改本轮有明确证据的项；用户加的行 / 改写的措辞原样保留，用户删掉的行不要凭旧记忆补回来。
插件不判断「哪行是谁写的」，这个约定靠 agent 的读取顺序与克制重写来成立。

## 取舍

| 备选 | 否掉的理由 |
| --- | --- |
| 只读展示，让用户去终端改 | 用户明确要求面板内直接改；与工作本 / 人物档案的编辑入口不一致 |
| 编辑器只允许追加「用户备注」 | 用户要的是「直接改动」：删行、改措辞都算；另开字段还会让 agent 多读一份 |
| 结构化表单（逐条增删） | 要解析分区与行格式，格式一漂就坏；违反铁律 8，且日报格式是 agent 的协议不是插件契约 |
| 编辑期间继续 3 秒静默刷新 | 输入到一半被磁盘新内容替换，轻则跳光标，重则覆盖用户草稿 |
| `stale` 直接丢弃草稿并重载 | 现有工作本保存没有冲突检测，人物档案的 `stale` 会丢草稿；日报更常被 agent 写，用户长文丢失代价更高 |
| 后端用版本号 / ETag 做并发控制 | 一个本机文件 + 单用户，mtime 已够；多一个契约要维护 |
| 保存空内容写成空文件 | 空文件会让面板显示「存在但空白」，与「没有日报」的语义混在一起；删除更干净 |

## 验收

- [x] `POST /api/digest` 写入后 `GET` 读到同一份文本；文件 600、目录 700、不留 `.tmp`。
- [x] `text` 为空白 → 文件被删、GET `exists:false`；目录不存在时 POST 不报错并创建目录。
- [x] 日期 `2026-13-99` / `../../etc/passwd` → `bad_date`，目录外文件不变。
- [x] 先 GET 拿 `mtime`，用 `fs.utimes` 把文件 mtime 推到更晚，再带旧 `base_mtime` POST →

- [x] 空态加载（`base_mtime=0`）后 agent 新建文件、或加载后文件被删 → 都回 `stale`，
      不静默覆盖 / 不凭旧内容复活；完全省略 `base_mtime` 才直接覆盖。
- [x] `text` 超过 256 KiB → 拒绝且不截断、不落盘。
- [x] 文件超过 256 KiB 时 GET `truncated:true`；面板不出现「编辑」。

- [x] 面板：空态点「编辑」写一段再保存 → 从空态变成正文；再清空保存 → 回到空态。
- [x] 面板：编辑中按 Esc / 点「取消」→ 草稿丢弃、回到只读正文；切页签再回来草稿仍在。

## 风险与回滚

- 风险 1：agent 下一轮整份重写，用户手改仍可能被抹掉。缓解：`SKILL.md` 明确「当前文件是底稿、
  不补回用户删掉的行」；冲突检测保证面板保存不覆盖 agent 刚写的内容，反向只能靠协议。
- 风险 2：用户清空保存误删当天日报。文件在 `~/.im-standin/digest/`，agent 下一轮会重建；
  编辑器底部明确写着「留空保存 = 删掉这一天」。若后续觉得危险，可改成「空内容拒绝」再加二次确认。
- 风险 3：`textarea` 编辑大文件卡顿。上限 256 KiB 且超限拒绝编辑；日报正常只有几 KB。
- 回滚：撤掉本 spec 对应 commit 即可；不涉及 `state.json`、配置键或迁移。已编辑的日报文件
  留在本机，删不删由用户定；`GET` 的 `truncated` 字段是纯增量，老面板忽略即可。

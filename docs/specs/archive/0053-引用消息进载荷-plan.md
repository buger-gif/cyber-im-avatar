# 0053 引用消息进载荷 — 实施计划

> 关联 spec：`docs/specs/archive/0053-引用消息进载荷.md`

## 步骤

1. **spec 与契约**：新增本 spec / plan，`docs/specs/README.md` 下一个号 0053 → 0054；
   契约 02 的 `recent` 表追加 `reply_to` / `quote`，契约 01 的 `/api/thread` 行补 `quote`。
   验证：`python3 tests/test_docs.py`（先会红，随代码一起绿）。

2. **适配层**：`lib/im.js` 飞书配置加 `f_reply_to` / `cmd_mget_quote`；`norm()` 带
   `reply_to`；新增 `resolveQuotes(messages, {since})`（本批命中、since 过滤、缓存、
   mget 批量与失败降级）。
   验证：`node --test tests/im.test.mjs`（reply_to 归一化；本批命中不 spawn；
   老消息 mget 一次、逗号分隔；缓存不重复；单个失效不拖累、失败不抛）。

3. **存储层**：`lib/state.js` 的 `normalizeMessage` 追加 `reply_to` / `quote`；
   `normalizeQuote` 只留六个字段；三处清正文时同时清 `quote`；`mergeRecent` 只补空。
   验证：`node --test tests/state.test.mjs`、`python3 tests/test_docs.py`。

4. **轮询接线**：`lib/poller.js` 的 `pollChat` 在 `process` 前用水位调
   `resolveQuotes`；`fetchThread` 对在线拉到的消息也补引用；`commandRow` 带上两字段；
   适配器没有 `resolveQuotes` 时静默跳过。
   验证：`node --test tests/poller.test.mjs`（新回复带 quote 进批次、老消息不重复 mget、
   取不到不阻断、命令行带 quote）。

5. **载荷格式**：`lib/turns.js` 的 `formatMsgLine` 追加缩进引用行；本批有引用时加一行
   格式说明；媒体引用给标记 + msg_id；取不到写「原消息取不到」；`sanitizeUntrusted`、
   单行、300 字截断。
   验证：`node --test tests/turns.test.mjs`（私聊 / 群、本人引用标「我」、媒体、
   取不到、超长、无引用逐字节不变）。

6. **面板**：`web/panel.js` 的消息气泡显示引用行，加 `.ims-quote` 样式；
   `python3 scripts/build_client.py` 重建 `lib/client.js`。
   验证：`node --test tests/app.test.mjs`、构建产物新鲜度（`tests/test_docs.py`）。

7. **文档**：根 `SKILL.md` 补引用行说明；`references/feishu.md` 记录 `reply_to` +
   `+messages-mget` 实测；`references/{wecom,dingtalk}.md` 写明未实测、不猜；
   `docs/architecture/03-runtime.md` 加一句载荷行为；`CHANGELOG.md` 未发布小节。
   验证：`python3 scripts/verify_docs.py`、`bash scripts/gate.sh --quick`。

8. **真机与收尾**：用测试私聊回复一条更早消息并 @自己，确认载荷出现 `↪ 引用`；
   删掉被引用消息再试一次，确认写「取不到」且轮询不报错；`PROGRESS.md` 更新断点，
   当日 log 记录读数；验收对勾后归档 spec。

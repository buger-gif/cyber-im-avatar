# 0058 分身值守筛选

> 状态: 实施中
> 编号: 0058
> 版本: 0.26.0
> 关联: 无（纯前端派生，不改 `docs/specs/contracts/` 的任何形状）

## 背景

0054 给「服务对象」的群聊 / 人物两段加了名称搜索、状态 chips、平台下拉与 facet 计数，
当时明确把「分身」的值守列表留在非目标里。2026-11-24 用户看面板「分身 · 值守中 26」，
说「这里也加个和服务对象一样的筛选吧」：26 个值守会话（18 群 + 8 私聊）整列铺开，
找一通正在处理的、上轮失败的或还有待回的，只能一路往下滚。

后端数据已经够用：`/api/chats` 每行带 `platform` / `name` / `kind` / `turn_state` /
`last_ok` / `pending`，这页本来就只列 `watching && !blocked`；过滤可以完全在客户端做。

## 目标与非目标

- 目标：「值守中」列表能按名称搜、按实例状态与平台筛，命中数实时可见；不改轮询、唤醒、
  值守范围，也不改卡片里任何既有操作。
- 非目标：
  - 不在这套 chips 里加更多维度（群 / 私聊、发送方式、工作区）——这次只跟 0054 对齐；
  - 不搜待回正文，不做拼音 / 模糊匹配 / 服务端搜索 / 分页，不动现有排序；
  - 不把筛选写进 `state.json` / localStorage；
  - 不把「已屏蔽」「未值守」的会话放进这一页（它们仍在设置与「服务对象」里）。

## 方案

### 1. 位置与状态

- `S.dutyFilter = { q, kind, platform }` 与 `targetFilter` / `personFilter` 并列，纯内存；
  面板刷新或重挂载回到「全部」。
- 控件放进「值守中」这张卡片：搜索框一行，状态 chips + 平台下拉一行；直接复用 0054 的
  `filterBar` / `filterEmpty` / `listCountText`，不复制样式与搜索语义。
- 搜索语义沿用 0054：trim 后按空白拆词、全部命中才算命中、ASCII 大小写不敏感、输入即筛、
  Esc 只清搜索词并 `stopPropagation`；只匹配展示名，不匹配 `chat_id`。

### 2. 状态判定与计数

| chip | 判定 |
| --- | --- |
| 全部 | 不加状态条件 |
| 处理中 | `turn_state === "running"` |
| 上轮失败 | `last_ok === false` 且 `turn_state` 不是 `running` / `warm`（与卡片标签同一优先级） |
| 待回 | `pending > 0` |

- 平台下拉只在值守列表出现 ≥2 个平台时出现，选项只取现存平台。
- chips 上显示**当前搜索 + 平台**条件下的 facet 计数；点击只切状态，不重置搜索与平台。
- 卡片头显示 `· 26 个会话` / `· 命中 5 / 26 个会话`；整列为空沿用原文案且不显示控件；
  筛空时给「清空搜索与筛选」一次复位 q / kind / platform。

### 3. 渲染方式

- 卡片照旧由 `watched.forEach` 建一次，放进 `cardOf`（键 `platform:chat_id`）；
  `apply()` 只按条件把这些节点挂进列表容器——隐藏的行不重建 DOM、不重跑事件绑定。
- 筛选变化不重建整页，输入焦点与光标不跳；后台刷新仍走 `paintBody()` 的 `typingFocus()`
  保护，正在打字时不会把输入框换掉。

## 影响面

- 代码：`dsh-plugin/web/panel.js`（唯一事实源）、重建 `dsh-plugin/lib/client.js`。
- 契约：无；无新路由、无 state 字段、无配置键。
- 用户可见：分身页「值守中」多出搜索框、状态 chips 与平台下拉；其余页签不变。
- 兼容：刷新面板即生效；无数据迁移，回滚只回代码。

## 风险与回滚

- 风险：低。筛选只在内存里派生，后端、轮询与唤醒不受影响；最坏是筛空了，点
  「清空搜索与筛选」即复位。
- 回滚：撤 `web/panel.js` + `lib/client.js` 两个文件，无数据需要清。

# 0054 服务对象筛选与搜索

> 状态: 实施中
> 编号: 0054
> 版本: 0.25.0
> 关联: 无（纯前端，不改 `docs/specs/contracts/` 的任何形状）

## 背景

2026-11-23 用户实测：面板「服务对象」已有 34 个群工作本、41 份人物档案。两段都是整页铺开
的长列表，找一个对象只能滚动；用户明确说「列表太多、可能看不完」，并预判服务对象会继续增加。

后端现状够用：`GET /api/targets` 与 `GET /api/persons` 已经一次返回全部行，行上带展示名、
`platform`、`profile_excerpt` 与人物 `chat_ids`；面板 `/api/chats` 也已有 `kind` / `watching` /
`blocked`。因此过滤可以完全在客户端做，不需要新路由、state 字段或配置键。

## 目标与非目标

- 目标：在「服务对象」两段里按名称搜索，并按关注状态 / 是否有内容 / 平台筛选；
  命中数实时可见；不改变后端数据、轮询与唤醒行为。
- 非目标：
  - 不搜工作本 / 档案正文——模板标题与说明每行都有，正文搜索会把所有行都打出来；
  - 不做拼音、模糊匹配、服务端搜索或分页；不动现有排序；
  - 不把筛选写进 `state.json` / localStorage；不改「分身」值守列表（这次只处理用户点名的两段）。

## 方案

### 1. 状态与位置

- 两段各维护一份**内存**过滤条件：`targetFilter` / `personFilter = { q, kind, platform }`。
  互不共享，切段不串味；面板刷新或重挂载回到「全部」。
- 控件都放在该段头部卡片里：搜索框一行，状态 chips + 平台下拉一行。
- 平台下拉只在**该段真实出现过 ≥2 个平台**时出现，避免单平台用户多一个无效控件。

### 2. 搜索语义

- `trim` 后按空白拆词，**全部命中**才算命中（`云雀 交付` 能搜到「云雀项目 · 交付群」）。
- 只匹配展示名；ASCII 大小写不敏感。不匹配 `chat_id` / `person_id` / 正文——
  界面上不出现内部 ID，搜索也不该成为读 ID 的入口。
- 输入即筛：只重建行容器与计数，不整页重绘，输入焦点与光标不跳。
- 搜索框里 Esc 只清搜索词并 `stopPropagation`，不触发全局「返回列表 / 取消编辑」。

### 3. 筛选与计数

| 段 | chips（互斥） | 判定 |
| --- | --- | --- |
| 群聊 | 全部 / 值守中 / 未写工作本 | 值守中 = `chat.watching && !chat.blocked`；未写 = `profile_excerpt` 去空白为空 |
| 人物 | 全部 / 未写档案 / 有私聊 | 未写 = `profile_excerpt` 去空白为空；有私聊 = 在 `/api/chats` 里至少出现在一个 `kind=p2p` 会话 |

- 平台下拉：`全部平台 / 飞书 / 企业微信 / 钉钉`，选项只取该段出现过的平台。
- 状态 chips 上显示**当前搜索 + 平台**条件下的 facet 计数（`值守中 · 12`），
  点击只切状态，不重置搜索与平台。
- 段头显示 `命中 N / 总 M`；分段条上的「群聊 · 34 / 人物 · 41」仍显示总数，不随筛选变。
- 搜索框旁「清空」只清搜索词；无命中时给「清空搜索与筛选」按钮，一次清掉 q / kind / platform。
  状态 chips 带 title 说明各自只看什么（如「只看还在值守、且没有被屏蔽的会话」）。
- 整段本身为空时沿用原文案，不显示搜索与筛选控件；加载失败仍走顶部连接错误条。

### 4. 不改的东西

- 无新路由、无 state 字段、无配置键、无契约变更；筛选纯派生，不写盘。
- 编辑态草稿仍在 `targetDrafts` / `personDrafts`；筛选变化不删除草稿，
  清空筛选后原样回到编辑态。

## 影响面

- 代码：`dsh-plugin/web/panel.js`（唯一事实源）、重新构建 `dsh-plugin/lib/client.js`；
  `loadChats` / 进入「服务对象」时补一次 chats，保证「有私聊」判断有数据。
- 契约：无。
- 用户可见：服务对象两段多出搜索框、状态 chips 与平台下拉；其余页签不变。
- 兼容：刷新面板即生效；无数据迁移，回滚只回代码。

## 风险与回滚

- **风险：只按名称搜，找不到「正文里写过」的对象。** 这次明确不做正文搜索；先用状态筛选与
  滚动兜底。将来要做，得先解决模板文案噪声，另起 spec。
- **风险：筛掉正在编辑的行。** 草稿不删，清空筛选即回到编辑态；编辑期间也能看到行被留下的原因。
- **回滚**：纯前端一个提交；revert 后面板回到旧列表，无数据影响。

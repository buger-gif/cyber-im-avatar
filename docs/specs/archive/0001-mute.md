# 0001 屏蔽群 / 屏蔽单聊

> 状态: 已验收
> 编号: 0001
> 版本: 0.5.0
> 关联: `docs/specs/contracts/02-storage.md`、`docs/specs/contracts/01-api.md`

## 背景

收件箱按会话聚合之后，「不想看」的会话仍然占着位置：机器人告警群、几百人的大群、
已经交接出去的对口人。这些会话的问题不是显示，是**还在被同步**——每轮轮询都在花接口调用，
进去之后还会把历史灌进 `messages`，收件箱与角标被它们撑着。

用户诉求原话：「增加屏蔽群 屏蔽单聊消息的功能 屏蔽的不同步消息」。

关键是后半句：屏蔽必须等于**不同步**，而不是仅仅在 UI 里藏起来。只藏不拉是假屏蔽——
配额照样在烧，只是看不见。

## 目标与非目标

- 目标：一条命令让某个群或某个人彻底退出同步，且随时能取消、历史不丢。
- 非目标：不做「只屏蔽通知但继续同步」（那需要另一套语义）；不做按关键词过滤（误伤成本高，
  且判断该由人做）。

## 方案

**数据**：`chats` 加两列 `blocked`（0/1）、`blocked_at`（时刻）。存量一律 0，升级不改行为。

**一处收口**：定时轮、点开补拉、手动单会话三条路径全部汇合在 `poller.poll_chat()`，
只在那里判 `blocked`——分散判断迟早会漏一个入口。`poll_targets()` 另在选目标时整行过滤，
省掉无用调用，但**不是**唯一防线。

**收件箱与计数**：`_inbox_filter()` 拼 `blocked=0` 条件，聚合与逐条两种模式共用；
`counts()` 同样排除。屏蔽那一刻把该会话 `state in (new, opened)` 的消息标 `ignored`，
否则角标一直红着却点不出东西。

**接口**：`POST /api/chat/block` `{platform, chat_id, blocked}` → `{ok, chat, counts, poll}`。
`/api/chats` 回传 `blocked`，`timed` 对屏蔽会话恒 false；`poll_info()` 加
`blocked` / `blocked_dm` / `blocked_group`。

**入口**：收件箱行右侧小铃铛、会话详情头部「屏蔽 / 取消屏蔽」、客服页群卡片与私聊卡片、
「客服 → 已屏蔽」区块统一放回。屏蔽时详情头部与顶部各给一条提示：历史只有屏蔽前的。

**副作用修正**：体检的探针会话不再挑屏蔽的——那条路本来就不拉，拿它测通路只会误报。

## 取舍

| 备选 | 否掉的理由 |
| --- | --- |
| 直接删会话数据 | 不可逆。屏蔽是「先别看」，不是「销毁」，取消屏蔽后历史还得在 |
| 只在 UI 过滤 | 假屏蔽：接口照打、配额照烧 |
| 加「静音」和「屏蔽」两档 | 当前没有「要同步但不要提醒」的真实场景，多一档就多一处 UI 与一处判断 |
| 每条拉取路径各自判 blocked | 漏一处就等于没做，收口在 `poll_chat` 只有一处可漏 |

## 风险与回滚

- 风险：屏蔽的会话若同时勾着「定时检测 @我」，用户可能以为还在盯——所以 UI 上屏蔽优先于定时，
  且客服页会把屏蔽会话移出群列表、放进「已屏蔽」区块。
- 回滚：`POST /api/chat/block {blocked:false}` 或删 `chats.blocked` 条件；
  数据层不删任何东西，回滚不需要迁移。

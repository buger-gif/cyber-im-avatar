# 0061 进度卡等待期与群聊

> 状态: 实施中
> 编号: 0061
> 版本: 0.26.0
> 关联: `docs/specs/contracts/01-api.md` / `02-storage.md` / `03-config.md`；ADR 0020

## 背景

spec 0052 的进度卡按 DSH turn 结束：只要 turn 成功就 patch「处理完成」，之后 agent 在本地
做画像 / 记忆归并，计数还会继续涨、卡片还会继续动。卡片发给目标 IM，目标不关心 DSH 会话
是否完成，只关心「有没有给我发消息」。另外 0052 只支持飞书私聊，群值守在面板里没有开关。

2026-11-24 实测运行版 DSH 的 `session/event`：`tool/call.data` 带 `turn`、`callId`、`name`、
`arguments`，其中 `arguments` 是模型原始 JSON 字符串。直接看 shell 类工具的 `command` 就能
在发信那一刻收口，不必等 turn 结束，也不必加轮询频率。

## 目标与非目标

- 目标：目标收到本人消息的那一刻，撤回当前进度卡；没看到发信才按最终 turn 结束兜底。
  中间计数 / `[进度]` 刷新不变。
- 目标：同一会话多条指令 / 用户连续打断时，按「等待期」续同一张卡；发信或最终 turn 结束
  才收口。新指令在发信后重新从 0 计 2 分钟。
- 目标：飞书群聊也支持进度卡，设置页加全局开关，会话详情可按群三态覆盖；默认关。
- 非目标：不新增端口、不新增拉取频率、不引入第三方运行时依赖、不读消息正文以外的工具参数
  或结果、不做卡片内容解析、不改 bot 身份。

## 方案

### 1. 等待期

- 一次真实私聊 / 群聊 `wake` 的 `followup` 成功后开始等待期；开场 `open`、保温 `warm`、
  值守台 `desk`、群 / 非飞书 / 屏蔽 / 未值守 / 开关关闭都不开始。
- 等待期绑定 DSH turn：`turns.runTurn` 在 `promptSeen` 且拿到 turn 号后调
  `progressCards.arm(...)`；arm 之前不计数、不做发信判定，arm 之后只认本 turn 的事件。
- 2 分钟从等待期开始算；但卡片不早于 turn 真正开始创建。turn 排队超过 2 分钟时，开始即建卡；
  未满 2 分钟则等剩余时间。
- 本 turn 未发信，但新指令打断在飞 turn：handoff，同一张卡、同一 `startedAt`、计数继续，
  `[进度]` 标记清空；不 patch「已暂停」。新 turn 失败则 abort handoff 并收口。
- 旧 turn 已正常结束 / 已发信：等待期结束；新指令新开等待期，重新计 2 分钟。
- 等待期最后一轮结束仍未发信：沿用现状 `done` / `failed` / `cancelled`。

### 2. 发信判定

- 主信号：当前 armed turn 的 `tool/call`，仅 shell 类工具，解析 `arguments.command`；
  识别 `lark-cli ... im ... +messages-send` / `+messages-reply`，且目标命中本会话：
  `--chat-id == chat.chat_id`、`--user-id == 对方 open_id`、reply 的 `--message-id` 在
  `recent` 里。排除 `--dry-run`、patch / delete / reaction、别的会话、注释 / echo / 脚本文件。
- 二级信号：`chat.recent` 里等待期开始后的本人 `out` 消息（排除进度卡自身、`cmd`）；
  arm、建卡前、每次 note / patch / 心跳、finish 前都查。不额外拉取。
- 命中：等待期结束，`state=replied`。**若已有卡片，直接撤回**（`im.recallCard`）；
  撤回失败才 patch 成绿头「已回复」保底。**同一等待期不再建新卡**；同一轮后续发信 no-op。
- 新等待期建卡前若上一张卡还在，先撤回旧卡；保证会话里只留最新一张进度卡。
- 没命中：最终 turn 结束检查一次 recent，仍没有就 `done/failed/cancelled`。

### 3. 群聊开关

- `config.dsh.progress_card` 继续管私聊；新增 `config.dsh.progress_card_group` 管群聊，默认
  `false`。`chats[].progress_card` 三态对私聊 / 群聊都生效，`null` 跟随对应全局键。
- 生效条件：飞书、`kind=p2p|group`、`watching=true`、`blocked=false`、对应全局或单点开、
  `im.sendCard/patchCard` 可用。群聊卡片全群可见，卡上仍只有动作计数和任务级标签。
- 面板设置页加「群聊进度卡」开关；会话详情对群聊也显示「进度卡：跟随全局 / 开 / 关」与
  最近状态。`/api/chat/progress` 不再拒绝群聊。
- 群卡片发送 / patch / 撤回仍走本人身份；非飞书群不生效。

### 4. 数据与文案

- `chats[].progress.state` 增加 `replied`；`ids` 仍保留最近 5 个卡片消息 ID，轮询器排除。
- 撤回成功时卡片消失，面板仍显示「已回复」；撤回失败才留一张「已回复」卡。
- `replied` 卡面：绿头「已回复 · 用时…」+「回复已经发出。」（仅撤回失败时可见）。
- `done` / `failed` / `cancelled` 卡面保持现状；面板 `failed` 统一为「处理中断」。

### 实施步骤

1. `progress.js`：等待期 / arm / handoff / 发信检测 / recent 兜底 / 撤回 / 群聊 enabled。
2. `im.js`：飞书 `recallCard`（`im messages delete --as user --yes`，仅插件自己发的卡）。
3. `turns.js`：仅真实 wake 开等待期；arm；wake 打断时 handoff；开场不发卡；载荷文案。
4. `state.js` / `app.js` / `panel.js`：群聊全局键、单点路由、面板开关与状态；重建 `client.js`。
5. 测试 + 契约 + 架构 + SKILL + CHANGELOG + PROGRESS/log。

## 取舍

| 备选 | 否掉的理由 |
| --- | --- |
| 只按 turn/end 收口 | 发信后的本地归并会继续计数，目标看到的是已完成后的「还在做」 |
| 20 秒轮询确认已发 | 增加拉取频率，且目标收到消息后仍要多等一轮；主信号本来就在会话事件里 |
| 让 agent 写完成标记 | 依赖模型自觉，漏写就回到旧问题 |
| 发信后 patch「已回复」保留卡 | 目标已经收到消息，旧卡留在会话里是噪音；用户明确要求撤回 |
| 群聊复用私聊开关 | 群卡片全群可见，风险不同，默认应单独关 |
| 不 handoff、每轮新卡 | 用户连续指令时会闪「已暂停 → 处理中」，且 2 分钟不断重置可能永不出卡 |

## 影响面

- 代码：`dsh-plugin/lib/progress.js`、`turns.js`、`im.js`、`state.js`、`app.js`、
  `dsh-plugin/web/panel.js`、`dsh-plugin/lib/client.js`。
- 契约：`01-api.md`（`/api/chat/progress` 允许群聊、配置键）、`02-storage.md`
  （`progress.state` 加 `replied`、`progress_card` 适用群聊）、`03-config.md`
  （新增 `dsh.progress_card_group`）。
- 用户可见：设置页多一个群聊开关；群详情有三态；发信后旧卡撤回。
- 兼容：老 `state` 缺 `progress_card_group` 按 false；`done` 等旧状态照常读；不升 state 版本。

## 验收

- [ ] 私聊 / 群聊分别开开关，2 分钟内结束不发卡；超过 2 分钟发卡并刷新计数 / `[进度]`。
- [ ] 开启后 agent 发出 `lark-cli im +messages-send` → 卡片消失，面板显示 `replied`；后续
      `tool/call`、`[进度]`、`turn/end` 不再 patch。
- [ ] 撤回失败（模拟 API 报错）→ 卡 patch 成「已回复」；再后续事件 no-op。
- [ ] 发到别的会话 / `--dry-run` / patch / reaction 不误收口。
- [ ] 2 分钟前发信 → 不建卡；建卡请求在飞时发信 → 卡落地后撤回。
- [ ] 多条指令打断 → 同一张卡、计数与已用时连续；旧轮结束不 patch 暂停。
- [ ] 发信后新指令 → 新等待期，重新 2 分钟；旧卡已撤回。
- [ ] 开场 / warm / desk / 群 / 非飞书 / 屏蔽 / 关闭 → 无卡。
- [ ] 进度卡自身不被 recent 兜底误判；`progress.ids` 仍排除轮询。
- [ ] 命令正文哨兵不进 state / 日志 / 卡片。
- [ ] `node --test`、`python3 tests/run_tests.py`、`bash scripts/gate.sh --quick` 全绿。

## 风险与回滚

- 风险：读 shell 命令参数，命令里可能含回复正文。只在本进程内存匹配，不落 state / 日志 /
  卡片；单测用哨兵验证。撤回是高风险 CLI 动作，只对插件自己 `progress.msg_id` 执行。
- 风险：群卡片全群可见。默认关 + 单群三态；卡面不展示内容。
- 回滚：关掉 `dsh.progress_card` / `dsh.progress_card_group` 或单会话三态即不再发新卡；
  已撤回的卡不可恢复，未撤回的旧卡可用面板关掉后停止 patch。

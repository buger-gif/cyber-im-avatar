# 0042 宿主入口懒加载与客户端立即预取

> 状态: 实施中
> 编号: 0042
> 版本: 0.18.3
> 关联: `docs/audits/2026-11-10-web-boot-audit-race.md`（诊断证据与上游补丁草稿）

## 背景

DSH 桌面端（0.2.2-rc.1）冷启动时，web boot 审计报：

```
web boot: 1 entry did not activate
dsh-cyber-im-avatar: import failed (see console for the import error)
```

本机 `~/Library/Logs/DeepSeek Harness/` 从 2026-11-03 起有 6 份同类 crash log，命名全部指向这个插件；
而打开页面后插件是好的（`sidebar.footer.action` 里 `dsh-cyber-im-avatar` 为 active，宿主半
`state.json` 正常写、`[im-standin] ready` 正常打印）。

事实链（详见 audit 文件）：

- 这句通用文案只在「entry 没有 fiber，且模块系统 `importErrors` 里没有该 id」时打印；
  模块系统的真实导入错误会带在冒号后面。
- 一个 entry 真正导入失败会永久没有 fiber，插件不会自己出现；现在它几秒后正常挂载，
  说明审计看到的是**尚未结算的导入**，不是失败的导入。
- 同一份代码在本机 0.2.1-rc.5 + 隔离 state 的干净冷启动里零报错，`window.__DSH_BOOT__`
  包含该行、面板正常挂上，说明 bundle、`dsh.client` 声明、宿主半都没有坏。
- 本插件宿主入口静态 import 12 个模块（约 320KB），是启动期较晚拿到 fiber 的 entry；
  客户端行发布得晚时，页面要等 `reconcile` 补建 entry 并异步 `prefetch → import → create`，
  而启动审计 `qZ` 不等这条队列。

结论：竞态的真修在 DSH 侧（另出补丁草稿）；本仓库能做的是把「晚发布」这件事本身去掉。

## 目标与非目标

- 目标：冷启动时该行在 boot 快照里已就绪，审计不再把它当成 import 失败；不改任何接口、
  state 字段、配置键与用户可见行为。
- 非目标：不改 DSH 安装包、不 vendors 补丁；不拆 client bundle、不改面板 UI；
  不把竞态说成「已修」——本仓库只降低触发面。

## 方案

### 1. 客户端半立即预取

`dsh-plugin/package.json` 的 `dsh.client` 增加 `immediately: true`。DSH 的 web shell 在
`entries.start()` 之前 `await prefetchImmediateTier()`，把标记了 `immediately` 的行先取回来；
entry 建出来时 factory 已注册，`import` 同步命中，不再留异步窗口。

### 2. 宿主入口收敛静态依赖

`lib/index.js` 的静态 import 只留 Node 内置（`node:crypto` / `node:path` / `node:url`）；
`State` / `Profiles` / `IM` / `MediaStore` / `Poller` / `Turns` / `TurnLog` / `App` /
`ensureDutyDir` 改为 `boot()` 内并发 `import()`，`ensureSkill` 改为 `apply()` 里异步 import。

fiber 是行发布的唯一前提（client-modules 的 scan 只收 `entry.fiber !== void 0` 的 entry），
入口模块越小，fiber 越早出现。

### 3. 启动生命周期保持

- `boot()` 由同步函数改为 memoized Promise：`bootPromise ??= bootOnce()`；
  失败时清空 memo，允许下一次请求或重新 apply 重试。
- `handler` 改为 `await boot()`；`mount()` 的 webServer 注入里 fire-and-forget 触发并记日志。
- `shutdown()` 清 memo，保证 dispose 后重新 apply 能重新装配。
- 轮询、媒体清理定时器、`turns.setHost()` 的接线时机与改动前一致（仍在 webServer 可用时启动）。

## 取舍

| 备选 | 否掉的理由 |
| --- | --- |
| 只改 DSH 启动审计 | 用户装的是 app.asar 里的发行版，插件发不出去；另出上游补丁草稿 |
| 把 panel 拆成 package-local chunk | 动构建产物与模板，且解决不了「行发布晚」，收益路径不对 |
| 什么都不改，只在文档里记一笔 | 每次冷启动都可能看到红字，用户持续以为插件坏了 |

## 影响面

- 代码：`dsh-plugin/package.json`、`dsh-plugin/lib/index.js`
- 契约：无（路由 / `state.json` / 配置键都没变），`docs/specs/contracts/` 不必同 commit 改
- 用户可见：冷启动不再出现这条审计红字；面板、值守、API 行为不变
- 兼容：目录安装是引用，不需要重装；`immediately` 是 DSH 2.1 起就有的 `dsh.client` 字段

## 验收

## 风险与回滚

- 风险：懒加载把模块解析挪到首次请求时（毫秒级），`boot()` 失败会清 memo 重试；
  `immediately` 只是提前取一次本来就要取的 bundle。
- 回滚：revert 该 commit；只想退预取就删 `dsh.client.immediately`。

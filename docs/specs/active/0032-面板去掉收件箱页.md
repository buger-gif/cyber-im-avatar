# 0032 面板去掉收件箱页：消息回 IM 里看

> 状态: 实施中
> 编号: 0032
> 版本: 0.14.0
> 关联: `docs/specs/contracts/01-api.md`（`/api/inbox` 保留不变）、`docs/architecture/01-shape.md`、
> `docs/architecture/02-data.md`

## 背景

2026-11-05 用户反馈：「收件箱的小红点怎么去掉，不要这些东西，正常大家还是在 IM 飞书或者
钉钉里自己看的」，并拍板「整个收件箱页都不要，面板只留 关注 / 分身 / 服务对象 / 体检 / 设置」。

现状（`web/panel.js`）：

- 面板默认页签是收件箱（`S.tab = "inbox"`），挂载后每 60 秒拉一次 `/api/inbox`；
  收件箱页约 350 行（筛选条 / 行渲染 / 空态 / 展开 / `loadInbox` / 6 处刷新调用）。
- 三处红色提醒：行内未读红点 `.ims-unread`、页签待回数字 `.ims-num`、侧边栏席位角标
  `.ims-seat-badge`。用户日常在飞书 / 钉钉里读消息，面板再亮一遍只是噪音。
- 会话详情不是收件箱独占：分身卡片上的「打开」、搜人 / 搜群结果、`#thread=` 深链都能进。

## 目标与非目标

- 目标：面板不再有收件箱页，也不再出现任何未读 / 待回红色提醒；其余五个页签与会话详情照常。
- 非目标：
  - 不改轮询、唤醒、待回状态机与 `state.json`；不加迁移；
  - 不删 `/api/inbox`、`POST /api/inbox/cleanup` 与 `state.inbox()` 派生：计数、体检页、
    详情「现在处理」与契约对账仍用；
  - 不动 skill 形态、平台适配与 CLI；
  - 不加新接口 / 配置键 / 依赖 / 端口；
  - 不用灰点或文案计数替代红点。

## 方案

1. **页签**：`tabs()` 删掉 `["inbox", "收件箱"]`，其余五个顺序不变；页签不再渲染数字角标。
   `S.tab` 默认值由 `"inbox"` 改为 `"service"`（分身 = 值守实例，是现在唯一可操作的家）。
2. **删收件箱视图**：`filters()` / `inboxList()` / `inboxRow()` / `inboxEmptyText()` /
   `previewItem()` / `loadInbox()`，以及 `S.filter / items / grouped / inboxChats /
   inboxTotal / expanded / inboxLoaded`。`body()` 去掉 inbox 分支；`tick()`、`syncNow()`、
   屏蔽、清理待回、详情返回、挂载初始化 6 处 `loadInbox()` 改走 `loadChats()` /
   `loadStatus()` / `paint()`。
3. **席位**：删 `.ims-seat-badge` 与 `paintSeat()` 里的计数；`shareCounts()` 与
   `im-standin:counts` 事件随角标一起删。保留状态点（绿 / 黄 / 灰）、文字与点击开面板。
4. **设置页**：「清理其他会话的待回」可点条件从 `counts.todo > 0 || inboxTotal > 0` 改为
   `counts.todo > 0`；确认文案「不会再出现在收件箱」改「不会再算作待回」；
   「关于」里「state.json 存会话与收件箱」改「存会话与待回状态」。
5. **分身页**：空态「或到『收件箱』点开会话打开值守」改「用上面的搜索加入一个人或一个群」。
6. **CSS**：删 `.ims-unread`、`.ims-tab .ims-num`、`.ims-seat-badge`，以及只被收件箱页
   使用的规则；判据是「CSS 里的类在 JS 里无引用」，逐类核对后删，不留死类。
7. **客户端引导文案**：`lib/client.template.js` 的 `guide.description`「收件箱、分身实例与
   手动发送」改「关注、分身实例与手动发送」。
8. **构建产物**：`python3 scripts/build_client.py` 重建 `lib/client.js`（`tests/test_docs.py`
   核对产物新鲜度）。
9. **截图脚本**：`scripts/shot-dsh.mjs` 的分镜从「席位 → 收件箱 → 详情」改为
   「席位 → 分身 → 详情」，不再点 `.ims-row`。
10. **文档与资产**：README（截图段去掉收件箱图）、`dsh-plugin/README.md`（五个页签、
    席位无角标、API 表）、`docs/architecture/01-shape.md`、`docs/architecture/02-data.md`、
    `CHANGELOG.md` 未发布、`PROGRESS.md`、当日 log；`dsh-plugin/screenshots.json` 4 → 3，
    删 `docs/images/panel-inbox.png`。

契约：路由与配置键都不增删，`/api/inbox` 形状不变，`docs/specs/contracts/` 不需要改。

## 取舍

| 备选 | 否掉的理由 |
| --- | --- |
| 只去掉红点、保留收件箱页 | 用户明确要整页不要；留页只是把未读换个地方堆着 |
| 连 `/api/inbox`、`counts`、`state.inbox()` 一起删 | 体检页、详情「现在处理」、唤醒载荷与契约测试还依赖这些派生；删接口是契约破坏且无用户收益 |
| 侧边栏席位一起去掉 | 席位是面板唯一常驻入口，去掉等于把面板藏起来 |
| 用灰点 / 文案计数替代红点 | 「大家还是在 IM 里自己看」= 不要再提醒，换个颜色不是解决 |

## 影响面

- 代码：`dsh-plugin/web/panel.js`、`lib/client.template.js`、`lib/client.js`（构建产物）、
  `scripts/shot-dsh.mjs`、`scripts/demo/fixture.mjs`（夹具保留 `/api/inbox`，与后端一致）
- 契约：无（`/api/inbox` 路由与响应形状不变）
- 用户可见：面板六个页签变五个，默认停在「分身」；侧边栏席位不再有红色数字；收件箱相关的
  红点、筛选条与空态文案消失；会话详情仍可从分身卡片与搜索进
- 兼容：`state.json` / 配置 / 数据目录都不动，不需要迁移；老链接 `#tab=inbox` 落到默认页

## 风险与回滚

- 风险：详情入口变少（只余分身卡片与搜索），「从收件箱点一行进详情」的习惯要改；默认页签
  变化会让人一时找不到方向；市场详情页少一张截图。
- 回滚：revert 这个 commit 即可。后端接口与数据都没动，不需要清数据；这次不保留「显示红点」
  的开关，要恢复得另开 spec。

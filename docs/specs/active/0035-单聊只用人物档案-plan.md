# 0035 单聊只用人物档案 · 实施计划

> 关联: `docs/specs/active/0035-单聊只用人物档案.md`
> 一步一验证：每步结束后跑该行的验证命令，红了先修再往下。

## 1. 存储层：单聊记忆解析 + 旧文件搬迁

- [x] `profiles.js` 加 `memoryRel(platform, chat, selfId)`：
      p2p 且有 `chatPersonId` → `personRel`；否则 `profileRel`。
- [x] `Profiles.memoryFor` / `ensureMemory` / `legacyBookFor` / `historyPathFor`：
      `ensureMemory` 在人物档案不存在且旧工作本有内容时整文件 `rename`；否则按需建模板。
- [x] 单测：四类判定（recent 发送者 / `ou_` chat_id / 企微 / 钉钉兜底 / 群）、
      搬迁后内容逐字节一致、人物档案已存在时不动旧文件。

验证：`cd dsh-plugin && node --test tests/profiles.test.mjs`

## 2. 载荷：私聊一份档案

- [x] `buildWakePrompt` / `buildOpenPrompt` / `buildWarmPrompt` 加 `single` 与
      `legacyPath` / `legacyHistory`；私聊只输出一行 `人物档案：`，群不变。
- [x] `Turns._wake` / `Turns.warm` 用 `memoryFor` 取路径；`single` 时不走 `peopleFor`。
- [x] 单测：私聊首轮/后续轮/开场/心跳无 `会话工作本：`；群用例不变；
      旧文件存在时出现「旧私聊工作本（待并入）」与 `.history.md` 目标。

验证：`cd dsh-plugin && node --test tests/turns.test.mjs`

## 3. 面板 API

- [x] `app.js`：`targets()` 对 p2p 用 `ensureMemory` 并把 `profile*` 指向人物档案；
      `targetProfile()` 对 p2p 写人物档案；`watch` / `chatMode` 的 `ensure` 换成记忆文件。
- [x] `forget` 不删人物档案（保持现状，补注释）。
- [x] 单测：targets 行路径、写接口落点、watch 后新建的是人物档案、forget 保留人物。

验证：`cd dsh-plugin && node --test tests/app.test.mjs`

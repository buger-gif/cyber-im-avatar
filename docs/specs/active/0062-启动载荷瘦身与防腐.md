# 0062 启动载荷瘦身与防腐

> 状态: 待实施
> 编号: 0062
> 版本: 0.27.0
> 关联: `docs/specs/archive/0045-载荷只声明变化.md`、`docs/specs/archive/0046-自at关键词启动值班.md`、
> `docs/decisions/implemented/0014-载荷只声明变化.md`、`SKILL.md §在 DSH 插件壳里`

## 背景

### 这次看到的

一次真实群启动复算（10 条上下文、2 份人物档案、全自动）：

| 载荷 | 行 | 字 | 消息行 | 口径 / 元信息 |
| --- | --- | --- | --- | --- |
| 开场（IM 指令启动） | 34 | 2553 | 12 行 / 648 字 | **22 行 / 1904 字（75%）** |
| 首轮唤醒（1 条消息） | 13 | 1091 | 1 行 / 71 字 | 723 字（66%） |
| 常规唤醒（口径已声明） | 3 | 159 | 159 | 0 |

口径部分主要是重复：发送方式 445 字（占开场 17%）复述 `SKILL.md §承诺边界` 与 `§铁律`；
「启动只是开关」出现 3 次；发言权写两条（147 + 151）与 skill 的三条并列；运行形态、记忆括注、
进度卡（330 字）、关注程度、富媒体各有一份 skill 正文。

### 这不是一次写崩，是每次局部最优

- `SKILL.md` 行数预算从 290 涨到 535（约三周，+84%），每次上调都有一条合理理由；
- 每个新 spec 都往首轮载荷补一段：0045 只声明变化、0051 发言权、0053 引用提示、
  0056 承诺边界（445 字）、0061 进度卡（330 字）——单看每一步都对，合起来 2553 字；
- `buildOpenPrompt` 与 `buildWakePrompt` 各拼一套头，加字段要改两处，已经开始漂
  （open 有启动指令行、wake 没有）；
- `turns.test.mjs` 202 条 `assert.match` 锁在整句文案上，改文案 = 改一堆测试，
  下一步自然就是「断言放松一点」；
- `turns.js` 已 2129 行：拼载荷、看门狗、媒体、日志、编排全在一个文件里。

结论：**劣化来自「没有归属 + 没有形状」**。新需求来了，最省事的落点永远是「首轮加一段」；
行数预算只拦上限，拦不住「这次 +5 有理由」。只做一次瘦身，三个月后还会回到 2553 字。

## 目标与非目标

- 目标 1：载荷只承担本轮事实、口径变化与一行硬门；开场口径文字 1904 → 约 650 字。
- 目标 2：拼载荷从散文变数据——`lib/prompt.js` 的 `BLOCKS`（版式）与 `DELTAS`（口径）两张表；
  新字段 = 注册一行。
- 目标 3：三道闸把劣化变成可见、可拦：快照 diff、尺寸与形状预算、发版读数。
- 目标 4：skill 按「每次都要读」与「装的时候才读」分家，`SKILL.md` 532 → 约 375 行，
  预算下调到 400 并只降不升。
- 目标 5：给下一个会话一条硬规则——**加法必须带减法**，首轮只声明会改变动作的开关。
- 目标 6：可自定义口径有统一模型——默认（skill）/ 生效值（载荷）/ 改的入口（面板或工作本）
  三件齐全，开关双向可声明，压缩后能重发。
- 非目标：不改唤醒范围、发送方式判定、防回环、分诊、面板，以及 `state.json` / 路由 /
  配置键；不改心跳与值守台载荷的语义；不重写 skill 的规则内容（只搬家与去重）。

0045 曾把「不改首轮 / 开场载荷的结构」列为非目标；本 spec 覆盖这一条，0045 的其余约定
（只在首次 / 变化 / 压缩后声明一次）不变。

## 方案

### 1. 归属：事实 / 变化 / 硬门

载荷只允许三类行：

| 内容 | 唯一归属 | 载荷形态 |
| --- | --- | --- |
| 平台 / chat_id / 本人 / 记忆路径 / 消息行 / 点名统计 / 更早消息入口 | 载荷 | 事实 |
| 发送方式、关注程度、发言权是否自定义、本人指令、进度卡、富媒体、运行形态 | `SKILL.md` | 变化行：只在首次 / 切换时一行 |
| 不可逆动作（钱、合同、付款、权限、凭据、公开发布、参会 / 签字 / 拍板） | 载荷（自包含） | 一行硬门 |

判据两句：

- **这句话下一轮还会不一样吗？** 会 → 载荷；不会 → skill。
- **声明的是开关状态，不是开关说明书。** 进度卡只写「进度卡：开」，`[进度]` 的写法留在
  skill；只有会改变发送动作 / 唤醒范围的开关才值得进载荷。

### 2. 结构：拼装变数据

- 新建 `dsh-plugin/lib/prompt.js`：`identityBlock()`、`promptBlock()`、`BLOCKS` 与 `DELTAS`；
  每种载荷 = 一个 block 名单（open / wake-first / wake-steady / warm / desk），builder
  只做选块与拼接，不再各写一套 if。
- `BLOCKS` 管版式（标题、身份、记忆、消息、尾注），`DELTAS` 管口径（§5）。加一个开关只改
  一行注册，不动 builder；加一类行才动 `BLOCKS`。
- `turns.js` 只保留编排（resolve、followup、看门狗、日志），从 2129 行降到约 1450 行。
- **快照先行**：先给现有输出拍快照（§3.1），再抽骨架；重构完成时快照必须逐字不变，
  以此证明这次只动结构不动文案。

### 3. 三道闸

**3.1 快照：改了就是看得见的 diff**

- `dsh-plugin/tests/fixtures/prompt/{open,wake-first,wake-steady,warm,desk}.txt`，固定虚构
  fixture（2 份档案、2 条消息、全自动、群）；
- 测试逐字比对；只有 `UPDATE_PROMPT=1 node --test` 才写回。任何载荷改动在提交里都是一段
  可读 diff，评审看「加了什么」，而不是散落在 200 条 `assert.match` 里；
- 快照文件大小本身就是趋势数据：`git log --stat` 就能看到增长曲线。

**3.2 预算与形状：长不过线**

- 非消息行（剔除 `- [` 开头的消息 / 人物行与 `  ↪` 引用行）：开场 ≤ 16 行、
  首轮唤醒 ≤ 13 行、常规唤醒 ≤ 5 行；消息行不计入；
- 单条元信息行 ≤ 160 字（含绝对路径的行除外）。445 字发送方式、330 字进度卡这种段落，
  结构上写不进来；
- 开场非消息总字数 ≤ 900，首轮唤醒 ≤ 750；超了测试红。

**3.3 趋势：劣化是曲线，不是断崖**

- 新增 `dsh-plugin/scripts/prompt-stats.mjs`：一条命令打印五类载荷的行 / 字数；
- 发版 runbook 增加一步：把三类读数抄进当日 log。下次再涨，先看到曲线，而不是又写完
  一篇才发现。

### 4. skill 分载：每次加载的只留守值要用的

`SKILL.md` 同时承担「值守时怎么想」和「怎么装、怎么排障、怎么在独立形态跑」。DSH 壳内
永远用不到后者（载荷明写「不要挂监听、不要跑 listen_cli」），但它们占了一半篇幅、
每次新会话都跟着进上下文。

| 章节（行数） | 谁需要 | 去向 |
| --- | --- | --- |
| 快速开始（27）、标准闭环（28）、监听脚本公共参数（14）、平台差异与字段漂移（11）、记忆 CLI（17）、核心设计三层降级（5）、出故障了（30）、权限标准（34） | 独立形态 / 装 / 排障 | `references/standalone.md` |
| 用户想装 DSH 插件时（12） | 用户问起 | `SKILL.md` 留 3 行（命令 + 指向 README） |
| 壳内契约、心跳、富媒体、承诺边界、发言权、本人指令、记忆读写、日报、铁律 | 每次值守 | 留在 `SKILL.md` |

- 指针写法：`没有「运行形态：DSH 插件壳」标记 = 独立形态，先读 references/standalone.md；
  壳内不要读它。`与现有「平台差异只读对应那一份」同构；
- 分载后 `SKILL.md` 约 375 行，预算 535 → 400；`references/standalone.md` 登记 220 行；
- 只建**一份** standalone 手册，不再按安装 / 授权 / 排障继续分裂——文件数量本身就是新的
  劣化面。

### 5. 可自定义口径：三件齐全，只给生效值

插件里有一批口径是用户随时可改的（值班卡、面板、配置文件、群工作本）。它们既不是纯事实，
也不该整段写进载荷。本 spec 把它们收成一张注册表。

**5.1 三件齐全（新开关的准入条件）**

| 位置 | 放什么 | 谁维护 |
| --- | --- | --- |
| 默认与判据 | `SKILL.md` 一处（不是某个部署的当前值） | skill |
| 生效值 | 载荷：首次给一次，之后只在变化时给；开关双向 | `DELTAS` 表 |
| 改的入口 | 面板（值班卡 / 详情 / 设置）或群工作本；agent 写回前必须重读 | 插件与 agent |

缺任何一件都算缺陷：没有默认 → 换个部署就错；没有生效值 → agent 按默认行动；没有入口 →
用户改不了，只能改代码。

**5.2 现有口径盘点**

| 口径 | 值域 / 来源 | 默认 | 入口 | 载荷行 |
| --- | --- | --- | --- | --- |
| 发送方式 | `chats[].send_mode`，缺省取 `send_mode_default` | 草稿审批 | 值班卡 / 详情 | `发送方式：X`（首次 / 切换，双向） |
| 关注程度 | `chats[].wake_mode` | 只认 @ | 值班卡 | `关注程度：X`（首次 / 切换，群切回也要说） |
| 发言权 | 工作本 `## 我在这个群的发言权` 自由文本 | 内置「默认沉默」 | 面板「发言权 → 编辑」或工作本 | `发言权：默认沉默` 或 `本群单独改过 → 那段` |
| 进度卡 | `chats[].progress_card` 三态 + `dsh.progress_card(_group)` 全局 | 关 | 值班卡 / 设置 | 开时 `进度卡：开`；切到关 `进度卡：关` |
| 本人指令 | `command.start_keyword` / `command.enabled` | 启动 / 开 | 设置 | `启动只是开关…`（仅首轮或首次出现指令） |
| 其余运行参数（超时、保温、回执、表情、分诊限额） | `dsh.*` / `duty.*` | 见 `docs/specs/contracts/03-config.md` | 设置 | 不进载荷：它们改变时机，不改变 agent 的下一个动作 |

**优先级**（只在 skill 写一次）：群工作本 / 值班单点 > 全局默认 > skill 默认。载荷给的是
解析后的生效值，不是某一层配置的原始值。

**5.3 现状缺口（本次顺带修）**

- 进度卡从开切到关时 `progressCardNote(false)` 返回空 → agent 不知道要停写 `[进度]`；
- 群的关注程度从「全部消息」切回「只认 @」时 `wakeModeNote()` 返回空 → agent 仍按全量判断；
- 会话压缩后 `noteCompacted()` 清了 `send_mode` / `wake_mode` / `cmd` / `progress_card`，
  但没清 `rights` → 自定义发言权的指针不会重发。

这三条都是「有注册、没覆盖」的典型，正好由 §5.4 的矩阵测试兜住。

**5.4 注册表与测试矩阵**

```js
// dsh-plugin/lib/prompt.js
export const DELTAS = {
  send_mode: { label: "发送方式", values: ["draft", "auto"], skillHint: "发送方式" },
  wake_mode: { label: "关注程度", values: ["mention", "all"], skillHint: "关注程度" },
  rights:    { label: "发言权",   values: [false, true],      skillHint: "发言权" },
  progress:  { label: "进度卡",   values: [false, true],      skillHint: "进度卡" },
  command:   { label: "启动",     values: [false, true],      skillHint: "启动关键词" },
};
```

- builder 不再写 `fresh || prevX !== x`，而是遍历 `DELTAS`，由每条自己的规则决定是否出行；
- 测试遍历 `DELTAS`，每个口径至少四个用例：默认首轮、开→关、关→开、压缩后重发；
  断言「变则恰好一行、不变则零行、单行 ≤160 字」；
- 测试同时断言每个 `skillHint` 在 `SKILL.md` 里仍能找到——skill 分载改名时不会悄悄丢口径；
- 加新开关必须进 `DELTAS`，否则矩阵测试覆盖不到它，review 也会在注册表里看见这一行。

**5.5 哪些口径不进载荷**

判据：**它改变 agent 的下一个动作吗？** 不改变的一律留在面板 / 配置里（超时、保温周期、
回执文案、表情回执、轮询频率、每天分诊限额）。triage 台是例外：它本来就是一问一答的
一次性判断，载荷给的是本次事实而不是常驻口径。

### 6. 流程闸：让「加一段」不再是默认选项

- `AGENTS.md` 设计铁律加一条：**载荷只给事实、变化与硬门；新口径进 skill，不进载荷；
  加规则必须带减法**（同一改动里删掉等量旧内容，或在 spec 里说明为什么不占预算）；
- 新需求落点决策（写在铁律旁注，四行）：
  1. 改变发送动作 / 唤醒范围吗？否 → 只进 skill 或面板，载荷最多一行开关状态；
  2. 是每轮都变的事实吗？是 → 事实 block，单行 ≤ 160 字；
  3. 是首次 / 切换才要的一次性口径吗？是 → 进 `DELTAS`，先看能否并进已有行；
  4. 不声明会导致误发 / 漏发吗？是 → 进硬门或变化行；否 → skill 兜底。
- 新开关必须三件齐全（§5.1），否则 spec 的「影响面」不成立；
- `docs/specs/_template.md` 的「影响面」加一行「载荷影响：新增 / 删除的口径行与净字数
  （无则写无）」，每份 spec 回答一次；
- `docs/implementation/runbooks/publish.md` 增加 prompt-stats 抄录一步。

### 7. 实施批次（每批独立可验收、可回滚）

| 批 | 做什么 | 验收 |
| --- | --- | --- |
| 1 | 拍快照 → 抽 `prompt.js` + `BLOCKS` / `DELTAS`，文案不动 | 新快照与重构前输出逐字一致；`node --test` 绿 |
| 2 | 按归属表删重复、压注记、合并启动语义；补三个缺口；加预算 / 矩阵测试与 `prompt-stats` | 尺寸达标；快照 diff 只剩删除与开关行；矩阵测试绿 |
| 3 | skill 分载到 `references/standalone.md`，更新指针与预算 | `SKILL.md` ≤ 400；独立形态命令一条不少；壳内提示不读它 |
| 4 | 流程闸（AGENTS / 模板 / runbook）、CHANGELOG / PROGRESS / log、真机看开场 | gate 绿；真机首条 ≤ 25 行；归档 spec |

## 取舍

| 备选 | 否掉的理由 |
| --- | --- |
| 只瘦身一次，不加闸 | `SKILL.md` 从 290 到 535 已经证明：没有闸，每次 +5 都有理由 |
| 只加尺寸预算 | 预算可以被上调；单行 160 与快照 diff 才让「加一段」变得显眼 |
| 用正则禁某些短语 | 换个说法就绕过，维护成本还高 |
| 把口径搬进 `SKILL.md` | 预算只剩 3 行；skill 本身还要分载，不能一边搬一边涨 |
| skill 按主题拆成多份 references | 文件越多，路由与维护成本越高；只留一份 standalone 手册 |
| 让 agent 直接读 `state.json` 取配置 | 要沙箱完整权限、耦合内部形状，还会把无关字段带进上下文；载荷给生效值更小更稳 |
| 所有配置项都进载荷 | 超时、轮询、回执不改变下一个动作，只会制造噪音 |
| 每次发版人肉提醒「别写长」 | 靠自觉的方案在第三次需求就会失效 |

## 影响面

- 代码：新增 `dsh-plugin/lib/prompt.js`、`dsh-plugin/scripts/prompt-stats.mjs`、
  `dsh-plugin/tests/prompt-snapshot.test.mjs`（含预算、形状与口径矩阵）；改
  `dsh-plugin/lib/turns.js`（抽出 builder、修三个缺口）、`dsh-plugin/tests/turns.test.mjs`
  （约 10 处断言）。
- 载荷影响：开场口径 22 行 / 1904 字 → 约 14 行 / 650 字；首轮唤醒 723 → 约 500 字；
  常规轮基本不变；新增「关」的开关行（仅切换时一条）。
- 文档：`SKILL.md`、新增 `references/standalone.md`、`docs/AGENTS.md`（references 归属描述）、
  `AGENTS.md`（铁律一条）、`docs/specs/_template.md`（载荷影响一行）、
  `docs/implementation/runbooks/publish.md`、`scripts/doc_budgets.json`、`CHANGELOG.md`、
  `PROGRESS.md`、当日 log。
- 契约：无新配置键、无新状态字段（`chats[].send_mode` / `wake_mode` / `progress_card` 与
  `dsh.*` 都不动）；`announced` 形状不变，只补 `rights` 的压缩清理。
- 用户可见：DSH 会话首条消息明显变短；切到「关」时 agent 会收到一行状态；skill 安装包的
  `SKILL.md` 变短、多一份按需手册。
- 兼容：老会话下一轮自然用新载荷；`state.json` 不迁移。

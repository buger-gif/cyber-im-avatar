# 0045 载荷只声明变化

> 状态: 实施中
> 编号: 0045
> 版本: 0.19.0
> 关联: spec 0043（发送方式）、spec 0024（关注程度）、spec 0029 / 0039（本人指令）、
> `docs/decisions/implemented/0014-载荷只声明变化.md`

## 背景

从 0043 起，唤醒载荷每轮都在末尾复读一段「发送方式：草稿审批 / 全自动（插件当前设置；
只由面板开关决定……）」；群「全部消息」与私聊「只认 @」还会每轮复读关注程度说明；
本人指令轮则每轮复读整段「【本人指令】……」规则。

实际读数：单聊「全部消息 + 全自动」的一次普通命中，载荷只有 1 行消息，却跟着 3–4 行
永远不变的发送方式；每次本人 @ 自己下指令，再叠 4 行同样不变的指令规则。用户在自己的
值守会话里持续看到这两段原样复读，明确指出「每轮追加太丑陋，没变的值不要来回一直追加」。

这些口径在同一条 DSH 会话里通常不变。重复只增加噪声和 token，不增加信息；真正需要
重复声明的是「切换 / 新会话 / 会话被压缩」——旧约定可能与新值不同，压缩则会让上下文里的
声明直接消失。用户补充要求：能判断会话被压缩过的话，压缩之后重新追加一次。

## 目标与非目标

- 目标：同一条 DSH 会话里，发送方式、关注程度、本人指令规则只在**首次**、**取值变化**
  或**会话被压缩**后的第一轮追加一次；其余轮次只追加本次新消息（以及尚未给过的人物档案行、
  待并入的旧工作本行）。
- 非目标：
  - 不改首轮 / 开场载荷的结构，它们本来就是一次性入口载荷；
  - 不改心跳与值守台载荷（仍不注入发送方式，边界仍是「不要发」）；
  - 不改 `state.json` 字段、路由、配置键，不加持久化迁移；
  - 不改面板交互与防回环熔断（本人指令 10 分钟 5 次）；
  - 不改 skill 独立形态的监听载荷。

## 方案

### 1. 纯函数：`buildWakePrompt()` 接受「已声明口径」

新增可选参数 `announced`，形状 `{ send_mode, wake_mode, cmd }`——这条 DSH 会话上一次
已经声明过的值。非首轮时按变化决定是否追加：

| 注记 | 追加条件 | 变化时文案 |
| --- | --- | --- |
| 发送方式 | `announced.send_mode !== sendMode` | `发送方式：全自动（已从草稿审批切换；只由面板开关决定……）` + 该模式原有规则 |
| 关注程度 | `announced.wake_mode !== wakeMode`（仅群 all / 私聊 mention 两种有说明的形态） | `（关注程度已切换为「全部消息」：……）` / `（关注程度已切换为「只盯 @我」：……）` |
| 本人指令规则 | `!announced.cmd` | 原文不变；只在会话里**第一次**出现 `cmd` 时带 |

- `announced` 缺省 / `null` 视为「没声明过」→ 三种注记照旧全带。这是旧调用与进程重启后
  首轮的安全兜底。
- `firstTurn === true` 时同样全带（入口载荷语义不变）。
- 变化文案保留 `发送方式：<新值>` 前缀，便于 grep 与 agent 扫读；只在括号里标明「已从 X 切换」。
- 未变时不输出空行、不输出「未变」占位——载荷里干脆没有这一段。

### 2. `Turns`：每 DSH 会话一份内存口径记录

- 新增 `announcedPolicy`：`Map<${platform}:${chatId}:${sid}, { send_mode, wake_mode, cmd }>`，
  上限 64 条，逐出最旧。与 `seenPeople`（人物档案只给一次）同一策略：**只在内存**，
  换会话 / 重开 / 进程重启后从零开始，最多补声明一次，不影响正确性。
- `_wake()` 取到 `sid` 后取记录，传给 `buildWakePrompt({ announced })`；`buildOpenPrompt`
  不传（开场照旧全带），但同样记账。
- 记账时机：`runTurn()` 新增可选 `onSent` 钩子，在 `agent.followup(message)` 成功之后
  才把本次口径写回记录。载荷没送出去就不会被误记为「已声明」。
- 载荷送出后把发送方式与关注程度写回记录（值相同也写，便于下次比较）；`cmd` 只在出现本人指令时置真。

### 3. 压缩检测：下一轮补声明一次

DSH 压缩会话时会 append `compaction/summary`（随后 replace 掉一段历史）和
`compaction/end`。插件在根 ctx 上订阅 `session/event`，按事件里的 `session.id` 找到
`announcedPolicy` 中对应记录并清空，下一轮唤醒 / 开场就会把三种口径完整重带一次；
同一批发言人的「人物档案」路径（`seenPeople`）也一起清掉，下一轮补一次。
`compaction/end` 带 `error` 表示压缩失败、上下文没有替换，不触发重带。

订阅只在 `setHost()` 时注册一次（与 `seenPeople` 同一生命周期），旧版 DSH 没有该事件时
订阅本身无害，行为退化为「靠 skill 常驻规则兜底」。

### 4. skill 常驻规则（不依赖每轮复读）

`SKILL.md` 的 DSH 插件壳段补两条，保证会话上下文被压缩后口径仍有依据：

- 「本人指令」：标「本人（@自己）」的行不是客户消息，按它执行 / 回答；除非明确要求对外
  回复，否则不发到会话；回复里不要 @ 本人自己（会再次触发唤醒，形成回环）。
- 「发送方式」：载荷在首轮、开场与**切换后**声明实际生效值；同一会话后续轮次可能不再重复，
  以本会话最后一次声明为准；没有声明过时按草稿审批。

## 取舍

| 备选 | 否掉的理由 |
| --- | --- |
| 维持每轮重复（现状） | 换会话 / 压缩后不丢口径，但每轮多 3–5 行噪声，用户已明确不要 |
| 只在首轮声明一次 | 模式中途切换时不生效，agent 会继续按旧模式；切换必须当轮可见 |
| 只在变化时声明（本方案） | 切换立即生效、未变不重复；压缩会丢口径，但 DSH 的 `compaction/*` 可确定性检测、下一轮补声明，另有 skill 常驻规则兜底 |
| 把口径持久化进 `state.json` | 重启后少声明一次，但要加字段 / 契约 / 迁移，收益远小于成本 |
| 本人指令规则继续每轮重复 | 防回环最稳，但与用户诉求冲突；改为会话内首次声明，另有 5 次 / 10 分钟熔断与 skill 常驻规则兜底 |
| 靠 skill 常驻规则兜底，不检测压缩 | 压缩后模型上下文里可能已经没有声明，agent 只能默认草稿审批；DSH 的 `compaction/*` 是确定性事件，可以准确补声明，没有理由靠猜 |
| 每次压缩都把所有会话重声明 | 压缩只影响一条 DSH 会话；按 `session.id` 精确清掉那一条的记录即可，别打扰其它值班 |
| 未变时输出「发送方式未变：X」 | 仍然每轮占一行，等于没解决问题；当前值以本会话最后一次声明为准 |
| 旧工作本「待并入」行也改成只声明一次 | 它是待办提醒不是值；文件消失才停，重复是在提醒 agent 还没做完 |

## 验收

- [x] 纯函数：`announced` 与当前一致 → 非首轮只剩消息行；不一致 → 带「已从…切换」；
      缺省 `announced` / `firstTurn: true` → 三种注记仍全带
- [x] 唤醒集成：首轮带发送方式；下一轮不变不带；改 `chat.send_mode` 后下一轮带，再下一轮不带
- [x] 关注程度：群「全部消息」首轮带；不变轮不重复；切到「全部消息」后第一轮带「已切换」
- [x] 本人指令：会话内第一条 cmd 带完整规则；后续 cmd 轮不重复，但消息行仍标「本人（@自己）」；
      换 DSH 会话后再带
- [x] 开场、心跳、值守台：开场仍带发送方式；心跳与值守台仍不出现发送方式
- [x] 重启（新 `Turns` 实例、同 session id）后首轮补声明一次，之后不再重复
- [x] 压缩：`compaction/summary` 或成功的 `compaction/end` 之后下一轮重新声明一次，
      同批发言人的人物档案行也补一次，再下一轮恢复安静；带 `error` 的 `compaction/end`
      不触发重带
- [x] `cd dsh-plugin && node --test` 全绿
- [x] `python3 tests/run_tests.py`、`bash scripts/gate.sh --quick` 全绿
- [ ] 用户真机：下一轮真实命中载荷只追加消息行；面板切发送方式 / 关注程度后的第一轮
      能看到对应声明

## 风险与回滚

- 风险：DSH 上下文被压缩后 agent 丢了口径，可能漏发或误发。缓解：`SKILL.md` 常驻规则；
  载荷缺行时沿用本会话最后一次声明、没有声明时默认草稿审批；面板可随时切；防回环有熔断。
- 风险：记录只在内存，进程重启后第一轮会补声明一次——只是多一段文本，不影响行为。
- 风险：压缩事件名 / 载荷依赖 DSH 版本。缓解：监听只读 `type` 与 `data.error`，
  旧版没有这些事件时退化为 skill 常驻规则兜底，不报错、不阻塞唤醒。
- 回滚：`buildWakePrompt()` 忽略 `announced`（删掉三处条件分支）即回到每轮声明；
  无需迁移、无需清库。

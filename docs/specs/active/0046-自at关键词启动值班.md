# 0046 自 @ 关键词启动值班

> 状态: 实施中
> 编号: 0046
> 版本: 0.20.0
> 关联: `docs/specs/contracts/01-api.md`、`docs/specs/contracts/02-storage.md`、
> `docs/specs/contracts/03-config.md`、`docs/specs/archive/0029-私聊at自己对替身说话.md`、
> `docs/specs/active/0039-群聊里at自己即指令.md`、`docs/specs/archive/0044-分诊值班跟随加入工作区.md`

## 背景

spec 0029 / 0039 已经把「本人 @ 自己」做成 `kind=cmd`：私聊与群里都会唤醒绑定会话，交给
agent 当作本人指令处理。但「在当前会话开启值守」仍然只能回面板点「加入值守」；人已经在
IM 里时，多一步切窗口。

用户要的是把自 @ 当成一个**确定性的开关**：在任意群聊或私聊里 @ 自己，正文带一个关键词
（默认「启动」），就在当前会话启动值班，等价于面板上的「加入值守」。关键词要能在设置页改。

风险是重复启动：同一 `platform:chat_id` 同时只能有一个值班会话。现在 `chats` 以
`platform:chat_id` 为键、`chats[].dsh_session` 单值绑定，结构上只有一个会话；但命令可能
并发到达（同一轮两条、快车道与跨会话搜索同时命中），必须显式去重，并把「已有值班」的
结果给用户看，而不是静默再开一轮。

## 目标与非目标

- 目标：本人发送、@ 到自己、正文含配置关键词的消息 → 在当前会话启动值班：
  `watching=true`、`target=true`、`timer=1`、按会话类型取默认关注程度、固化发送方式、
  按「`config.join_workspace` → 最近在用 → DSH 默认」落工作区，然后开一场开场 turn。
- 目标：**已值守会话即时识别**（快车道下一轮）；**飞书未值守会话也能发现**（包括私聊与
  群聊、存量群）：每分钟一条跨会话消息搜索，只查本人发送且 @ 本人的消息。
- 目标：同一 `platform:chat_id` 同一时间只允许一个值班。已有绑定会话 → `already`，
  不新建、不再开 turn；正在启动 → 本次不重复启动；被屏蔽 → `blocked`。
- 目标：关键词在面板设置页可改，可整体关闭；关闭或留空时自 @ 仍按 0029 / 0039 的普通
  `cmd` 唤醒，不启动值班。
- 目标：命中启动关键词的 `cmd` 被开关消费，不再作为「本人指令」交给 agent；开场 turn 的
  上下文里仍能看到这条消息，但载荷说明它只是启动开关、不要为它往会话里发言。
- 目标：面板能看到最近一次指令结果（`started` / `already` / `blocked` / `failed`）。
- 非目标：不做「停止 / 暂停 / 重启」关键词，本次只有启动；停止仍走面板「不盯」。
- 非目标：不做通用命令路由；只有「启动」这一条确定性命令，其余自 @ 仍是 `cmd`。
- 非目标：不为指令自动往 IM 回执或发确认消息；结果只在面板与本地状态里。
- 非目标：不逐会话轮询未值守的群 / 私聊，不开新端口，不新增第三方依赖。飞书用一条
  `+messages-search` 搜索兜底；企微 / 钉钉没有跨会话搜索，只支持已值守会话里即时识别。
- 非目标：不改变 `duty` 分诊的自动判断口径；启动指令是用户显式动作，直接 `watch`，
  不受 `duty.max_groups` / 群成员上限 / 分诊开关限制（与面板手动加入同权）。

## 方案

### 1. 配置（契约 03）

```json
"command": {
  "enabled": true,
  "start_keyword": "启动"
}
```

- `command.enabled`：默认 `true`；`false` 时即时与搜索都不再消费启动指令。
- `command.start_keyword`：默认 `"启动"`；去掉首尾空白与控制字符，最多 20 个字符；
  空串等价于关闭启动指令。面板可改；只写给本插件，不发给模型。
- `POST /api/config` 合并 `command` 子对象。启用状态 + 空关键词整次拒绝并返回原因；
  关键词超长同样拒绝，不静默截断。

### 2. 识别（`lib/command.js` + `poller.process`）

`command.js` 只做纯函数，不碰状态：

- `normalizeKeyword(raw)`：trim、压缩空白、去控制字符、最多 20 字。
- `commandEnabled(cfg)`：`enabled !== false` 且关键词非空。
- `stripMentions(content, selfNames)`：去掉 `@_user_<N>` 与 `@<本人显示名>`，用于关键词匹配。
- `isStartCommand(msg, { selfId, selfNames, keyword })`：发送者是本人、`isMention` 命中本人、
  去掉 mention 后正文包含关键词（ASCII 大小写不敏感；中文原样）。
- `commandRow(msg)`：把检索结果归一成 `recent` 行（`kind=cmd`、`state=new`、保留正文），
  开场上下文用。

识别位置：

- `pollChat()` 拿到 `process()` 的批次后，取其中 `kind=cmd` 且命中关键词的消息；只处理
  最新一条，其余命中消息一并从唤醒批次里移除。
- `maybeCommandScan()` 每 `COMMAND_SCAN_SEC=60` 秒跑一次，仅飞书；用
  `+messages-search --sender <本人> --at-chatter-ids <本人> --page-size 50` 跨
  p2p / group 搜索最近 3 分钟（只取一页，不 `--page-all`）；不把关键词交给服务端分词，
  服务端只收窄到「本人发送 + @本人」，结果再按
  上面的纯函数本地过滤（关键词可能是分词器搜不到的词）。返回的 `chat_type`
  决定新会话的 `kind`；群名可取时一并带上。
- 同一 `msg_id` 只处理一次：`chats[].command.msg_id` 记录最近处理过的启动指令；
  `result="starting"` 不算已处理，允许重启后重试。
- 点开详情等只读拉取（`wake=false`）不消费启动指令：指令只在定时 / 快车道与跨会话
  扫描两条路径生效，避免「看一眼」就意外开值班。

### 3. 启动与冲突（`poller.startDutyFromCommand`）

按以下顺序收口，逐条返回结果：

| 条件 | 结果 | 动作 |
| --- | --- | --- |
| 同一会话已有启动中的锁 | `already` | 不写状态、不开 turn，提示「正在启动」 |
| 同一 `msg_id` 已处理且结果不是 `starting` | 已有结果 | 直接跳过（幂等） |
| `chat.blocked` | `blocked` | 不改状态，不拉取 |
| `chat.watching && chat.dsh_session` | `already` | 记录冲突，不新建、不开 turn |
| `chat.watching && !chat.dsh_session` | `started` | 补开会话（修复空绑定），不新建第二个 |
| 其余 | `started` | 启动值班并开一场开场 turn |

启动步骤：写 `watching/target/timer`、保留已有 `wake_mode`（群默认 `mention`、私聊默认
`all`）、固化 `send_mode`、按加入默认落 `workspace`、把 `duty` 记成 `watch / manual / user`
并清掉排队中的事件，保存后再 `turns.open()`。跨会话搜索命中的会话先做一次
`pollChat({ wake:false, handleCommands:false })` 补会话 / 水位，再用 `fetchThread` 取一次
原始最近消息当开场上下文——首次见到的会话会在 baseline 清空正文，不能让开场只剩一句
「没有新消息」；快车道里命中的直接用已经并入 `recent` 的消息。`turns.open()` 内部按 chat
串行且只认一个 `dsh_session`，再加 `dutyStarts` 锁，保证并发命令不会开出第二个。

启动失败不回滚 `watching`（与面板加入一致），只把 `command.result="failed"` 与原因写回，
下一次真实消息仍可唤醒。启动成功后不改 `cmd` 消息的 `state`，它仍是非待回指针；面板
「全部」里可见，但不会再交给 agent。

### 4. 开场载荷（`turns.buildOpenPrompt`）

`turns.open(chat, { reason:"command", dutyContext:{ command:{ keyword, msg_id, source } } })`。
`buildOpenPrompt` 识别 `dutyContext.command` 后：

- 标题写「值守已开启 · … · IM 指令启动（不是新消息唤醒）」；
- 不出现值守台的「值守判断 / 接手轮」话术；
- 明确「这条启动指令只负责打开值守，不要为它往会话里发消息；最近上下文里其它需要回的
  消息照常按 skill 处理」；
- 回复里仍不要 @ 本人自己（防回环）。

### 5. 面板

设置页新增「IM 启动指令」卡片：启用开关、关键词输入、保存，并显示最近一次跨会话扫描
（读多少条 / 命中多少 / 启动几个 / 失败原因）；说明即时范围与飞书每分钟搜索范围，以及
「同一会话已有值班时不会重复创建」。会话详情在 `chats[].command.result` 非空时显示最近
一次结果（`started` / `already` / `blocked` / `failed` + 原因），失败用错误色。

### 6. 数据形状（契约 02）

```json
"command": {
  "at": 0,
  "keyword": "",
  "msg_id": "",
  "result": "",
  "reason": ""
}
```

`result` 枚举：`""` / `starting` / `started` / `already` / `blocked` / `failed`；
`reason` 单行 ≤160 字；老 state 缺字段时补默认，不升 `STATE_VERSION`，不改变存量行为。

## 取舍

| 备选 | 否掉的理由 |
| --- | --- |
| 把启动指令交给 agent 执行 | 需要先唤醒一轮再让 agent 调 API，命令本身还花 token；开关应由插件确定性执行，agent 只处理业务消息 |
| 只认已值守会话 | 用户明确要「不论何时何地」；飞书一条跨会话搜索已能覆盖未值守私聊 / 群，成本是每分钟 1 次 |
| 逐会话轮询未值守聊天 | 会把 IM 接口当靶子打，违反拉取成本模型；搜索只取「本人发送 + @本人」的窄结果，关键词在本地过滤 |
| 同一会话允许再开一个会话 | 同一 `platform:chat_id` 键与 `dsh_session` 单值本来就只能有一个；再开会让两条 turn 抢同一会话，必须拒绝 |
| 已有值班时也把关键词消息交给 agent | 用户会看到 agent 对「启动」这条开关本身回话，群里尤其吵；消费掉并在面板显示冲突更可控 |
| 命中后自动回一条「已启动」 | 自动对外发言不在本次授权内；面板状态足够，用户不需要在群里制造一条噪音 |
| 关键词出现即触发，不要求是整句 | 自 @ 本身已是显式动作；要求严格前缀会挡住「@我自己 启动值班」这类自然写法 |

- [x] 未值守私聊里同样消息 → `watching/timer/target` 写入，`send_mode` 固化，起一场开场
      turn，不额外唤醒（同上）。

- [x] 不带关键词的自 @ → 仍是 `cmd` 并唤醒；关掉指令或换关键词后旧词不再触发
      （同上）。
- [x] 只读拉取（`wake=false`）看到启动指令 → 不启动、不建会话；正常轮询才消费（同上）。

## 风险与回滚

- 风险：关键词选得太宽（如「我」「在」）会让普通自 @ 消息被当成启动指令，反而不会交给
  agent。设置页说明关键词应短而明确；改宽后旧词立即失效，无需迁移。
- 风险：飞书搜索接口的 `--at-chatter-ids` 只证明了能筛「@本人」，不能证明所有自 @ 形态都
  返回；搜不到时用户仍可在面板加入。即时路径不依赖搜索。
- 风险：启动与分诊同时进行时，陈旧的分诊决策可能想把刚启动的群关掉。启动时清空
  `duty.event_id` 并把状态记成 `watch/manual/user`；`finishTriage` 看到用户已手动接管就
  不再应用该决策。
- 风险：飞书搜索每分钟一次（约 1440 次/天，只取一页），结果含正文但只在本地过滤，不写日志、不上传。
- 回滚：`command.enabled=false` 立即回到纯 `cmd` 行为；代码回滚只需撤掉识别 / 扫描分支，
  `chats[].command` 与 `config.command` 是新增字段，旧版忽略即可，不需要清理 state。

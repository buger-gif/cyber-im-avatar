# 0038 外来轮次打断与 turn 日志

> 状态: 待实施
> 编号: 0038
> 版本: 0.18.0
> 关联: `docs/specs/contracts/01-api.md`、`docs/specs/contracts/02-storage.md`、
> `docs/specs/active/0034-单轮停滞超时.md`、`dsh-plugin/lib/turns.js`

## 背景

2026-11-06 15:01–15:09，一个值守群的 @ 消息在 turn 里等了 7 分 47 秒。DSH 会话日志
（`session.v4.jsonl.zstd`）给出的现场：

| 时刻 | 事件 |
| --- | --- |
| 15:01:29 | 人在 DSH 会话里直接发消息（`source.kind=user`、带 `rpcId`，不是插件） |
| 15:01:41 | 该消息起 turn 4 |
| 15:03:06 | 群里 @ 到达，插件 `wake` 把载荷放进 `next-turn`，**没有打断 turn 4** |
| 15:03:27 | 队列项被 `queue action=steer`（面板动作）移进 `next-step`；15:03:35 才被消费 |
| 15:09:28 | turn 4 结束。没人手动插队的话，@ 要等到这时 |
| 15:19:28 | 插件对该轮误报 `timeout`（`last_turn={ok:false,reason:"timeout"}`），其实 15:03:35 就已送达 |

同一时段另一通会话里，插件自己起的 turn 在 15:01:52 被正常打断
（`turn/end reason={kind:"aborted",reason:{kind:"user"}}`）并立刻起新轮——打断机制本身没坏，
**只覆盖插件自己起的轮次**。

衍生问题：

- 载荷被别人 `steer` 进已经在跑的轮次后，插件挂监听晚于该轮 `turn/start`，
  `turnStarted` 永远是 false，收不到 `turn/end`；看门狗又在事件断流 `dsh.timeout` 后才触发，
  于是消息其实已送达、插件仍显示处理中，最后误报 `timeout`。
- turn 生命周期没有落盘日志；面板「最近错误」只收轮询/身份/回执错误，重启即空。
  出问题只能翻 DSH 的 zstd 会话日志反推。

## 目标与非目标

- 目标：真实唤醒到达时，**绑定会话里正在跑的任何 turn 都被打断**——不管是插件起的，
  还是人在 DSH 面板里直接发消息、goal / 定时任务起的。
- 目标：载荷被 `steer` 进已在跑的轮次时，`runTurn` 能把它认作本轮并正常收口，不再误报超时。
- 目标：停滞看门狗只统计「本轮载荷已进会话」之后的事件；载荷还排在队里时不能靠别人的
  轮次续命。
- 目标：turn 生命周期事件（唤醒 / 打断 / 送达 / 进入会话 / 结束 / 失败）落盘，
  面板体检页可看；**不记消息正文、不记发送者**。
- 非目标：不改「加入值守即开会话」不打断在飞轮次的语义（spec 0025）。
- 非目标：不把插件自动改成 `steer`；外部队列的 edit / remove / steer 行为不改。
- 非目标：不改 DSH `agent.cancel` 的 cause（仍是 `{kind:"user"}`）。
- 非目标：不改 `state.json` 字段、不加配置键、不改轮询节奏。

## 方案

### 1. 打断外来轮次（`dsh-plugin/lib/turns.js`）

`wake()` 记下 `hadActive = !!this.active.get(key)`，再调用 `_wake(chat, { hadActive, ... })`。
`_wake()` 在 `resolveSession()` 拿到 live agent 之后、下载媒体之前：

```js
if (!opening && agent.status === "running") {
  /* 本插件没记着这一轮 = 人 / goal / 定时任务起的 */
  try { agent.cancel({ kind: "user" }, { keepInbox: true }); } catch { /* best effort */ }
  if (!hadActive) interrupted = true;   // 首轮载荷带「上一轮被打断」提示
}
```

- `opening`（加入值守开场）不打断，保持 spec 0025。
- `hadActive` 为 true 时旧轮已在 `wake()` 里 cancel 过；这里再 cancel 一次是幂等的，
  只补日志，不改 `interrupted`。
- 取消后立即 `followup`：DSH 的 `send()` 看到 abort 已置位，会把消息放进 `next-turn`
  并置 `wakeRequested`，abort 收尾后立刻起新轮——不排队等旧轮跑完。

### 2. 轮次关联与看门狗（`dsh-plugin/lib/turns.js`）

- `user/message` 命中本轮 `promptId` 且此前没见到 `turn/start`（`lastTurnStart == null`，
  即监听挂晚、载荷被 steer 进旧轮）：`turnStarted = true`、`turnNumber = null`（认作当前
  唯一在跑的轮）；`turn/end` 在 `turnNumber == null` 时不再比对轮号。
- 看门狗 `touch()` 只在 `promptSeen` 为 true 后调用。载荷还没进会话时，同会话其它事件不算
  本轮活动；这样「排队等待」会按 `dsh.timeout` 正常兜底，不会永远挂着。
- 0034 的「每个 `session/event` 都 touch」收窄为「本轮载荷消费后的每个事件」。

### 3. turn 事件日志（新增 `dsh-plugin/lib/turn-log.js`）

`~/.im-standin/logs/turns.jsonl`（目录 0700、文件 0600），JSON Lines，单行一个事件：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `ts` | number | epoch 秒 |
| `event` | string | `wake` / `open` / `warm` / `cancel` / `followup` / `prompt_seen` / `turn_end` / `warm_end` / `wake_failed` |
| `platform` | string | `feishu` / `wecom` / `dingtalk` |
| `chat_id` | string | 平台会话 ID（面板据此映射会话名；不记名字） |
| `turn_id` | string | 插件本轮 UUID；外来轮次取消时为空 |
| `owner` | string | `cancel` 专用：`plugin` / `foreign` |
| `reason` | string | 取消原因或失败原因 |
| `count` | number | `wake` 本批消息条数 |
| `interrupted` | bool | `wake` 是否打断了在飞轮 |
| `wait_ms` | number | `prompt_seen` 从 `followup` 到载荷进会话的耗时 |
| `ms` | number | `turn_end` 本轮耗时 |
| `ok` | bool | `turn_end` 结果 |

- 环形内存 200 条同步保留，启动时从文件尾部预载 200 条；写失败只静默（`failed=true`），
  不影响 turn。
- 轮转：文件超过 512 KiB 时把当前文件改名为 `turns.1.jsonl`，旧 `.1` 覆盖；
  最多两个文件。
- 不写消息正文、发送者 ID / 名字、聊天名。

### 4. 接口与面板

- `GET /api/logs` 增加 `events`：`turnLog.recent(80)`，最新在前。
  `errors` / `turns` / `sends` 形状不变。
- 面板「体检」页在「最近错误」上方加「最近事件」卡片：时间 · 平台 · 会话名（按
  `status.instances` 映射，取不到显示 ID 后 6 位）· 事件中文名 · 关键字段。
  切到体检页、点刷新、打开面板时拉一次 `/api/logs`；不跟 60 秒轮询。
- 改 `web/panel.js` 后跑 `python3 scripts/build_client.py` 重建 `lib/client.js`。

## 取舍

| 备选 | 否掉的理由 |
| --- | --- |
| 外来轮次用 `agent.steer`，不打断 | 用户 15:03 手动 steer 过，但那只是解一时；值守语义是「新消息到就以最新为准」，排队/插队都会让 agent 在旧上下文里继续跑 |
| 只在 `wake()` 里检查 `active`，不查 `agent.status` | 正是现在的 bug：`active` 只记插件自己的轮 |
| 保留「所有会话事件都 touch」 | 排队时会被别人的轮续命，消息明明没进会话却永不超时 |
| 事件日志写 `state.json` | state 是快照契约，按秒级事件写会把文件撑大且每次全量原子写；独立 JSONL 更适合流水 |
| 日志记聊天名/发送者 | 本地也没有必要；排障只需要会话 ID 与事件时序，少一份个人信息 |
| 日志按天分文件 | 当前量级（每个 turn 5–8 行）按大小轮转更简单，不引入清理任务 |

## 风险与回滚

- 风险：真实消息会打断人在 DSH 面板里的手动轮次，正在跑的活会丢；这是「以最新消息为准」
  的直接代价。若实际使用中不能接受，改成 `steer` 只需改 `_wake()` 一处。
- 风险：日志目录写失败（磁盘只读等）→ 只影响日志，不影响值守；`TurnLog` 静默降级。
- 回滚：revert 本 commit；`logs/` 可直接删除，state 无迁移。

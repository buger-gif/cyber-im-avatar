# 0044 分诊值班跟随加入工作区

> 状态: 实施中
> 编号: 0044
> 版本: 0.19.0
> 关联: `docs/specs/contracts/03-config.md`、spec 0040（值守分诊）

## 背景

手动「加入值守」时，面板「加入值守时绑定工作区」决定这通值班落在哪个工作区：
面板记忆 → 最近在用的工作区 → DSH 默认；选中值会写进 `chats[].workspace`，
会话按它创建，之后轮换 / 重开也沿用。

自动分诊判定 `watch` / `trial` 后，插件在 `duty.applyDecision()` 里直接
`turns.open()` 开首个值班会话。新群 `chats[].workspace` 为空，于是总是落到 DSH 默认
工作区——与手动加入的结果不一致。用户明确要求：自动分诊创建的值班也要跟随页面上
「加入值守时绑定工作区」的配置。

面板的选择当前只存在浏览器 `localStorage`（`ims_add_workspace`），后端读不到；
所以“分诊跟随页面配置”必须先把这个选择持久化到插件配置里。

## 目标与非目标

- 目标：自动分诊创建的 watch / trial 值班，与手动加入使用同一套工作区默认，并把结果
  落成 `chats[].workspace` 显式绑定；之后会话轮换 / 重开沿用。
- 非目标：不改手动加入的交互与顺序；不改值守台私有 cwd；不为每个群自动创建工作区；
  不改变 `/api/workspaces` 的登记表。

## 方案

### 1. 新配置键 `join_workspace`

`DEFAULT_CONFIG.join_workspace = ""`（string）。

- 语义：面板「加入值守时绑定工作区」选择值的持久化副本。
- `""` = 没有显式选择：按「最近在用 → DSH 默认」推断。
- 非空必须是存在的绝对路径；面板变更 / 加入成功后写入，清空选择时写回 `""`。
- `POST /api/config` 校验：非空路径必须 `workspaces.normalize()` 通过，否则拒绝整次保存；
  `normalizeConfig()` 只做类型归一（非 string → `""`），不碰文件系统。

### 2. 后端默认工作区解析

`workspaces.resolveJoinDefault(chats, config)`：

1. `normalize(config.join_workspace)` 非空 → 用它；
2. 否则 `lastUsedPath(chats)`：与面板 `lastUsedWs()` 同口径，从有 `workspace` 的会话里取
   `session_bound_at || added_at || last_sync` 最大者的工作区；
3. 都没有 → `""`（跟随 DSH 默认）。

`duty.applyDecision()` 在 `firstOpen` 且 `chat.workspace` 为空时，把解析结果写入
`chat.workspace`（非空才写）后再 `state.save()` / `turns.open()`；已有的显式绑定不覆盖。
判断仍归 agent，插件只按确定规则落工作区。

### 3. 面板

- `joinWorkspace()` 顺序改为：面板记忆 → `config.join_workspace` → 最近在用 → DSH 默认。
  `loadChats()` 自动补记忆时同样优先 `config.join_workspace`，不再直接取最近在用。
- 面板里改「加入值守时绑定工作区」、加入成功、切换会话工作区时，把选择同步到
  `POST /api/config`（`{join_workspace: <路径或 "">}`），后端与页面保持一致。
- 显式选「跟随 DSH 默认」会清空后端记忆（写 `""`），下一次分诊回到最近在用 / DSH 默认。

### 4. 契约

`docs/specs/contracts/03-config.md` 增加 `join_workspace` 行（默认 `""`，无夹取范围）。

## 取舍

| 备选 | 否掉的理由 |
| --- | --- |
| 分诊时只给 `turns.open()` 传临时 cwd，不写 `chats[].workspace` | 面板仍显示「跟随 DSH 默认」，下次轮换 / 重开又回默认，与手动加入不一致 |
| 读浏览器 `localStorage` 或让分诊走面板 | 分诊在宿主进程里跑，读不到浏览器存储；拉浏览器参与违反“判断与执行分离” |
| 自动分诊也建独立工作区目录 | 越权造目录；工作区选择器被污染；实际只需要一个默认绑定 |
| 只在 `watch` 生效、`trial` 不生效 | 试用期同样要读项目上下文，行为应一致 |
| 复用 `dsh` / `duty` 下的配置键 | 该值同时服务手动加入与自动分诊，放顶层与 `send_mode_default` 同级更直白 |

## 影响面

- 代码：`dsh-plugin/lib/state.js`、`lib/workspaces.js`、`lib/app.js`、`lib/duty.js`、
  `web/panel.js`（构建产物 `lib/client.js`）。
- 契约：`docs/specs/contracts/03-config.md`。
- 用户可见：自动分诊判定 watch / trial 后，面板会话卡片会显示绑定的工作区
  （不再一律「默认」）；页面上的「加入值守时绑定工作区」刷新后由配置恢复。
- 兼容：老 `state.json` 无 `join_workspace` 时补 `""`，不升 `STATE_VERSION`；但行为会变：
  无显式配置时，自动值班优先跟随“最近在用”的工作区（这是本次需求本身）。

## 验收

- [ ] 单测：`config.join_workspace=<存在的目录>` 时，`applyDecision(watch)` 后
  `chat.workspace` 等于该目录，`turns.open()` 拿到的会话对象也是同一绑定。
- [ ] 单测：`join_workspace=""` 且有更早绑定过工作区的会话时，回退到“最近在用”。
- [ ] 单测：`join_workspace=""` 且没有任何绑定过工作区的会话时，`chat.workspace` 保持空
  （跟随 DSH 默认），不凭空绑定。
- [ ] 单测：已有 `chat.workspace` 不被分诊覆盖。
- [ ] `POST /api/config {join_workspace:"/不存在"}` 被拒绝，配置保持原值。
- [ ] 面板：改了「加入值守时绑定工作区」后刷新面板，下拉仍显示该值；
  `curl /api/config` 能看到 `join_workspace`。
- [ ] `cd dsh-plugin && node --test`、`python3 tests/test_docs.py`、`bash scripts/gate.sh --quick`
  全绿；`lib/client.js` 与 `web/panel.js` 构建一致。

## 风险与回滚

- 风险：用户没显式选过工作区时，自动值班可能绑到“最近在用”的目录而不是 DSH 默认；
  该目录后来被删时按现有 `workspace_missing` 处理，面板可改绑。
- 回滚：撤本次 commit 恢复旧逻辑；已写下的 `chats[].workspace` 由用户在面板切回
  「跟随 DSH 默认」即可，不需要清 state。

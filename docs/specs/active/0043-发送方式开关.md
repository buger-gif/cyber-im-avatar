# 0043 发送方式：值班单点 + 新建默认

> 状态: 实施中
> 编号: 0043
> 版本: 0.19.0
> 关联: `docs/specs/contracts/01-api.md`、`docs/specs/contracts/02-storage.md`、
> `docs/specs/contracts/03-config.md`、
> `docs/decisions/implemented/0013-发送策略由用户显式设定.md`

## 背景

发送方式（草稿审批 / 全自动）原来靠用户和 agent 在值守会话里口头约定：

- 默认草稿审批：agent 把回复留在 DSH 会话里，用户说「发」才发；
- 全自动：用户在某条 DSH 会话里说「以后这个人的消息直接回」，agent 记住。

问题有三个，都是实际使用里反复出现的：

1. **会话会换，约定会丢。** 闲置重开、手动重开会话、工作区变更都会换新 DSH 会话；
   新会话里 agent 不知道旧约定，于是重新问「要发吗 / 还是以后都直接发？」。
2. **同一句话在不同会话里打架。** 有的会话记住了全自动，有的默认草稿；用户在同一时间
   面对两种行为，无法从面板判断当前策略。
3. **「每条都问」不 ai native。** 发送策略是环境配置，不应该由每轮 agent 临场询问。

第一次实现做成了**全局开关**，但用户明确纠正：发送方式属于**值班单点配置**，每个值守
会话各自一档；全局只提供「新建值守时的默认值」。用户自己的默认是全自动。也就是说：

- 已经值守的会话各自保留自己的发送方式，改全局默认不覆盖它们；
- 新加入值守时才复制当时的全局默认；
- 每个值班卡片/详情都能单独切，不需要回到设置页改全局。

0004 曾删掉插件侧 `auto_send` 开关（起草管道归 agent），0006 也明确「不绕过 skill 的确认
铁律」。本次不恢复插件起草/审批队列，只把**值班单点的发送策略**持久化并随每轮载荷交给
agent——判断内容仍归 agent，策略选择归用户，插件不解析正文。

## 目标与非目标

- 目标：每个值守会话有一个独立的 `send_mode`；面板「分身」卡片和会话详情可直接切；
  设置页提供「新建值守默认发送方式」，新值班首次加入时复制该值。之后改默认不覆盖已有值班。
- 非目标：
  - 不做插件侧草稿箱/审批队列，不存、不解析、不代发消息正文；
  - 不做「跟随全局默认」的动态继承：默认只在新建时生效，用户明确要求；
  - 不做 per-message 的发送确认流，不恢复 0003 的回复模式；
  - 不做插件侧内容风险闸门（金额/合同/承诺仍由 skill 铁律判断，插件不读正文）；
  - 不改面板手动发送（手打即本人，永远可用）；
  - 不改 skill 独立形态的配置（独立形态没有面板，仍默认草稿审批）。

## 方案

### 1. 配置：全局默认 `send_mode_default`

`~/.im-standin/state.json` 的 `config`：

```json
{ "send_mode_default": "draft" }
```

| 值 | 含义 |
| --- | --- |
| `"draft"` | 新建值守默认草稿审批（仓库默认，保守） |
| `"auto"` | 新建值守默认全自动 |

- 只决定**之后首次加入值守**的会话；已有值班的 `chats[].send_mode` 不受影响。
- `normalizeConfig()` 只接受这两个值；缺省、非法、老 state 一律回 `"draft"`。
- 未发布时的临时全局键 `send_mode` 若存在且新键缺省，迁成 `send_mode_default` 后丢弃。

### 2. 数据：每个值班 `chats[].send_mode`

```json
{ "send_mode": "" }
```

| 值 | 含义 |
| --- | --- |
| `""` | 还没单独设过；首次加入值守时固化为当时的 `send_mode_default` |
| `"draft"` | 这通值班草稿审批 |
| `"auto"` | 这通值班全自动 |

- 新 chat 对象默认 `""`；`/api/watch`、`/api/chat/mode` 开启值守、值守台 watch 决策时，
  若仍为空则复制当前 `send_mode_default` 成显式值。
- 存量已值守会话加载时：没有 `send_mode` 的按旧全局值（未发布时）/当前默认补齐；
  未值守会话保持 `""`，等首次加入值守再取默认。
- 显式值之后不随全局默认变化；用户切「不盯」再重新加入也不重置。
- 不升 `STATE_VERSION`：字段有默认值，未值守会话行为不变。

契约同步：`docs/specs/contracts/02-storage.md`。

### 3. 接口

- `POST /api/chat/send-mode`：`{platform, chat_id, mode}` → 写 `chats[].send_mode`，
  返回 `{ok, send_mode, chat}`；`mode` 只接受 `draft` / `auto`，会话不存在回 `not_found`。
- `POST /api/config`：写 `send_mode_default`；只影响之后新加入的值守。
- `GET /api/chats` / `GET /api/status`：会话行透出实际生效的 `send_mode`；配置透出
  `send_mode_default`。

契约同步：`docs/specs/contracts/01-api.md`、`docs/specs/contracts/03-config.md`。

### 4. 载荷：每轮声明实际生效值

`buildWakePrompt()` / `buildOpenPrompt()` 的 `sendMode` 由 `Turns._wake()` 传入：

```
sendMode = chat.send_mode || config.send_mode_default || "draft"
```

每次唤醒、每次开场都追加一行；`buildWarmPrompt()`（心跳）与 `buildDeskPrompt()`（值守台）
原有「不要发消息」边界不变，不注入发送方式。

- **草稿审批**：
  `发送方式：草稿审批（插件当前设置；只由面板开关决定，口头约定不改模式，要改请用户点面板「发送方式」）。`
  正文留在会话里，末尾另起一行「草稿待确认」；不要自己发，也不要反问「要不要发」。
- **全自动**：
  `发送方式：全自动（插件当前设置；只由面板开关决定，口头约定不改模式，要改请用户点面板「发送方式」）。`
  本轮该回的按 skill 以本人身份直接发出，不要征求确认；发完在本会话里只回一行结果，
  不要把执行结果再发到 IM。
- 两种模式都保留边界：
  - 只改变「发送动作」，不改变唤醒范围（群全量模式下非点名消息仍只看不回）；
  - 钱、合同、对外承诺、权限/凭据、外部群等敏感内容一律停下等用户确认；
  - 用户在本会话里当轮明确说「先别发」时，以当轮指令为准。

### 5. 面板

- **每个值班单点**：「分身」页每张值守卡片、会话详情都放两段开关（草稿审批 / 全自动），
  即时写 `/api/chat/send-mode`；卡片上同时显示当前档位的说明。
- **新建默认**：「设置」页一张「新建值守默认发送方式」卡片，写 `send_mode_default`；
  文案明确「只影响之后新加入值守的会话，已有值班不受影响」。
- 切到「全自动」时弹一次确认（单点与默认各一次）；切回草稿审批不弹。
- 控件即时保存，成功后更新本地对象并重绘；失败 toast 原因，不假装保存成功。
- 顶部不再显示全局「自动」标签，避免把新建默认误读成当前所有值班的状态。

### 6. skill 文案

`SKILL.md` 的「DSH 插件壳」段与铁律补一条：发送方式以载荷声明为准，覆盖会话历史里的旧约定；
插件形态下口头约定不改模式，要改让用户点面板；插件载荷没有这行时默认草稿审批。
`references/troubleshooting.md` 的「人工确认」同步改口径。

## 取舍

| 备选 | 否掉的理由 |
| --- | --- |
| 只做全局开关 | 用户要的是值班单点：不同客户/群本来就需要不同节奏；全局开关会把一个会话的选择带到所有会话 |
| 动态「跟随全局默认」 | 用户明确「默认是新建的时候的默认状态」；改默认不应回头覆盖已有值班。要改单点就明确点那一下 |
| 每个值班各自设，不给全局默认 | 每加一个值班都要多点一次；默认值解决新建时的重复操作 |
| 插件做草稿箱 + 面板审批 | 要存消息正文、解析 agent 输出，违背「插件只做确定性搬运」；0004 已因两套脑子漂移删过一次 |
| 复用退役键 `reply` | `reply.*` 是 0003 起草管道的遗产，语义会被误读；`send_mode` 更窄 |
| 全自动也由插件做风险闸门 | 插件不读正文，关键词闸门会误伤且与 skill 铁律长两套；边界留给 skill |
| 仓库默认全自动 | 以本人身份外发是高风险动作；代码默认必须保守，个人可以在设置里把新建默认改成 auto |
| 只在首轮载荷声明 | 模式可能中途切换；每轮都带一行才能覆盖旧约定，成本约一行文本 |

## 风险与回滚

- 风险：某个值班被切成全自动后误发。缓解：单点开关只影响该会话；切全自动二次确认；
  每轮载荷声明风险边界；敏感内容仍停下；随时可切回草稿审批。插件不做正文级闸门，这是有意的边界。
- 风险：agent 仍按旧会话里的口头约定执行。缓解：载荷明确「口头约定不改模式」，
  且每轮都带。
- 回滚：把值班切回「草稿审批」即可；删掉 `chats[].send_mode` 会回落到 `send_mode_default`。
  无需清库、无需迁移；未发布旧键会自动迁。

# 0048 启动值守后回一条回执

> 状态: 实施中
> 编号: 0048
> 版本: 0.21.0
> 关联: `docs/specs/contracts/01-api.md`、`docs/specs/contracts/02-storage.md`、
> `docs/specs/contracts/03-config.md`、`docs/specs/active/0046-自at关键词启动值班.md`

## 背景

0046 把「本人 @ 自己 + 关键词」做成了当前会话的确定性启动开关，但把「命中后自动回一条
『已启动』」明确列进非目标，理由是自动对外发言没授权、面板状态足够。用户在真机上要的正好
相反：在群里 @ 自己发「启动」之后，会话里要有人看得见的一句回执，告诉成员这个分身默认
24 小时值班、上线 @ 一下就能唤起。0046 的启动结果目前只落在 `chats[].command.result`，
群成员在 IM 里看不到任何变化。

## 目标与非目标

- 目标：启动指令**真正拉起一场新值班**（`result=started`）后，在该会话回一条纯文本回执；
  群聊与私聊都发。
- 目标：回执文案可在设置页改、可整体关闭；默认就是用户给的那句
  「支持用户自定义，默认就是 24 小时值班，上线 @ 我即可触发。」。
- 目标：发送失败不回滚值班，只把失败原因记在 `chats[].command.reply`，面板可见。
- 非目标：`already`（已有值班）/ `blocked` / `failed` 不发；不做「停止 / 暂停」回执。
- 非目标：不做富文本、卡片、真实 @ 人；只发一条纯文本。
- 非目标：不改 agent 开场 turn 的口径——回执由插件确定性发出，agent 仍然不要为启动指令发言。
- 非目标：不做按会话 / 按人区分文案；同一条文案发到所有启动成功的会话。

## 方案

### 1. 配置（契约 03）

```json
"command": {
  "enabled": true,
  "start_keyword": "启动",
  "reply_enabled": true,
  "reply_text": "支持用户自定义，默认就是 24 小时值班，上线 @ 我即可触发。"
}
```

- `reply_enabled`：默认 `true`；只有显式 `false / 0 / "false" / "off"` 才算关。
- `reply_text`：默认用户给的那句；去控制字符、压缩空白、最多 200 个字符；**空串 = 不发**。
- `POST /api/config` 合并 `command` 子对象；超长整次拒绝，不静默截断；`reply_enabled=true`
  配空文案不报错（等价于关），避免「想清空文案还得先关开关」。
- 归一化以 `DEFAULT_CONFIG.command` 兜底：老 state 里的 `command` 只有两个键时，合并后
  自动补上回执两键，存量配置升级后默认开启。

### 2. 发送（`poller.startDutyFromCommand`）

- 只在 `turns.open()` 成功、写完 `command.result=started` 之后发；`already / blocked /
  failed` 分支不经过发送。
- 通路复用 `im.adapter(platform).sendText(chat.chat_id, text)`（与面板手动发送同一条 CLI），
  平台差异留在 adapter；不新增依赖、不碰模型。
- 发送结果写 `chats[].command.reply`：
  ```json
  "reply": { "at": 0, "ok": false, "msg_id": "", "error": "" }
  ```
  `at=0` 表示没发过；`ok` 是最后一次尝试是否成功；`error` 单行 ≤160 字。
- 失败只 `logger.warn`，`command.result` 保持 `started`，`watching` 不回滚。
- `writeCommand()` 重写 `command` 时保留 `reply`，避免下一条 `already` 把上次回执记录抹掉。
- 同一 `msg_id` 幂等早退不重发；同一会话的并发启动由 `dutyStarts` 锁挡住，不会发两条。

### 3. 面板

- 设置页「IM 启动指令」卡片加一行：回执开关 + 文案输入（≤200 字），随「保存指令」一起提交。
- 会话详情在 `command.reply.at > 0` 时显示「启动回执：已发 / 发送失败 · 原因 · 时间」。
- 卡片说明补一句：只在真正拉起新值班时发；已有值班不重复发。

## 取舍

| 备选 | 否掉的理由 |
| --- | --- |
| 交给 agent 在开场 turn 里发 | 会被模型改写、要花一轮 token，且开场轮还在拉上下文；回执要求一字不差，插件确定性发更合适 |
| `already` 也回 | 用户要的是「启动」那一下；已有值班再发会在群里刷屏，当前只记冲突 |
| 只在群聊发 | 用户明确要私聊也发；私聊里同样有「告诉对方怎么唤起」的价值 |
| 默认关 | 用户要的就是发；触发是本人显式动作，不是替用户回复别人 |
| 发送失败回滚 `watching` | 与面板「加入值守」一致：值班已经起来，失败只是少一句话 |
| 文案写死在代码里 | 不同群的口径不同，设置页可改才不用为一句文案发版 |

## 验收

- [ ] 未值守私聊里 @ 自己 + 「启动」→ 该私聊收到与配置一致的文案，
      `command.result=started`、`command.reply.ok=true`（`tests/poller.test.mjs`）。
- [ ] 未值守群里同样操作 → 群收到同一条文案（同上）。
- [ ] 已值守会话再发「启动」→ `already`，不再发第二条（同上）。
- [ ] 关掉回执或文案留空 → 只启动、不发送（同上）。
- [ ] 发送失败 → `result=started`、`reply.ok=false` + 原因，`watching` 仍在（同上）。
- [ ] 设置页保存回执开关与文案 → 读回一致；文案超长整次拒绝（`tests/app.test.mjs`）。
- [ ] 纯函数：`replyText` 压缩空白、去控制字符、封顶 200 字，`replyEnabled` 只认显式关闭
      （`tests/command.test.mjs`）。
- [ ] `node --test`、`python3 tests/run_tests.py`、`bash scripts/gate.sh --quick` 全绿。
- [ ] 真机（用户）：在一个没值守的飞书群 @ 自己 + 「启动」，群里出现这句回执，
      面板显示「已发」。

## 风险与回滚

- 风险：默认开，用户升级后第一次「启动」会在会话里多一条消息，可能被群成员读成客服承诺；
  文案里「24 小时」与独立 skill 形态的 3 小时闲置退出不一致。
- 回滚：设置页关掉「启动后回一条」即可，无需改数据；代码层撤 commit 后
  `chats[].command.reply` 字段留着不读不写，不影响旧版。

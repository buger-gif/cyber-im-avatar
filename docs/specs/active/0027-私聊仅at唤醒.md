# 0027 私聊仅 @ 唤醒

> 状态: 实施中
> 编号: 0027
> 版本: 0.13.0
> 关联: `docs/specs/contracts/01-api.md`、`docs/specs/contracts/02-storage.md`

## 背景

「关注程度」目前只有群有：`chats[].wake_mode` 的 `mention` / `all` 只对 `kind=group` 生效
（`dsh-plugin/lib/poller.js` 的 `process()` 里私聊恒为 `dm`），面板私聊卡片也只有「值守」开关。
结果是私聊里**每一条**新消息都唤醒 agent：寒暄、通知、转发、「收到」各起一轮 live turn，
既花 token，也让 agent 有机会对不必回的话做反应。

群聊已经有一档三态（不盯 / 只盯 @我 / 全部消息，spec 0024）。用户要的是同一口径落到私聊：
**对方 @ 我时才唤醒 agent，其它消息只记知会**。

## 目标与非目标

- 目标：私聊可选「只盯 @我」。非 @ 消息只进本地最近 10 条、记 `fyi` / `ignored`，不唤醒、
  不算待回、不进唤醒批次；@ 的消息照常唤醒。
- 目标：存量私聊升级后行为不变（仍是每条都唤醒），面板能随时切回「全部消息」。
- 非目标：不改群的默认值与合并窗口；不改快慢车道（私聊仍按 `poll.fast_sec` 拉，否则发现不了 @）；
  不改「加入即开会话」与开场轮。
- 非目标：不做关键词触发。skill 形态的 `--keyword` 是子串匹配，`--keyword "@张三"` 已经能做
  同样的事，本次不动 `dsh-plugin/skill/scripts/`，也不新增配置键。
- 非目标：不替用户判断「什么算闲聊」——只做确定性的 @ 判定，判断与维护归 agent 和用户。

## 方案

### 1. 字段口径（`state.json` → `chats[].wake_mode`）

| 会话 | `mention` | `all` | 默认 |
| --- | --- | --- | --- |
| 群 | 只有 @ 我进批次（现状） | 非 @ 也进批次、只看不回（现状） | `mention` |
| 私聊 | **新增**：只有 @ 我唤醒；其它记知会 | 每条新消息都唤醒（现状） | `all` |

- `state.version` 1 → 2。加载 version 1 的 state 时，把 `kind=p2p` 的 `wake_mode` 一次性
  改成 `all`：老数据里私聊的 `mention` 只是「群策略」的默认值，对私聊没有语义；不改会把
  存量私聊静默变成只认 @。迁移在内存里完成，下一次落盘写回 `version: 2`。
- `normalizeChat()` 的默认值改成按 kind 取；`/api/watch` 加入的私聊不带 `wake_mode`，
  自然落到 `all`。群加入仍默认 `mention`（spec 0024 的口径不变）。

### 2. 判定（`poller.process()`）

私聊且 `wake_mode=mention` 时：

- `isMention(msg, self_id, self_names)` 为真 → `kind=dm`、`state=new`，进唤醒批次；
- 为假 → `kind=fyi`、`state=ignored`，正文照旧不落盘，不算待回、不进批次。

@ 的口径与群共用 `isMention`：
1. 有结构化 `mentions`：按本人 `open_id` / `user_id` / `union_id` / `key` 精确匹配，不按名字子串；
2. 没有 `mentions`：正文按词边界匹配 `@` + 本人显示名（`whoami` 的 `userName`，含去括号的简称）。

私聊里被 @ 的消息仍记 `kind=dm`，不改记 `mention`：否则它会从面板「私聊」筛选里消失，
而「这条是 @ 才唤醒的」已由唤醒本身证明。

### 3. 不提供会静默失效的开关

企微适配层没有 `mentions`，`whoami` 也只给 Bot ID、拿不到本人显示名（`references/wecom.md`），
只认 @ 在这条通路上永远不触发。适配器加能力位 `canMention`（`f_mentions || f_self_name`，
`env.json` 的 `overrides` 可扩展）：
- 为 false 时 `POST /api/chat/mode` 对 `mention` 返回 `{ok:false, reason:"…"}`；
- `/api/chats` 每条带 `mentionable`，面板把「只盯 @我」置灰并写明原因。

群的三态不动；企微群本来就识别不了 @，属既有已知限制（`dsh-plugin/README.md §已知限制`）。

### 4. 面板

- 私聊详情把「值守」开关换成与群相同的三态下拉：不盯 / 只盯 @我 / 全部消息。
  `chatModeOf()` 的「不盯」判定按 kind 区分（群看 `timer!==1`，私聊看 `timer===-1`）。
- 文案：私聊「只盯 @我」写清「对方 @ 你（或正文写 @你的名字）才唤醒；其它消息记知会」；
  切换后的 toast 按 kind 分开，不再说「不再拉这个群」。
- 改完 `web/panel.js` 跑 `python3 scripts/build_client.py` 重建 `lib/client.js`。

### 5. 唤醒载荷

`buildWakePrompt` / `buildOpenPrompt` 增加 kind：全量模式的「非点名的群消息只看不回」只对群
生效；私聊 `all` 不再被误标成群口径，私聊 `mention` 在载荷里带一句「只认 @：其它消息没有转给你，
需要上下文时按 skill 在线拉」。

## 取舍

| 备选 | 否掉的理由 |
| --- | --- |
| 全局开关（所有私聊一刀切） | 不同对象要不同口径；私聊名单常变，全局切换会误伤正在等回复的对象 |
| 新增独立字段 `dm_wake` | 同一概念两处存储，接口与面板都要分叉；用一次版本迁移承载语义扩展更省 |
| 私聊 @ 的消息记成 `kind=mention` | 会从「私聊」筛选里消失；私聊里 `dm` 更准确 |
| 私聊默认改「只认 @」 | 存量与新加入的私聊会突然不回，违反「迁移只放宽」 |
| 企微私聊也放开只认 @ | 拿不到 @ 信息，会装好却永远不动；明确拒绝比静默失效强 |

## 影响面

- 代码：`dsh-plugin/lib/state.js`（`version` 2、按 kind 的默认值、迁移）、`poller.js`
  （私聊 mention 判定、`canMention`）、`im.js`（能力位）、`app.js`（`chatMode`、`publicChat`）、
  `turns.js`（载荷口径）、`web/panel.js` 与构建产物 `lib/client.js`。
- 契约：`docs/specs/contracts/01-api.md`（`/api/chat/mode` 私聊可用、`/api/chats` 加
  `mentionable`）、`docs/specs/contracts/02-storage.md`（`version` 2、`wake_mode` 语义、迁移）。
- 用户可见：私聊详情出现「关注程度」；默认「全部消息」行为不变；切到「只盯 @我」后闲聊不唤醒。
- 兼容：老 `state.json`（version 1）加载即迁移；没有新配置键，老配置照常加载；降级回旧版
  时 `wake_mode=all` 对老代码无意义、不影响发送。

## 风险与回滚

- 风险：对方不知道要 @，只认 @ 的私聊会一直不唤醒。这是用户主动选的模式，面板有「全部消息」
  可立刻切回；知会记录与「待回」计数能看出它只是没叫醒。
- 风险：迁移把「历史上被程序设成 mention」的私聊改成 all——那正是升级前的实际行为。
- 回滚：撤销本轮 commit；已被写成 `version: 2` 的 state 旧版照常读（旧版不校验 version，
  私聊 `wake_mode=all` 对旧代码无意义），不需要清数据。

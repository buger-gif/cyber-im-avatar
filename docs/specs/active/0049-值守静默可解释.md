# 0049 值守静默可解释

> 状态: 实施中
> 待办: 重启插件后真机看一眼面板那行提示
> 编号: 0049
> 版本: 0.22.0
> 关联: `docs/specs/contracts/01-api.md`、`docs/specs/contracts/02-storage.md`

## 背景

「值守中」只说明每轮会拉这个会话，不说明拉到的消息会唤醒 agent。触发条件由
`chats[].wake_mode` 决定：`mention` 模式下只有 @ 我 才唤醒，其余消息落 `ignored`。

2026-11-17 现场：一个私聊设成 `mention` 后，对方连发 4 条（含一张图）都没有唤醒，
每轮 60 秒照常拉取、照常判成 `fyi/ignored`，界面上除了「值守中」没有任何信号。用户
直到对比原始消息的 `mentions` 才确认原因。

问题不在判定错，而在**判定结果不可解释**：`recent[]` 只存 `kind/state`，`ignored` 的
正文按隐私规则不落盘，面板也没有任何提示。同一份 state 里，`ignored` 可能是三种完全
不同的原因（首次基线 / 没 @ 我 / 你先自己回过了），事后无法区分。

## 目标与非目标

- 目标：让人不看代码就能回答「这条为什么没叫醒」。
- 非目标：不改任何唤醒判定本身；不落被忽略消息的正文；不新增接口路由。

## 方案

### 1. `recent[].skip`：判定时记原因

分类时给「不唤醒」的行写一个原因码，只枚举三种：

| 码 | 含义 |
| --- | --- |
| `baseline` | 首次建成基线，历史消息不算待回 |
| `no-mention` | 关注程度是「只盯 @我」，这条没 @ 到本人 |
| `you-replied` | 这条之后本人自己发过话，视为已处理 |

进唤醒批次的行 `skip` 为空串。写入点在 `Poller.process()` 的 state 判定分支，
`normalizeMessage()` 按白名单归一（未知值归空）。不升 `STATE_VERSION`：老数据缺键即空。

### 2. `GET /api/chats` 每行加 `silent` 汇总

```json
"silent": { "count": 3, "skip": "no-mention" }
```

`count` = 本地 `recent`（上限 10 条）里 `state=ignored` 且带 `skip` 的条数，**排除 `baseline`**
（刚加入值守时的历史消息本来就该忽略，报出来只是噪音）；`skip` = 其中出现最多的原因码，
没有就是空串。只做汇总，不返回正文。

### 3. `GET /api/thread` 的 items 带 `skip`

在线/本地两条路径都把行上的 `skip` 原样透出，前端不猜。

### 4. 面板

- 值守卡片：`silent.count > 0` 时加一行「最近 N 条没有唤醒：没 @ 你」。
- 会话详情：每条未唤醒消息的 meta 后面挂「· 未唤醒：没 @ 你」；
  原有的「只盯 @我」灰字提示保留，两者不重复时合并成一句。

## 取舍

| 备选 | 否掉的理由 |
| --- | --- |
| 存被忽略消息的正文，事后回看 | 违反「正文只在本机、且只在需要时留」的既有边界；本次只要原因 |
| 新增 `/api/why` 路由 | 现有 `/api/chats` 与 `/api/thread` 已经承载这些行，加字段即可 |
| 把原因做成自由文本 | 面板要按原因聚合成一句话，自由文本没法稳定归类 |

## 影响面

- 代码：`dsh-plugin/lib/{state,poller,app}.js`、`dsh-plugin/web/panel.js`、
  `dsh-plugin/lib/client.js`（重建）。
- 契约：`02-storage.md` 补 `recent[].skip`；`01-api.md` 补 `silent` 与 item 的 `skip`。
- 用户可见：面板值守卡片与会话详情多一行；旧数据不显示（`skip` 为空）。
- 兼容：只加可选字段，不升 `STATE_VERSION`，老版本读到会忽略。

- [x] 私聊设 `mention`，对方发一条不带 @ 的文本 → 该行 `state=ignored`、`skip=no-mention`。
- [ ] 同上会话写入面板 → 卡片出现「最近 1 条没有唤醒：没 @ 你」。（待重启后真机看一眼）

## 风险与回滚

- 风险：`silent.count` 只统计本地 10 条指针，长期静默的会话数字不会超过 10；
  文案必须写「最近」，不能写成总量。
- 回滚：撤掉 `skip` 的写入与两个字段即可，老 state 无需清理。

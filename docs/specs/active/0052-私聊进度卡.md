> 状态: 待实施
> 编号: 0052
> 版本: 0.25.0
> 关联: `docs/specs/contracts/01-api.md`、`docs/specs/contracts/02-storage.md`、
> `docs/specs/contracts/03-config.md`、`references/feishu.md`

## 背景

本项目的对外消息**全部由本人身份发出**：插件和 agent 都用
`lark-cli ... --as user`，没有机器人消息。用户要的是：别人私聊找他干活时，能看见
“跑没跑、走到哪了”，但一条消息不要刷屏，也不要泄露过程内容。

实测确认了一条可行路径（本人私聊探针，已撤回）：

- `lark-cli im +messages-send --as user --msg-type interactive` 能发 Card 2.0，
  `+messages-mget` 显示 `sender_type=user`、`is_agent=false`，**不是应用号**。
- `lark-cli im messages patch --as user` 能原地更新这张卡；`config.update_multi=true`
  必需，14 天内、单条 5 QPS。
- 反过来，**用户 token 不能编辑本人文本**：`+messages-edit` 只接受 bot；raw
  `PUT /open-apis/im/v1/messages/<id> --as user` 返回 `230027`；对文本调
  `im messages patch` 返回 `230001 This message is NOT a card`。所以卡片不是“退路”，
  而是本项目形态下唯一能原地刷新一条消息的官方路径。

卡片内容不能是插件写死的“处理中”，但也不能把会话过程摊开。对方只需要一个**最小可感知的思考**：
现在在做什么、接下来准备做什么、走到第几步、已经用了多久。

先看实际值班会话，而不是照搬开源插件的 todo 卡片。实读 值班工作区里 3 个由插件
调起的值班会话：

- 37 个 turn、398 条 `assistant/message`；工具以 `bash` 为主（430+ 次），另有 `read` /
  `write` / `web_fetch` / `skill`；
- **`todo/write` 出现 0 次**；agent 不用 todo 工具，开源插件那套“完整 todo 清单”在本项目
  的真实会话里根本不会出现；
- 其中一个真实 turn 跑了 **707 秒、85 次 bash、69 条 assistant message**；但 68 条
  assistant 是空的，最后只有一句“已发送”。agent 在长任务里**不会自然写进度**；
- assistant 消息大多 ≤80 字，但夹带人名、URL、代码片段、路径；`job/registered.label`
  直接是原始 bash 命令。这些都不能原样上卡；
- bash 命令大多是 `cd ... && ...` 链式调用，从命令推断“下一步”既不可读也不安全。


  39 次 patch，计数从 29 长到 239；对方看到的是“做了多少事”，不是“过了多久”。
- 动作计数只来自工具名，不读参数/结果/命令：`read/search/web/skill` → 查资料，
  `edit/write` → 改文件，`bash` → 执行操作，`subagent/workflow` → 并行处理。
- 43 个 p2p 长 turn 都出卡；22 个群长 turn（最长 16 分 56 秒）v1 不发。群聊留作后续。
- 历史 10 个会话里 `[进度]` 标记仍是 0，所以卡片只有“已做”计数，没有任务级
  “现在/接着”；这是标记的增量，不是卡片有意义的前提。

## 目标与非目标

- 目标：私聊里一轮真实工作**超过 2 分钟**，插件用本人身份发一张 Card 2.0 进度卡；
  之后按会话事件原地 patch，显示**已做动作计数 + 现在/接着（有标记时）+ 第 n/m 步
  （有标记时）+ 已用时**，结束时变完成/中断；对方看到的是一条持续刷新的消息，
  不是一串“收到”，也不是一个只会走的计时器。
- 目标：卡片内容来自 DSH 会话，而不是固定文案。数据源是 `session/event` 的
  `tool/call.name`（只做分类计数）、`assistant/message` 里 agent 显式写的 `[进度]` 行，
  以及 `turn/start` / `turn/end` 生命周期；插件不读工具参数/结果，不读其它 assistant 正文。
- 目标：没有 `[进度]` 行时仍有真实的“查资料/改文件/执行操作”计数，卡片依然能证明
  “在干活”；标记只负责补任务级的“现在/接着”，不是卡片有意义的前提。
- 目标：默认关闭；面板开启后才以本人身份外发。关闭后零行为变化。
- 目标：卡片和它的 message_id 不进轮询的“本人已回复”判定；不能让进度卡把对方的
  消息吞成 `you-replied`。
- 非目标：不发机器人消息、不发应用号卡片；卡片必须由本人账号发出。
- 非目标：不把 agent 的思考正文、回答草稿、工具参数、工具结果、文件路径、命令、
  错误原文、会话/用户 ID 放上卡；不展示完整 todo 清单、已完成项、工具调用历史；
  不展示工具级阶段（“正在查资料/处理”）作为兜底。
- 非目标：不做群聊进度（v1 只私聊）；不做按钮/回调；不做多卡滚动列表。
- 非目标：不让 agent 直接 patch 卡片；agent 只通过 `[进度]` 标记和正常回复影响卡片。
- 非目标：不改草稿审批 / 全自动发送方式。

## 方案

### 1. 一张卡的生命周期

- 只在 `platform === "feishu"`、`chat.kind === "p2p"`、`watching && !blocked`、
  真实 wake turn（非 warm/desk）时启用。
- 生效优先级：`chats[].progress_card` 是**三态**——`null` = 跟随全局，`true` = 这个
  私聊开，`false` = 这个私聊关；全局 `config.dsh.progress_card` 默认 **false**。
  即：
  `on = chat.progress_card === true ? true : chat.progress_card === false ? false
   : config.dsh.progress_card === true`。
  - 全局关 + 单点开 → 这个人开；全局开 + 单点关 → 这个人关；
  - 全局开 + 单点跟随 → 所有私聊开；群聊永远不发。
- 关掉只在下一轮生效：当前在飞的卡可以走完本轮再收口，不删已有卡。
- `followup()` 被接受后开始计时；**2 分钟**时 turn 仍在跑才创建卡片。2 分钟内结束就不发。
- 同一会话 10 分钟内再来一轮：如果上一张卡还是 `running`，复用它，不新建；
  如果上一张已经 `done/failed/cancelled`，新开一张。
- 卡片创建后：
  - 事件驱动：`tool/call`（只取 `name` 增加分类计数）、`assistant/message`
    （只为找 `[进度]` 行）、`turn/end` 各触发一次 1.5 秒防抖 patch；
    `tool/result` / `step/start` / `todo/write` 不接。
  - 时间驱动：从建卡起算——前 2 分钟 10 秒，2–10 分钟 30 秒，>10 分钟 60 秒；
    只改“已用时”也值得让对方看到在跑。
  - 单卡同一时刻只允许一个 patch 在飞；新状态合并到下一跳。
  - 内容 hash 不变就不 patch；hash 覆盖 header、body、footer。
- 结束：
  - `completed` → 绿头“处理完成”，只留一句收尾；实际回复仍由 agent 发。
  - `error / timeout / max-tokens / blocked` → 橙头“处理中断”，不写错误原文。
  - `aborted` / 新消息打断 → 灰头“已暂停”；如果新 turn 复用同一张卡，
    新 tracker 会马上把它改回“处理中”。
  - 进程重启：`state=running` 且已有 `msg_id` 的卡，启动后异步 patch 成“已暂停”一次。
- 卡片 patch 失败：记 `last_error`；被撤回/删除（`230011/230110`）停止；
  连续 3 次失败停止；不阻塞 turn。

### 2. 卡片内容：动作计数 + 可选任务级“现在/接着”

Card 2.0 固定。**不展示完整 todo、工具名、命令、路径、正文。** 目标样子：

```text
处理中 · 已用时 2 分 10 秒
已做：查资料 3 次 · 改文件 1 次 · 执行操作 26 次
现在：核对数据
接着：整理结论
────────────────
只同步进度，不展示内容
```

- header：`处理中 · 已用时 x`；标记给了 `n/m` 时可加 `第 n/m 步`。完成/中断/暂停
  换成对应词与颜色（绿/橙/灰）。
- body 第一行永远是动作计数：
  - `read/search/glob/grep/list/web_search/web_fetch/skill` → `查资料`
  - `edit/write/apply_patch` → `改文件`
  - `bash/shell/exec` → `执行操作`
  - `subagent/workflow` → `并行处理`
  - `todo_write` 不计；未知工具归 `执行操作`。
  - 每次 `tool/call` 加 1，按“查资料 / 改文件 / 执行操作 / 并行处理”顺序拼成
    `已做：查资料 3 次 · 改文件 1 次 · 执行操作 26 次`；不出现 0 项；最多 4 项；
    一个动作都没有时写 `已做：正在准备`。
  - 计数从 turn 开始累计，不是从建卡开始；所以 2 分钟建卡时已经有真实工作量。
- 第二段是**可选**的任务级标记：
  - 有 `[进度]`：`现在：...`，有“接着”时再加 `接着：...`。
  - 没有标记：不写“现在/接着”，只留计数；不猜工具级阶段。
- 结束态：保留计数，再加一句
  `已经处理完，稍后回你。` / `这边有点状况，稍后回你。` / `这边先暂停一下，稍后回你。`
- **进度标记**（可选，不是卡片有意义的前提）：agent 在 assistant 消息里单独写一行：

  ```text
  [进度] 2/5 现在：核对数据；接着：整理结论
  ```

  - `n/m` 可省略；`现在：` / `接着：` 可只写一个，`下一步：` 等同 `接着：`；
    分隔符允许 `；` / `;` / `|`。
  - 一条 assistant 消息里有多行 `[进度]` 时取最后一条能解析的；解析失败的标记忽略，
    保留上一条有效标记。没有标记的消息不改进度。
  - `n/m` 只接受 1–99 的整数；`n > m` 时忽略步数，仍可用“现在/接着”。
  - 标记是**会话内部行**，不会自动发到 IM；agent 不要把它写进发给对方的回复。
- 事件只投影需要的字段：
  - `turn/start`：开始计数、开始时间；
  - `tool/call`：**只取 `name` 做分类计数**，不读 `arguments`；
  - `assistant/message`：只为找 `[进度]` 行而读文本；
  - `turn/end`：只取 `reason.kind`；
  - **不读** `tool/result`、`step/start`、`todo/write`。
- 隐私：
  - 计数只按固定分类聚合，不出现工具名、命令、文件名、路径、URL、ID；
  - 标记里的“现在/接着”按原结构性过滤：URL、邮箱、`@`、电话、6 位以上数字、
    `oc_/ou_/om_/cli_/sk-/ak_` ID、绝对/相对路径、反引号/代码块、`<...>` 丢弃；
  - 标签被丢弃时省略“现在/接着”；计数不受影响，不把原文写日志。
  - agent 仍负责标记只写**任务级**动作，不写工具名、命令、文件名、人名、金额、
    合同、未确认结论。
- 卡片大小 < 30KB；实际内容远小于上限，构建时仍做一次字节数兜底。

### 3. 发送与 patch

- `im.js` 新增两个 Feishu 命令模板：
  - `cmd_send_card`：`im +messages-send --as user --msg-type interactive --content {card}`
    （`ou_` 目标走 `cmd_send_card_user`，与 `sendText` 同规则）；
  - `cmd_patch_card`：`im messages patch --as user --message-id {msg_id} --data {data}`。
- `IM.sendCard(platform, chatId, card, { idempotencyKey })` / `IM.patchCard(platform, msgId, card)`：
  - 只飞书支持；其它平台返回 `unsupported`。
  - 发送必须拿到 `message_id`；拿不到就按失败处理，不开始 patch。
  - `--idempotency-key` 用 `progress:<platform>:<chat_id 的短哈希>:<turn_id>`，
    防止重试/重启重复发卡。
- 卡片 message_id 立即写入 `chats[].progress.ids`（最多 5 条）并 `state.save()`。
- 不新增依赖、不开端口、不读模型凭据。

### 4. 状态形状与轮询过滤

```json
"progress": {
  "msg_id": "",
  "turn_id": "",
  "state": "",
  "created_at": 0,
  "updated_at": 0,
  "last_error": "",
  "ids": []
}
```

- `state`：`"" | "running" | "done" | "failed" | "cancelled"`。
- `ids`：本会话发过的进度卡 ID，最多 5 条；轮询器用它排除“本人消息”。
- **轮询器必须排除**：
  - `selfEpoch` 不计进度卡；
  - 分类循环跳过进度卡，不写 `recent`；
  - `best` 水位仍包含进度卡（它是最新一条时，下一条对方消息仍是新的）；
  - 否则进度卡会被当成本人回复，把对方消息标成 `you-replied`，吞掉待回。
- 老 state 缺 `progress` 补默认；旧版本 `normalizeChat` 重建时会丢弃这个键，
  不需要迁移。

### 5. agent 侧：最小进度标记

- 在 DSH 插件壳的载荷里，开启且私聊时首次/开关变化后加一行：

  ```
  进度卡：插件会在本轮超过 2 分钟时用你本人身份发一张卡片并原地刷新。
  卡片会自动显示“已做：查资料 N 次 · 改文件 N 次 · 执行操作 N 次”。
  如果想让对方知道具体在做什么，在 assistant 消息里单独写一行（不会自动发到 IM）：
  [进度] 1/3 现在：核对数据；接着：整理结论
  当前动作变化时更新 n/N、现在、接着；只写任务级动作，
  不写工具名、命令、文件名、路径、链接、ID、人名、金额或未确认的结论。
  不写也有动作计数，不会只剩计时器。不要另发「收到/处理中」。
  ```

- `SKILL.md`（根目录与插件副本）补一节“进度卡与最小进度标记”：
  - **建议起点**：想补任务级时，在调用第一个工具前写一行
    `[进度] 1/N 现在：...；接着：...`；当前动作变化时更新 `n/N`、`现在`、`接着`；
    不需要每一步都写；
  - 标记是**可选增强**：不写也有动作计数，卡片仍能证明“在干活”；标记只补任务级的
    “现在/接着”，不是卡片有意义的前提；
  - 实际值班会话里 agent 不会自然写进度（一个 11.8 分钟的 turn 只有最后一句“已发送”），
    所以卡片必须靠自动计数兜底，不能把可读性押在标记上；
  - 标记只放在 assistant 消息里，**不要写进发给对方的 IM 回复**；
  - 标记由 agent 负责措辞，插件只做结构性过滤；敏感任务（人名、金额、合同、凭据、
    未确认结论）不要写进标记；计数仍然只显示分类；
  - 不要直接 patch 卡片，也不要另发进度消息；
  - 不要求用 `todo_write`；真实值班会话里没有 todo，卡片不依赖它。
- 会话压缩后清空声明记录，下一轮重带一次。

### 6. 面板

- 设置页「命中回执」旁加「私聊进度卡：开 / 关」，默认关。
  - 说明：**全局开** = 所有未单独设置的私聊生效；单点关可覆盖。
  - 以本人身份发 Card 2.0，自动统计“查资料/改文件/执行操作”次数，
    可选读任务级 `[进度]` 标记；不含聊天内容/命令/路径；2 分钟内结束的轮次不发。
- 会话详情（仅私聊）加三态「进度卡：跟随全局 / 开 / 关」：
  - 跟随全局时显示全局当前值（开/关）；
  - 单点开可在全局关时只给这个人开；单点关可在全局开时只关这个人；
  - 群聊不显示这一行。
- 会话详情显示 `进度卡：处理中 / 已完成 / 已暂停 / 发送失败` 与最近更新时间；
  不显示 `msg_id`，不显示卡片正文。
- `publicChat()` 已整体展开 `chat`，`/api/chats` 自动带 `progress`，无需新路由。

### 7. 平台范围

v1 只开飞书；企微/钉钉没有本文实测的卡片 patch 通路，保持关闭，不假装支持。
平台事实写进 `references/feishu.md`。

## 取舍

| 备选 | 否掉的理由 |
| --- | --- |
| 用 `+messages-edit` 编辑本人文本 | 只接受 bot token；用户 token 服务端拒绝 |
| 撤回旧消息再重发 | 对方看到撤回提示；撤回时限可能已过；不是编辑 |
| bot 发卡片 / bot 编辑 | 换身份，破坏“以本人身份值守” |
| 卡片写死“处理中” | 用户明确要求按 DSH 会话内容变化；固定文案回答不了“走到哪了” |
| 只显示“正在处理/还在处理”或纯计时器 | 不构成“在工作”的证据；23 分钟的卡只有时间在动，用户已经明确否掉 |
| 用工具级阶段“正在查资料/处理”兜底 | 会切 39 次、不可读，还把长任务写成同一句假细节 |
| 10 秒建卡 | 短回复也会出卡；实测长任务都 >2 分钟，2 分钟门限更安静 |
| 展示完整 todo/进度清单 | 对方不需要看全部步骤；信息越多越容易泄露，也更像工作流面板而不是 IM 进度 |
| 把 agent 思考/回答/工具参数搬上卡 | 对方会看到草稿、路径、命令、未确认结论；泄露面太大 |
| 让 agent 直接 patch 卡 | 绕过插件的过滤与节流；agent 要学卡片 JSON；容易刷屏 |
| 每个阶段发一条文本 | 3–5 条新消息，比现在还吵 |
| 群聊也发 | 群可见范围大、噪音高；v1 只私聊 |
| 默认开启 | 以本人身份对外发卡，必须用户显式点头；默认关，面板一键开 |

## 验收

卡片构建与隐私（Node 测试，逐条断言）：

- [ ] 只解析 `[进度]` 开头的行；同一 assistant 消息里的其它正文（含 URL/路径/人名哨兵）
      完全不进卡片，也不落状态。
- [ ] `[进度] 2/5 现在：核对排期；接着：整理可选时间` 解析出 step=2/5、现在、接着。
- [ ] `现在` / `接着` 可只写一个；`下一步：` 等同 `接着：`；分隔符 `；;|` 都可；
      没有 `n/m` 时 header 不显示步数；`n > m` / 非 1–99 的步数被忽略。
- [ ] 一条消息多行 `[进度]` 取最后一条有效；解析失败保留上一条有效标记；
      没有标记的消息不改进度。
- [ ] 标记里的 URL、邮箱、路径、`oc_/ou_/om_`、6 位数字、反引号、`@` 被丢弃；
      两个标签都被丢弃时省略“现在/接着”，但“已做”计数仍在。
- [ ] 卡片出现“已做：查资料 N 次 · 改文件 N 次 · 执行操作 N 次”；有标记时再加
      “现在/接着”；不出现完整清单、已完成项、工具名、命令、路径。
- [ ] 只读 `tool/call.name` 做分类计数；不读 `arguments` / `tool/result` / `step/start` /
      `todo/write`；卡片不出现任何工具名、命令、文件路径。
- [ ] `assistant/message` 没有标记时只有“已做”计数；标记里的内容必须是任务级动作。
- [ ] 计数从 turn 开始累计：P01 2 分钟为 `查资料 3 · 执行 26`，结束为
      `查资料 5 · 改文件 1 · 执行 233`；0 动作显示“正在准备”。
- [ ] 运行/完成/中断/暂停四种 header 文案与颜色正确。
- [ ] 卡片是 `schema:2.0`、`config.update_multi=true`、无 `note`、字节数 < 30KB。
- [ ] 内容不变时 hash 相同，不 patch；现在/下一步/计数变化时 hash 变化。

生命周期与发送：

- [ ] 2 分钟前结束 → 不发卡；2 分钟后仍在跑 → 发一张。
- [ ] 全局关 + 单点 `true` 出卡；全局开 + 单点 `false` 不出；单点 `null` 跟随全局；群聊永远不出。
- [ ] `POST /api/chat/progress` 接受 `inherit` / `on` / `off`，群聊回 `single_chat`；`/api/chats` 带
      `progress_card` 与 `progress`。
- [ ] 同一会话 10 分钟内新 turn → 复用 running 卡；上一张已结束 → 新开一张。
- [ ] 从建卡起按 10s/30s/60s 分档刷新；事件触发 1.5s 防抖；同一时刻最多一个 patch 在飞。
- [ ] 没有 `[进度]` 标记时仍显示“已做”计数，不出现工具级“正在查资料/处理”。
- [ ] 有标记时加任务级“现在/接着/第 n/m 步”；标记更新立即生效，不等 15 秒。
- [ ] 长任务回放（脱敏 fixture）：10 个 >2min p2p 出卡（27–39 次 patch），2 分钟已有
      真实计数；22 个群长 turn 不出；历史 0 标记时无“现在/接着”。
- [ ] 发送失败 / 无 message_id → 不开 patch、不阻塞 turn、`last_error` 有值。
- [ ] patch 被撤回/删除（230011/230110）→ 停止；连续 3 次失败 → 停止。
- [ ] 进程重启 → running 卡补一次“已暂停”，第二次启动不重复。
- [ ] 卡片 message_id 写入 `progress.ids`，最多 5 条。

轮询与面板：

- [ ] 进度卡是最新本人消息时，`last_msg_id` 推进，但 `selfEpoch` 不含它。
- [ ] 进度卡之后对方再发一条 → 仍进唤醒批次，不出现 `you-replied`。
- [ ] 进度卡不进 `recent` / `pending` / `silent`。
- [ ] 设置页开关读写一致；会话详情显示状态，不显示 msg_id 与卡片正文。
- [ ] 开启且私聊时载荷出现进度标记口径；关闭/群聊/非飞书不出现；压缩后重带。

真机（需用户开启开关并同意测试私聊）：

- [ ] 本人私聊里出现卡片，发送者是本人（`sender_type=user`、`is_agent=false`）。
- [ ] 长任务（>2 分钟）在 2 分钟左右出现卡片；2 分钟时已有“已做”计数；
      agent 写标记时再加任务级现在/接着/第 n/m 步；没写也有计数，
      不出现正文/命令/工具名/人名/URL。
- [ ] 卡片按 `[进度]` 标记原地更新；对方侧不出现新消息通知（需实测确认）。
- [ ] agent 的 `[进度]` 标记出现在卡片；非标记的 assistant 正文不出现。
- [ ] 结束态变绿/橙/灰；实际回复正常发出。
- [ ] 关掉开关后不再发卡；重启后未完成的卡补“已暂停”。

收尾：

- [ ] `node --test`、`python3 tests/run_tests.py`、`bash scripts/gate.sh --quick` 全绿。

## 风险与回滚

- 风险：卡片是本人身份外发的新消息形态，用户可能觉得突兀。默认关、面板一键开、
  2 分钟内快回复不发、同一会话复用一张卡。
- 风险：patch 频率过高触发 5 QPS 或让对方觉得闪。分档 10/30/60 秒、1.5 秒防抖、
  hash 防重复、同刻单 patch；被限频（230020）退避。
- 风险：动作计数暴露工作体量（次数），但不暴露内容；标记是可选公开行，插件再做结构性
  过滤。agent 仍负责不把人名/金额/合同/未确认结论写进标记。真机前用哨兵测试。
- 风险：进度卡被轮询器当成本人回复。按 `progress.ids` 精确排除，单测覆盖。
- 风险：卡片被对方删除/撤回后一直 patch 失败。命中 `230011/230110` 立即停止。
- 风险：重启后卡片永远停在“处理中”。启动扫尾补一次“已暂停”。
- 回滚：面板关掉 `dsh.progress_card` 即不再发/不再 patch；已有卡留在会话里，不删。
  代码层撤 commit 后，`chats[].progress` 不读不写，旧版本忽略。

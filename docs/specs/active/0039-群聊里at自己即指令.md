# 0039 群聊里 @ 自己即指令

> 状态: 实施中
> 编号: 0039
> 版本: 0.18.0
> 关联: `docs/specs/contracts/02-storage.md`、`docs/specs/archive/0029-私聊at自己对替身说话.md`、
> `dsh-plugin/lib/poller.js`、`dsh-plugin/lib/turns.js`

## 背景

spec 0029 把「本人 @ 自己 = 对替身说话」做成 `kind=cmd`，但写明群聊是非目标：群里自己 @
自己仍记 `out/replied`，永不唤醒。代码里就是 `isCmdMsg` 上的一个 `chat.kind !== "group"`
（`dsh-plugin/lib/poller.js`）。

用户视角的事实（2026-11-06 15:53，本机）：一个在盯且 `timer=1` 的群里，本人发了一条
`@<自己的显示名> …`，快车道 60 秒内拉到了它，`recent` 里记 `out/replied`、正文被清空，
面板没有「处理中」、没有 turn。用户的判断是**行为不对**：群正是工作发生的地方，@ 自己是
显式指向替身的动作，不该因为会话类型不同就失效。

群默认不拉（`timer=-1`）是另一件事：没在盯的群本来就不会被看到，本次不动拉取节奏。

## 目标与非目标

- 目标：**群聊**里本人发的、确实 @ 到本人的新消息 → `kind=cmd`、`state=new`，进唤醒批次、
  唤醒 agent。群「只盯 @我」与「全部消息」两种关注程度都算。
- 目标：`cmd` 仍不算待回、不刷未读角标；不参与 `selfEpoch`——不能把同批里更早的对面 @
  标成 `replied`。
- 目标：全量模式群的合并窗口（`poll.group_wake_sec`，默认 60 秒）**对指令不生效**：
  指令是交互，不该等下一轮合并；其余消息的合并行为不变。
- 目标：唤醒载荷说明这是群里下的指令：默认只在本地处理、不在群里发言，除非指令明确要求；
  回复里不要 @ 本人自己。
- 目标：熔断沿用——同一会话 10 分钟内 cmd 唤醒超过 5 次就暂停并在面板报错（防回环）。
- 非目标：不改拉取节奏与候选口径（默认不拉的群、没在盯的群仍然看不到自 @）。
- 非目标：不改 `isMention` 的判定（结构化 mentions 按本人 ID，缺 mentions 时按正文
  `@显示名` 词边界）。
- 非目标：不改 `cmd` 的待回 / 角标 / 面板分类口径；也不自动补拉历史——已按 `out` 落盘的
  老消息不回放，用户重发一条即可。
- 非目标：不加配置键，默认开启；不改 `state.json` 版本（`kind` 是开放枚举，`cmd` 早已存在）。

## 方案

### 1. 分类（`poller.process()`）

`isCmdMsg` 去掉 `chat.kind !== "group"` 限定，只保留「本人发送 + `isMention` 命中自己」。
`selfEpoch` 与状态机不变：`cmd` 记 `new`、保留正文、排除在 `selfEpoch` 之外。

### 2. 批次（`poller.collectBatch()`）

- 非 all 分支（私聊、群「只盯 @我」）已经把 `cmd` 放进批次，行为不变。
- 全量群分支的 `pendings` 加入 `cmd`：指令不能再像以前那样以 `out` 混过去，也不能只落盘
  不唤醒。

### 3. 唤醒（`poller.maybeWake()`）

全量模式的合并窗口判断加「批次里没有 `cmd`」：有指令就立刻 `turns.wake`；唤醒成功后照旧
推进 `last_wake_at` / `last_wake_epoch`。

### 4. 载荷（`turns.js`）

- `formatMsgLine` 的 `cmd` 行仍标 `本人（@自己）`。
- `cmdNote` 在群聊里追加一句「这是群聊：默认只在本地处理，不为确认收到在群里发言」，
  私聊措辞不变。
- 注释里「私聊里本人 @ 自己」的限定改成「本人 @ 自己」。

### 5. 契约与文档

`docs/specs/contracts/02-storage.md` 的 `kind` 说明、`docs/architecture/02-data.md` 的分类表、
`dsh-plugin/README.md` 的交互说明同步。spec 0029 是冻结区，不回改；本次在
`docs/decisions/implemented/0011-群聊自at也算指令.md` 记这次翻案与代价。

## 取舍

| 备选 | 否掉的理由 |
| --- | --- |
| 维持「只做私聊」（spec 0029） | 群是工作发生的地方；用户不得不在私聊下指令再切回群，@ 自己这个动作在群里反而失效 |
| 群里自 @ 只在「只盯 @我」模式算 | 关注程度管的是「旁观消息要不要叫醒」，不是「本人能不能下指令」；全量群同样需要 |
| 全量模式也让指令等合并窗口 | 最多晚 60 秒才起 turn，用户看到的就是「没触发」；指令是交互，其余消息照旧合并 |
| 群里自 @ 也进待回 / 角标 | 指令是本人对替身说的，不是客户在等回复 |
| 加开关 | 需求是交互方式本身；「默认不对外发言」+ 熔断已经兜住风险 |
| 用前缀（如 `/im`）区分 | 平台已把 @ 自己做成显式动作，不必再发明第二套语法 |

## 影响面

- 代码：`dsh-plugin/lib/poller.js`（分类、批次、窗口）、`dsh-plugin/lib/turns.js`（注释与
  群聊指令规则）、`dsh-plugin/lib/profiles.js`（注释）。
- 契约：`docs/specs/contracts/02-storage.md`。
- 用户可见：在盯的群里 @ 自己会唤醒替身；面板「全部」里该行标签仍是「指令」；不会自动往
  群里发消息。
- 兼容：无需迁移；老 `out` 记录保持原样；降级到不认识 `cmd` 的旧版时归一化为 `fyi`。

## 验收

- [x] 群 mention 模式：自 @ 一条 → `kind=cmd`、`state=new`、唤醒一次，`pendingCount` 仍为 0
      （`tests/poller.test.mjs`）。
- [x] 群 all 模式：自 @ → 立刻唤醒，不等合并窗口；`last_wake_epoch` 推进。
- [x] 同一批里「对面 @ 我」+「本人自 @」→ 两条都进批次，对面的仍是 `new`（不被吞）。
- [x] 群里本人不 @ 的消息仍是 `out`、不唤醒（防回环回归）。
- [x] 载荷：群里 `cmd` 行标「本人（@自己）」，带「默认不在群里发言」提示
      （`tests/turns.test.mjs`）。
- [x] `node --test` 与 `bash scripts/gate.sh --quick` 全绿。
- [ ] 真机（用户）：重启后，在在盯的群里 @ 自己 → 面板出现「处理中」，群里没有自动发言。

## 风险与回滚

- 风险：agent 在群里回复时若 @ 了自己 → 回环；载荷规则 + 10 分钟 5 次熔断兜底，
  面板 `last_error` 可见。
- 风险：群里 @ 自己是对全群可见的动作，可能被同事看到；本方案不增加任何自动对外发言，
  指令默认只在本地处理。
- 回滚：恢复 `isCmdMsg` 的群限制，并撤掉全量批次里的 `cmd` 与窗口例外；已写入的 `cmd`
  行在旧版若无该枚举会归一化为 `fyi`，`state.json` 无需迁移。

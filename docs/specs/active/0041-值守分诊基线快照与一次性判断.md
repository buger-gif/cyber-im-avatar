# 0041 值守分诊：完整基线快照与一次性判断

> 状态: 实施中
> 编号: 0041
> 版本: 0.18.1
> 关联: `docs/specs/archive/0040-值守分诊.md`、`docs/specs/contracts/02-storage.md`、
> `docs/specs/contracts/03-config.md`、`dsh-plugin/lib/poller.js`、`dsh-plugin/lib/turns.js`

## 背景

0.18.0 把「基线」建在第一次成功刷会话列表上，但只拉了第一页（默认 20 个会话）。
飞书有大量旧群排在第二页以后：它们第一次被发现时，插件把 `added_at` 记在今天，
`added_at > baseline_at` 就被当成新群，触发值守判断。用户看到很多旧群被拉进候选。

飞书 CLI 的 `im +chat-list` **不返回群的 `create_time`**（实测字段只有 chat_id / name /
owner / status 等；`im chats get` 也没有创建时间），不能直接按创建时间过滤。可用的等价
事实是：**第一次成功刷列表时把所有群都登记成存量**，以后新出现的才算新群。

另外，值守判断本身是「同一事实、同一口径」的短判断；不需要复用会话上下文。0.18.0 的全局
值守台会话会越积越长，和它的任务复杂度不匹配。用户要求一次性会话、最短 token。

## 目标

1. 第一次成功刷列表（以及 0.18.0 升上来的第一次补全）拉**完整群列表**，所有已有群先登记为
   存量；旧群哪怕今天才在列表中出现，也不触发「新群」判断。
2. 升级时清掉 0.18.0 已排队的 `trigger=added` 事件，避免旧候选继续被判断；`sweep` 的
   个人 @ 事件和手动事件不清。
3. 值守台每次判断**新建会话**，不复用 `desk.dsh_session`；旧会话留在 DSH 历史，插件没有
   删除接口。判断 prompt 去掉最近判断、人物档案和会话历史，只留事实、硬门、决策路径。
4. `duty.session_max_turns` 保留为兼容键但不再生效；面板不再展示。

## 非目标

- 不伪造/推算飞书群创建时间；不为此增加逐群 `chats get` 调用。
- 不删除 DSH 历史会话；不新增会话清理 API。
- 不改变「只处理基线之后新群」的范围，也不恢复已有群的 @ 清查。

## 方案

### 完整基线

- `Adapter.listChats(limit, { all })`：飞书 `all` 时只用 `--types group --page-size 100 --page-all
  --page-limit 100`（3k+ 会话时 p2p 会让单次命令超时）；其他平台没有该能力时退回原调用。
- `refreshChatlist()` 在 `desk.baseline_at=0` 或 `desk.full_baseline_at=0` 时 `all=true`：
  - 完整列表只收集群 ID 到 `desk.baseline_group_ids`（最多 10000），**不**给 3k+ 旧群建 state。
  - 首次基线/0.18.0 升级：写 `full_baseline_at`；升级时把现有 `queued`/`triaging` 且
    `trigger=added` 的清回 `none`，保留 `member_count`/`sweep_epoch`。
  - 完整列表失败时不要写 `full_baseline_at`（下一轮再试）。
- 日常仍只拉一页；不在 state、且 ID 在 `baseline_group_ids` 里的旧群直接跳过；
  不在集合里的新群才 `ensureChat` + 排队。
- 首轮顶部 20 条仍会 ensure，保证面板有入口；更靠后的旧群不建行。

### 一次性判断

- `Turns.resolveDesk()` 每次 `sessionController.create({ cwd })`；`desk.dsh_session` 只作
  最近一次展示，不再 `resolveAgent` 复用。`session_turns` 仍计总轮数，但不再驱动轮换。
- `buildDeskPrompt()` 去掉最近判断、人物档案、重复候选行；保留群名、chat_id、成员数/上限、
  探测到的消息、硬门、决策路径和**一次性、本轮无历史**的说明。
- `deskTriage()` 不再算人物档案，只传事实 + 消息。
- `policy.md` 初始化保持 0.18.0 行为（安装/启动、缺/空才补，已有内容不覆盖）。

## 状态与配置

- `desk.full_baseline_at`（number，0=尚未完整登记）。
- `desk.baseline_group_ids`（string[]，最多 10000；完整基线群 ID）。
- `duty.session_max_turns` 保留读取/默认 20，但不再使用；契约标「已废弃」。
- 不新增路由、不升 `state.version`。

## 验收

- [ ] 首次启动飞书有 >100 个群：`listChats` 带 `--page-all --types group`，只写
      `baseline_group_ids`，不为 3k+ 旧群建 state；没有 `trigger=added` 事件。
- [ ] 模拟 0.18.0 状态（`baseline_at>0`、`full_baseline_at=0`、若干 `queued/added`）：
      第一次刷新后全部登记为存量，queued/added 清空，`sweep`/`manual` 保留。
- [ ] 完整列表失败时 `full_baseline_at` 仍为 0；下一轮重试。
- [ ] 完整登记后，新出现的群（不在 `baseline_group_ids`）仍会排队；旧群在第二页不再被排队。
- [ ] 值守台每次判断创建新 `session-…`，不调用 `resolveAgent`；旧会话不删。
- [ ] prompt 不含最近判断/人物档案/`/cyber-im-avatar`；仍含决定路径、硬门、成员上限。
- [ ] 全量 `bash scripts/gate.sh` 通过。

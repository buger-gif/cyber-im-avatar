## 发送方式：值班单点 + 新建默认（spec 0043 / ADR 0013）

**起因**：用户要求把「全自动发送 / 草稿审批」做成不等于每次在值守会话里问的配置；
并指出经常出现同一句话在不同会话里打架。第一次实现做成了全局开关，用户随即纠正：
发送方式是**值班单点配置**，不是全局配置；全局只配「新建值守时的默认状态」，
用户自己的默认是全自动。

**设计**：

- `chats[].send_mode`：每通值班自己的 `draft` / `auto`；新 chat 先为 `""`，首次加入值守
  （`/api/watch`、`/api/chat/mode` 开启、值守台 watch）时固化为当时的
  `config.send_mode_default`。显式值之后不随默认变化。
- `config.send_mode_default`：只决定之后新加入值守的默认；仓库代码默认 `draft`，
  用户可在设置页改成 `auto`。未发布时的旧全局键 `config.send_mode` 自动迁成它后丢弃。
- 存量迁移：已值守会话没有 `send_mode` 时按旧全局值/当前默认补成显式值；未值守保持 `""`，
  首次加入值守再取默认。不升 `STATE_VERSION`。
- 载荷：`Turns._wake()` 用 `chat.send_mode || config.send_mode_default || "draft"`；
  每轮唤醒 / 开场声明该值班实际生效值，明确「只由面板开关决定，口头约定不改模式」。
- 面板：「分身」每张值守卡片与会话详情各一个两段开关，写 `POST /api/chat/send-mode`；
  「设置」只留「新建值守默认发送方式」卡，写 `config.send_mode_default`。去掉全局顶部标签。
- 内容风险边界仍在 skill 铁律：钱 / 合同 / 承诺 / 权限凭据 / 外部群在两种模式下都停下。

  360 / 320 宽无横向溢出。截图只落 `/tmp/im-ui/`，未入库。

  spec 0043 保持 active，验收勾到预览页为止。
- 仓库代码默认仍是 `draft`；用户本地 state 里的旧 `send_mode: "auto"` 会在宿主重启加载时
  迁成 `send_mode_default: "auto"`，并把已值守会话补成 `auto`。没有向任何真实会话发送过消息。

## 分诊创建的值班跟随加入值守工作区（spec 0044）

**起因**：用户发现自动分诊判定 watch 后创建的会话总落在 DSH 默认工作区，而手动「加入值守」
会按页面上的「加入值守时绑定工作区」落工作区；要求自动分诊也跟随同一配置。
排查确认：面板选择只存在浏览器 `localStorage`，宿主进程读不到，分诊只能用
`chats[].workspace`（新群为空）→ DSH 默认，所以行为分叉。

**设计**：

- 新增 `config.join_workspace`（默认 `""`）：面板「加入值守时绑定工作区」选择的持久化副本；
  非空必须是真实存在的绝对路径，`POST /api/config` 校验失败整次拒绝。
- `workspaces.resolveJoinDefault(chats, config)`：显式配置 → 最近在用（与面板 `lastUsedWs()`
  同口径：`session_bound_at || added_at || last_sync` 最大者）→ 空（跟随 DSH 默认）。
- `duty.applyDecision()`：首次开监听且 `chat.workspace` 为空时，把解析结果写进
  `chats[].workspace` 再 `turns.open()`；已有显式绑定不覆盖。
- 面板：`joinWorkspace()` 顺序变为「面板记忆 → 配置 → 最近在用 → DSH 默认」；改选择 /
  加入成功 / 切换会话工作区时同步 `POST /api/config`，显式「跟随 DSH 默认」写回空值。
- 老 `state.json` 无该键补空，不升 `STATE_VERSION`。

**验证读数**：

- `cd dsh-plugin && node --test`：259 通过 / 0 失败（新增 4 条分诊绑定用例 + 配置归一 + API 校验）。
- `python3 tests/test_docs.py`、`bash scripts/gate.sh`：全绿（配置契约、构建产物、文档对账）。
- 未做真机点验：重启宿主后由自动分诊实际拉起一个新值班，确认会话落在配置的工作区。
  spec 0044 保持 active，等用户按验收清单勾完再归档。

**未做 / 留给用户**：

- 面板手动点验：改「加入值守时绑定工作区」→ 刷新仍显示该值；自动分诊判 watch 后卡片显示
  同一工作区，DSH 会话 cwd 与之一致。
- 如果用户从没显式选过工作区，自动值班会优先跟随「最近在用」的工作区；不想要就重新选
  「跟随 DSH 默认」，或把该值班在详情里改回默认。

## 载荷只声明变化（spec 0045）

**起因**：用户在自己的值守会话里看到，普通命中只有一行消息，却每轮跟着整段「发送方式…」；
本人每次 @ 自己下指令，同一段「【本人指令】…」规则原样复读。原话：「每轮追加太丑陋了，
没变的值就不要来回一直追加」。用户补充：如果知道会话被压缩过，压缩之后重新追加一次。

**设计**：

- `buildWakePrompt()` 新增 `announced` 参数（该 DSH 会话上次声明的
  `{send_mode, wake_mode, cmd}`）：非首轮只在发送方式 / 关注程度取值变化时追加注记，
  本人指令规则只在会话里第一次出现 `cmd` 时带；未变的轮次只输出消息行。
  `announced` 缺省视为没声明过，照旧全带（旧调用 / 重启后首轮兜底）；首轮与开场不变。
- `Turns._wake()` 按 `${platform}:${chatId}:${sid}` 取内存口径记录；`runTurn` 新增
  `onSent` 钩子，`agent.followup()` 成功后才把本次值写回，载荷没送出不算声明过。
- 压缩检测：查 `~/.dsh/runtime/node_modules/@deepseek-ai/dsh-*` 实现确认，DSH 压缩会话会
  append `compaction/summary`（随后 `user/message` 带 `surfaceOp.replace` 替换一段历史）
  和 `compaction/end`；`compaction/end` 成功无 `error` 字段，失败带 `error`。
  `Turns` 在根 ctx 上订阅 `session/event`，按事件里的 `session.id` 清空该会话口径记录
  与已给过的人物档案指针（`seenPeople`），下一轮完整补一次；失败压缩不清。
- 常驻依据写进 `SKILL.md`：本人指令规则 + 「后续轮次没带声明时沿用本会话最后一次、从没
  声明过默认草稿」；插件形态下不依赖每轮复读。
- 口径记录只在内存（与 `seenPeople` 同策略），不升 `state.json`，不动契约。
- spec 0043 的「每轮声明」小节同步改成「首轮 / 切档后声明」；新增 ADR 0014 记录这次改判，
  决策索引里给 0013 标了「声明时机由 0014 修订」。

# 2026-11-26

## 0063 中断收尾保护

**触发**：上游 [Discussion #14340](https://github.com/deepseek-ai/deepseek-harness/discussions/14340)
报告 DSH 0.2.2-rc.5 的一个永久卡死路径——流式回答在思考阶段被停止时，如果只产出了
reasoning，agent loop 会持久化 `interrupted: true` 的 `assistant/message`，内容只有
reasoning。下一轮请求把它发成只含 thinking 块、没有 text / tool_use 的 assistant 消息，
严格 Anthropic Messages 网关直接 400 `The content field is a required field.`；消息在历史里，
之后每轮都失败，重试 / 重开会话 / 重启 App 都不能自愈。上游 master 与
`dsh-v0.2.3-alpha.2` 都未修。

**约束**：不能改 DSH 安装目录（app.asar）或 `~/.dsh` 下的 vendor 代码；不能改已有
`session.v4.jsonl.zstd`；不改事件类型 / seq / Transcript。

**改动**：

1. 新增 `dsh-plugin/lib/guard.js`：导出 `installReasoningGuard(ctx)`。先挂
   `session/created`，再 `ctx.inject(["sessions"])` 扫 `sessions.list()`；实例级包装
   `session.append`，用 `Symbol.for` 标记 + `WeakSet` 保证同一 session 只包一次，
   prototype 不动。包装返回原 append 的返回值。
2. 命中条件：`assistant/message` + `interrupted === true` + content 数组 + 没有非空白
   text / tool-call / image。命中时浅拷贝 data / message，在 content 末尾追加 text 块。
3. 占位文案 `（上一轮在思考阶段被中断，未产生内容）` 用 Markdown 链接定义
   `[//]: # (...)` 包住：GFM 把 definition 节点渲染为 null，聊天转录看不到；模型请求里
   仍是非空 text，满足网关。直接写裸文案会让 Transcript 多出一行假正文，已否掉。
4. 安全：守护逻辑 try/catch，失败按原参数调用原 append；原 append 的错误原样抛出，
   不吞、不重试。安装 / 命中只打 `[im-standin]` 前缀日志（session id + seq），不打印正文。
5. `IM_REASONING_GUARD=0` 完全旁路；默认开启。`dsh-plugin/lib/index.js` 的 `apply()`
   只调用一次。

**自动测试**：

- `cd dsh-plugin && node --test tests/guard.test.mjs`：8 条全过（补块 / 透传 / 非命中 /
  原 append 抛错 / 幂等 / 实例级 / 开关 / 日志脱敏）。
- `cd dsh-plugin && npm test`：426 条全过，0 失败。

**隔离真机（DSH 0.2.2-rc.5）**：

- 宿主：app 自带 CLI，独立 `DSH_HOME=/tmp/dsh-guard-home`、`IM_STANDIN_DIR=/tmp/im-standin-guard*`；
  模型指向本地模拟 Messages 网关（只在假数据上跑，未连真实网关）。
- 关闭开关（`IM_REASONING_GUARD=0`）：新会话发「长思考测试」，思考阶段 SIGINT 停止；
  session log 出现 `interrupted: true`、content 仅 reasoning 的 `assistant/message`；
  `--session-id` 续聊同一会话，请求得到 400 `invalid_parameter_error: The content field is
  a required field.`，`turn_end` 为 error——与上游描述一致。
- 开启开关（`IM_REASONING_GUARD=1`）：同样的停止方式；日志出现
  `[im-standin] reasoning guard: stand-in text appended (session=…, seq=…)`；session log 的
  该条 message content 为 reasoning + text，text 是 `[//]: # (（上一轮在思考阶段被中断，
  未产生内容）)`；续聊返回 `{"kind":"completed"}` 与正文「已恢复：能看到上一轮的中断，
  继续回答。」。
- 同一轮请求体：关闭时 assistant content 只有 `thinking`；开启时为
  `thinking + text:[//]: # (...)`。网关对该形状返回 200。
- Web 转录：用隔离 web 宿主（3082，同样指向模拟网关）打开该会话，截图与
  `document.body.innerText` 均只有「已停止 / 已完成分析 / 收到请继续 / 已恢复：…」，
  没有「上一轮在思考阶段被中断」占位文案；侧边栏 `IM 值守` 席位正常挂载。

**失败与限制**：

- SIGINT 关闭 headless 进程时 DSH 报 `flush on a closed handle`，但 session log 已落盘；
  这是停止路径的既有收尾噪声，不是 guard 引入的，续聊验证照常通过。
- 没有重启用户桌面 app（会中断当前会话）；真机改用隔离的同版本宿主，等价验证
  Session / agent-loop / serializer / 网关形状。桌面 app 复核写进 `PROGRESS.md` 挂账。
- 未处理存量已卡死会话（按用户边界，由主工作区单独处理）。

**回滚**：删掉 `apply()` 里的 `installReasoningGuard(ctx)`，或启动前设
`IM_REASONING_GUARD=0` 重启；无数据迁移、无存量文件改动。上游修好后整段可撤。

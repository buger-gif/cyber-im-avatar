## 0063 中断收尾保护

**触发**：上游 [Discussion #14340](https://github.com/deepseek-ai/deepseek-harness/discussions/14340)。
DSH 0.2.2-rc.5 在思考阶段停止流式回答时，会持久化只有 reasoning 的 `interrupted`
assistant 消息；下一轮被严格网关 400 `The content field is a required field.`，之后每轮都
失败，重试 / 重开会话 / 重启 App 都不能自愈。上游 master 与 `dsh-v0.2.3-alpha.2` 未修。

**边界**：不改 app.asar / vendor / 已有 session log；不改事件类型、seq、Transcript。

**改法**：`lib/guard.js` 实例级包装 `session.append`，命中时在 content 末尾补一个 Markdown
定义形式的占位正文（模型请求可见、Transcript 不渲染）；`IM_REASONING_GUARD=0` 旁路。
实现与取舍见 `docs/specs/archive/0063-中断收尾占位.md`。

**读数**：`tests/guard.test.mjs` 8 条；全量 426 条。隔离宿主（同版本 CLI、假网关）关闭
开关续聊 400、开启后续聊 200（「已恢复：…」），Web 转录无占位文案；`gate` 绿。

**失败与限制**：SIGINT 收尾有 `flush on a closed handle` 噪声（既有，不是 guard 引入）；
未重启用户桌面 app，真机改用隔离宿主；存量已卡死会话未处理。

**回滚**：删 `installReasoningGuard(ctx)`，或设 `IM_REASONING_GUARD=0` 重启；无数据迁移。

## 面板 401：桌面壳的注入快照（0064）

**现象**：面板横幅「会话凭据过期」，⌘R 无效；值守轮询与唤醒正常。

**读数**：页面 13:34:44 加载；宿主 13:48:40、15:10:35 各重载；之后刷新没有新的 index
注入 / `client-apply`；15:38 有 `ims_tok_reload` 写入，说明自动刷新跑过。

**根因**：桌面壳 `dsh-app://app/` 的 index 来自打包 dist + 宿主启动时一次
`ready.injections` 快照；插件热重载换 token 后壳不重取，页面刷新只是重放旧快照；
生产包没绑定 `role: reload`，⌘R 本来就没有。

**修法**：`lib/panel-auth.js` 认 `connection.requestRejection`（DSH 签名会话），token
保留兜底；回环 / Host / Origin 三道门不变；401 文案去掉 ⌘R。见
`docs/specs/archive/0064-面板认DSH会话.md`。

**验证**：433 条测试全过。真机用 profile 配置注释触发 HMR（验证后恢复，sha256 一致）：
15:58:56 宿主重载、页面未刷新；15:59:38 `/api/status` 走 `auth-dsh` 通过，轮询未断。
另记一条事实：源码改动不会自动热重载，只有 profile 配置变更触发 reconcile，且会顺带
把已改的插件模块带进宿主。

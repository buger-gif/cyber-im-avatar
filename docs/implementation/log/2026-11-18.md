## 群发言权契约（spec 0051 / ADR 0016）

**起因**：飞书催办群里某值班机器人 @ 的是处理人，值守账号是跟进人，`send_mode=auto`，
agent 在开场轮以跟进人身份代处理人回了一句「我先看下代码」。用户提出的约束是：收紧成
「没 @ 我禁止发」不行——新建群常常没有任何 @，但任务确实是本人的。

**取证（纠正了当时的归因）**：

- `state.json` 里那条 @ 处理人的消息是 `kind=fyi` / `skip=baseline`，`duty.trigger` 停在
  `added` 而不是 `mentioned`（`probeForDuty` 只在 `anyMention` 为真时改它）——插件的
  `mention.id == self.open_id` 比对是对的，`isMention` 的用例也早就在。
- `logs/turns.jsonl`：`event=open`、`count=3`、`10:42:24` 起轮，`10:44:53` 收口，误发在
  `10:44:00`。失效点就是开场轮。
- 本机读数：314 个会话、32 个 `send_mode=auto`、`config.send_mode_default=auto`。

**做法**（详见 spec 0051）：

1. 事实进载荷：`本人：姓名 · 平台 · open_id`、每条消息的被 @ 对象、`本批 N 条点你名`。
2. 删掉三句机械结论，改成「默认沉默 + 判定该你出手才发言 + 说清为什么」。
3. 群工作本加 `## 我在这个群的发言权`；未定义 → 该群本轮强制草稿，定义后自动恢复
   （依赖关系，不是开关，无新配置键）。
4. 面板「发言权 → 编辑」只改这一段：`GET/POST /api/rights`，段内替换 + `base_mtime` 冲突
   + 标题丢失补回 + 8KB 上限；工作本其余字节逐字节不动（有断言）。

**读数**：Node 320 绿（含新增成对的 A/B 用例：@ 别人 → 草稿；没人点名但任务是本人的 → 允许
发言）；`bash scripts/gate.sh --quick` 绿；`dsh-plugin/skill/` 已用 `bundle-skill.mjs` 重新生成。

**没做**：发送闸门（agent 用平台 CLI 直发，插件拦不住，0013 已否过关键词闸门）；新增关注
程度档（`all` 改文案即可）；撤回观察窗（留作下一轮 ADR 的候选）。

**留给真机验证**：改动真实群工作本后，面板「发言权」行是否显示「未定义 · 全自动已暂停」，
以及补上契约后下一轮载荷是否恢复 `全自动`。

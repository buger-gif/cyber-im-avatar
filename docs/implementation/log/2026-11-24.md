## 0056 人员承诺边界

**触发**：查「日常工作 / 项目区」的一个值守会话（手动开场的那一轮）。对方在群里点名约
「明天抽时间开个会」，agent 查了日历后直接回「明天 11 点可以」。工作本里已经写了「不替人
答应时间」，但没把「参会」归进承诺；全自动模式直接以本人身份发了出去。

**盘点**（18 份值守日报，按条计）：漏洞 / 复测 / 修复 / 关单 56、进度同步 / 催办 / 协调 57、
查证 / 核对 / 分析 50、解释口径 / 答疑 40、文档 / 表格 / 清单 36、交付文件 27、会议 / 参会 1。
绝大多数是分身自己就能做完的活，不能因为「像承诺」就一起停掉。

**判断**：按能力分，不按措辞分——分身现在能用工具做完的（查、核、复测、修、跑测试、写
文档、解释、同步、催办）直接做掉；只有需要本人未来亲自到场 / 花时间 / 签字 / 付款 / 授权 /
拍板的事（参会、约时间、出差、合同价格付款、系统权限、公开发布、接受风险 / 批准例外）才停，
回「收到，具体安排我确认后答复」并记 P1。别人做的事可以催办 / 同步，但不替别人承诺完成时间。

**改动**：

1. `SKILL.md` 的 `## 承诺边界：自己能做的直接做，本人到场 / 拍板的才停`：三类判断 + 两个例子；
   硬停清单只留本人事项。
2. `lib/turns.js` 的 `sendModeNote`：草稿 / 全自动都补「能查、能核、能测、能修、能写的直接
   做掉再回结果，不要留成 P1」；参会 / 签字 / 付款 / 授权 / 接受风险才停。
3. `lib/duty.js` 的 `DEFAULT_POLICY` 同步；已有 `policy.md` 不覆盖。

## 0057 值守自动退役

**触发**：用户指出群值守 / 用户值守越来越多、没有自动退役；要求在看会话保活的同一步
做退役判断，并加 7 天不活跃直接退出。

**读数**（本机 state，仅数量）：343 个会话，26 个值守（18 群 / 8 私聊）；按「7 天没有
命中」的时钟，6 个群超过 7 天，私聊 0 个。临时目录复制 state 跑 `maybeRetire()`：
26 → 20，6 个变 `retired`，`watching=false`、`timer=-1`，没有删会话 / 画像 / 绑定。

**判断**：

- 不能把退役塞进 `maybeWarm()` 现有条件：它只处理已绑定会话、闲置 55–110 分钟的窗口，
  7 天不活跃的会话永远不在窗口里。正确位置是同一个后台 tick 里的独立 `maybeRetire()`。
- 活跃口径不能用 `last_epoch`（群里的非 @ 闲聊会一直续命）；用「命中」消息时间
  `duty.last_hit_at`：私聊来信、个人 @、全量模式群消息。群里有闲聊但没人点你名 = 不活跃。
- 待回 / 在飞 / trial 不退役；退役后群的新个人 @ 仍走 sweep 重新分诊，私聊需手动重加。

**改动**：

1. `lib/state.js`：`duty.retire_after_days`（默认 7，0 关，0–365）；`duty.state` 加
   `retired`；`duty.last_hit_at` 追加在 duty 对象最后。
2. `lib/duty.js`：`activityAt()`、`retire()`、`dutyCounts.retired`；`newEvent` 保留命中时间。
3. `lib/poller.js`：`process()` 写命中时间；`maybeRetire()` 接进 `tick()`；`maybeSweep()`
   纳入 retired（只对 retired 放宽存量群限制）；sweep 命中写时间。
4. `web/panel.js`：设置页退役天数、会话详情「已自动退役」、说明文案；重建 `lib/client.js`。
5. 契约 01/02/03、architecture 02/03、插件 README、CHANGELOG 未发布同步。

`node --test` 361 通过；`python3 tests/run_tests.py` 213 通过；`bash scripts/gate.sh --quick`

## 0059 任务完成收尾

**触发**：用户补要求——会话保活判断时，如果发现群的任务已经干完、或某个人要 agent 干的活
已经结束，可以记录「准备关闭」，但不要立刻关；两天内没人再让它干活，才真正退出。

**判断**：这是 agent 的语义判断，不是插件的聊天解析。放在保活轮最便宜：那一轮已经在读
工作本 / 人物档案，不额外拉消息、不发消息；agent 认为干完了就写一行结构化标记，插件只认
标记并给 2 天观察期。任何新命中 / 待回 / 在飞 / 手动活动都取消收尾；到期无新活才退役。

**实现**：

1. `lib/duty.js`：`closing` 状态 + `close_at`、`markClosing` / `cancelClosing` /
   `parseClosingMarker`；`retire()` 支持自定义 reason。
2. `lib/state.js`：`duty.close_after_days`（默认 2，0–30，0=关）；duty 枚举 / 字段同步。
3. `lib/poller.js`：`maybeClose()` 接进 tick；新命中 / 命令在 `process()` 里直接取消；
   `maybeRetire()` 跳过 `closing`；收尾关闭复用 `retire()`。
4. `lib/turns.js`：保活 prompt 增加可选收尾说明（0 时不出现）；warm 轮收集 assistant 文本，
   `result.ok` 且无 pending 时解析标记并 `markClosing`。
5. 面板：设置页「任务完成收尾（天，0=关）」；详情 / 卡片「任务已完成 · 观察中」；
   duty 计数加 `closing`；重建 `lib/client.js`。
6. 契约 01/02/03、architecture 02/03、插件 README、CHANGELOG 未发布同步；spec 0059 归档。

**读数**：`node --test` 374 通过（新增 13 条）；`python3 tests/run_tests.py` 213 通过；
`bash scripts/gate.sh --quick` 全绿。未重启用户正在用的插件，`closing` 要等新版本 / 重启后

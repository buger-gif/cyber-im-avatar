## 闲置重开与值守心跳（spec 0026）

- 用户问插件是不是还缺两项：55 分钟缓存续期、超过 3 小时没人聊自动重开会话。查代码后确认
  两项都不存在：`--cache-refresh-min 55` 只在独立 skill 的 `listen_core.py` 里；插件形态
  `README.md` 原本明确写「目前不做 55 分钟心跳」。`dsh_session` 只在手动重开、换工作区、
  会话丢失时清空，没有按闲置时长触发的路径。
- 本机 `state.json` 读数：137 个会话、6 个已绑定 DSH 会话，其中 5 个闲置超过 3 小时；
  最多 10 轮。说明改动会有实际效果，但也说明当前会话普遍不长，冷读收益要等会话养大后才明显。
- 设计（`docs/specs/active/0026-闲置重开与值守心跳.md`）：
  - `dsh.idle_reset_min`（默认 180，0=关）：下一条消息唤醒前，若距最后一次真实 turn 超过阈值，
    先解绑旧会话，在新会话里带完整首轮载荷处理；旧会话留在侧边栏。
  - `dsh.warm_min`（默认 55，0=关）：闲置达到该间隔且未到重开阈值时，在已绑定会话里起一轮
    「值守心跳」——续上下文缓存，并让 agent 按 skill 规则归并当前对象画像。
  - 心跳不写 `session_turns` / `last_turn` / `wake`，只写 `last_warm_at` / `last_warm_ok`；
    真实消息到达时按现有 `wake()` 取消在飞心跳。重开时钟只认真实 turn，否则每小时心跳会把
    3 小时重开永远推后。
- 代码：`state.js`（两个配置键、三个 chat 字段、`setSession` 记原因）、`turns.js`

## skill 形态：3 小时没有新消息就退出（同日晚些时候）

- 用户补充：skill 的保温和超时也保持同等行为；skill 模式没有会话管理权，不自动开新会话，
  3 小时没有新消息直接退出。
- 实现：`scripts/listen_core.py` 增加 `--idle-exit-min`（默认 180，0=关闭）与 `--new-watch`；
  闲置时钟 `idle_at` 存进水位文件，跨 55 分钟重挂沿用；只认命中（sender/keyword 过滤和
  自己发的不算）。命中时刷新 `idle_at`；到点退出 **4**，stderr 标 `[idle-exit]`，
  重用现有退出码 0/2/3 之外的一个，agent 必须停止重挂。
- `--new-watch` 用于用户明确要求重新值守时归零时钟；自动重挂不带，否则 3 小时上限会被绕过。
- 保温：`[cache-refresh]` 退出 3 时，SKILL.md 要求重挂前先按画像规则检查/归并当前画像，
  与插件心跳同口径；skill 没有会话可换，所以只归并、不换会话。
- 测试：`tests/run_tests.py` 新增 `test_idle_exit`——到点退 4、命中刷新 idle_at、
  `0` 关闭、过期时钟立即退 4、`--new-watch` 重新计时；共 +10 条检查。
- 文档：`SKILL.md` 退出码/标准闭环/参数、`README.md` 新增「为什么连续 3 小时没消息就自己停」、
  `references/troubleshooting.md` 退出码表、CHANGELOG 未发布同步。

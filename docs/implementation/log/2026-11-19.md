# 2026-11-19

## 0.24.2 发布：交付本人文档不再当成「授权」

**现象**：上一轮值守里把分析文档发给被值守对象时，agent 先问「要不要开权限」；授权时还带了通知参数，
对方收到「权限授予」和「消息」两次提醒。

**根因**：`SKILL.md` 铁律把「权限/凭据」一律当敏感动作，没区分「把自己刚写的文档交给对面」与
「提权 / 改他人权限」；`turns.js` 的唤醒文案同样只有一句「权限/凭据不许自动发」。

**改动**：

1. `3abef89 fix(skill)`：`SKILL.md` 明确把本人新建的文档发给当前会话对象属于回复的组成部分——
   直接 `drive +member-add --perm view --yes` 再发链接；只有扩大范围（租户/外部可读、给第三方、
   改他人权限、放进公开空间）才停下确认。开权限默认不通知；链接另发时不带 `--need-notification`。
   `turns.js` 的载荷文案同步补这两句（`sendModeNote` 两段）。
2. `0d1340f docs(runbook)`：`dev-loop` 新增「真源与产物」对照表，写清 `SKILL.md` / `turns.js` /
   `panel.js` 各改哪里、哪些是生成物不要手改，以及改完 `build:skill` 再同步安装副本。

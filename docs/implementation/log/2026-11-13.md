## 手动停盯后旧 @ 不再重新分诊

**现象**：用户在面板把刚分诊过的群点「不盯」后，下一轮定期 @ 清查（`maybeSweep`）又拿
停盯前的旧 @ 起了一次值守台 turn；agent 按同一条 @ 重新判 `watch`，刚停掉的值班被原样
判回来，白花一次 token。

**根因**：`docs/specs/archive/0040-值守分诊.md §3.1` 写的是「用户手动 watch/off 同样推进
`sweep_epoch`」，但 `App.recordUserDuty()` 只在 `action=watch` 分支直接 return，`ignore`
分支没有动水位。走 `duty.applyDecision()` 的自动判定会推进，面板手动停盯不会；一次性
事件留下的 `event_id` 与决策文件也还在，晚到的 `watch` 决策仍有应用路径。

**改法**：

- `dsh-plugin/lib/app.js` `recordUserDuty()`：`ignore` 时把 `duty.sweep_epoch` 推到
  `max(原水位, chat.last_epoch, 现在)`；清空 `event_id` / `event_at`，并删掉该事件对应的
  `duty/decisions/<event_id>.json`（`by=user` 已让 `maybeTriage` 的 `superseded()` 拦下
  晚到决策，删文件是第二道）。
- `dsh-plugin/lib/poller.js` `maybeSweep()`：飞书 @ 搜索与钉钉逐群回退两条路都加一道
  `state=ignore && by=user && ts <= decided_at` 的过滤。老 state 里手动停盯过的会话水位
  可能仍是 0，这条兜底不需要迁移；停盯之后的新 @ 仍照常入队。
- 测试：`tests/app.test.mjs` 断言停盯把水位推到当前、清掉未落地事件；
  `tests/poller.test.mjs` 断言停盯前的旧 @ 不重新入队、停盯后的新 @ 仍会分诊。

**验证**：

- `cd dsh-plugin && node --test`：287 项全过。
- `bash scripts/gate.sh --quick`：py-compile / js-check / docs / contracts / secrets 全绿。
- 未发真实 IM 消息，真机项仍按 0046 / 0040 的验收清单执行。

## 自检分诊：一次瞬时网络失败被放大成红色故障

**现象**：面板飞书卡片出现红色 `last_error`，是 lark-cli stderr 的多行错误 JSON 被 HTML
压平、截到 300 字符后的结果；错误体 `type=network, subtype=transport`，URL 断在
`container_id_type=cha`。同一条 `im +chat-messages-list` 直连 1.3 秒成功；
`bootstrap.py --selftest` 连跑 3 次全过；`lark-cli doctor` 8 项全 pass（token 有效、
`endpoint_open` reachable）。

**根因**（四处，均可复现）：

1. `scripts/doctor.py` 把 CLI 体检里所有非 `pass/ok/skip` 的状态算 `fail`，
   `cli_update=warn(1.0.98 → 1.0.100 available)` 因此判飞书不可用、退出码 2。
2. `check_path()` 只取 stderr 第一行 `err[0][:160]`；CLI 错误是多行 JSON，第一行是 `{`，
   实测输出为 `[fail] 通路: ERROR: 初始化水位失败: `，原因整段消失。
3. `scripts/listen_core.py` 的短窗口自检先查 deadline 再查 `fail_streak`：3 秒内全部拉取失败
   也走 `timeout_exit()` 退出 3（按成功处理）。有水位文件时自检根本发现不了通路坏；这次
   面板没被它骗过，但 `--selftest` 会。
4. 读请求与自检全程无重试；`redact_sensitive()` 的 URL 正则会连反斜杠一起吃掉，把
   `\"<URL>\"` 变成 `"<URL>"`，转义 JSON 被自己弄坏，后续解析不到结构化 cause。

**改法**（`docs/specs/active/0047-自检分诊.md`）：

- `dsh-plugin/lib/im.js`：`describeCliError()` 归一 `network/auth/permission/schema/api/other`；
  读请求 `runRead()` 对 network + `rc!=124` 重试一次（500ms）；`redact()` 给 `oc_/ou_/om_/cidr/wo`
  打码；`fetchMessages()` 返回 `error`=一行结论、`error_detail`=脱敏原文。
- `dsh-plugin/lib/poller.js`：`last_error` / `errors[]` 只存结论，原文走 `logger.warn`。
- `scripts/bootstrap.py`：`classify_cli_error()` / `listen_probe()` / `probe_path()`；
  `--selftest` 对 network 重试一次并打印归一原因。
- `scripts/doctor.py`：`warn` 归 warn；`check_path()` 复用探针并给出分类原因；
  `enabled_platforms()`（`state.json` 配置 > `env.json` 登录记录 > 全部），未启用报 `skip`。
- `scripts/listen_core.py`：窗口内零成功且有失败 → `ERROR: 自检窗口内拉取全部失败`、退出 2。
- `scripts/data_guard.py`：URL 字符类排除 `\\`，脱敏不再破坏转义 JSON。

**验证读数**：

- 真机 `python3 scripts/doctor.py`：退出 0，飞书只剩 1 条 warn（`cli_update`），
  `未启用: wecom, dingtalk（不检查…）`。
- 真机 `bootstrap.py --selftest feishu <目标>`：`[ok] 拉取通路正常`；插件适配层

- 错误 ID 下 `doctor.py feishu --chat-id`：`[fail] 通路: 接口报错 230001：… <ID>`；
  stub 网络错误下：`网络传输失败：…（已重试 1 次）`，探针调用 2 次。
- `python3 tests/run_tests.py` 213 通过 / 0 失败；`cd dsh-plugin && node --test` 293 通过；

## 0048 启动值守回执

**需求**：用户在群里 @ 自己发「启动」之后，会话里要看得见一句回执——「支持用户自定义，
默认就是 24 小时值班，上线 @ 我即可触发。」。0046 当时把「自动回执」写进了非目标，这次
是用户明确翻案：只在真正拉起新值班时发，群聊 / 私聊都发。

**改法**：

- `dsh-plugin/lib/command.js`：`normalizeReplyText` / `replyTooLong` / `replyEnabled` /
  `replyText`；文案压缩空白、去控制字符、封顶 200 字。
- `dsh-plugin/lib/state.js`：`DEFAULT_CONFIG.command` 加 `reply_enabled=true` /
  `reply_text=<用户给的句子>`；`normalizeConfig` 保留两键；`chats[].command.reply` 归一。
- `dsh-plugin/lib/poller.js`：`turns.open()` 成功后 `sendStartReply()` 走
  `adapter.sendText`；失败只 `logger.warn`、`result` 保持 `started`；`writeCommand` 保留
  `reply`，下一条 `already` 不抹掉上次记录。
- `dsh-plugin/lib/app.js`：`reply_text` 超长整次拒绝。
- `dsh-plugin/web/panel.js`：设置卡加回执开关 / 文案，会话详情显示「已发 / 发送失败」。
- 契约 01/02/03、架构 02/03、README、SKILL、插件 README、CHANGELOG 同步。

**验证**：

- `cd dsh-plugin && node --test`：300 通过 / 0 失败（新增 7 条：纯函数 2、poller 4 含
  「已值班不发」「失败不回滚」「关 / 空不发」、app 配置 1）。
- `python3 tests/test_docs.py`：20 通过 / 0 失败。

**没做的**：没有向任何真实群 / 私聊发消息；默认文案里的「24 小时」与独立 skill 形态的

## v0.7.0 发版（npm 0.7.0 + 市场索引切 npm 源）

- publish workflow（OIDC）连败两次，真实报错 404 PUT——根因确认：npm 包页 **Trusted Publisher 一个连接都没登记过**（不是字段不匹配）。
- 网页登记走到最后一步被 npm 新门槛拦下：编辑启用了 2FA 要求的包需要**账号先开通 2FA**；账号没开 2FA，而 2FA 现在只剩 Security key（通行键）方式，注册必须本人在场按指纹，此路当天走不通。
- 改走 runbook §B 手动兜底：网页新建 granular token（bypass 2FA + read and write + all packages，7 天期），本机 `npm publish` 成功发出 **0.7.0**（`+ dsh-cyber-im-avatar@0.7.0`，registry latest 一分钟内翻转）。**发布完立刻在网页删除了该 token**，本地临时 npmrc 一并清理。
- `market/index.json` 由 `make-market-index.mjs --source npm` 重新生成（0.4.0 git 源 → 0.7.0 npm 源），format-1 校验过，`gate.sh --quick` 全绿，随后推上 main。
- 删远端 tag 重推，publish run 绿（版本已存在→跳过发布），test workflow 同绿。
- 发版时的 npm 网页操作只借浏览器登录态；密码、验证码与令牌未写入仓库
  （临时 token 用完即删）。
- 账号现状：npm 账号需先完成 2FA，才能登记 Trusted Publisher；登记后发版走 OIDC。
- 教训：macOS System Events `key code 40` 是字母 k 不是 ↓（↓ 是 125）；npm「新包预登记 Trusted Publisher」不存在——Staged Packages 页与预登记无关，未发布过的包名必须等首次发布后才有包设置页。
